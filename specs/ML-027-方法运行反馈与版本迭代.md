# ML-027 方法运行、反馈与版本迭代规范

状态：approved（2026-11-05，用户确认继续；仅规范，未实施）

## 要什么

让每次方法经MCP或引擎使用后，都能沉淀为可回放的方法应用记录，并把机器事件、人工反馈和真实结果转成有证据的版本修订建议。最终形成“运行→评价→提案→回归→发布→回滚”的方法生命周期，而非只有调用日志。

## 不做什么

- 不用调用量、点赞或项目最终结果直接证明方法有效。
- 不允许模型、Host或单条反馈自动修改公共方法、事实、评分、审核和授权状态。
- 不覆盖历史Run、Artifact、ResearchPack、Feedback或Release。
- 不默认公开或用于训练，不采集密钥、无关个人信息和未授权企业原件。
- 本轮不迁移旧SQLite、不增加公网写入、不实施自动上线或模型微调。

## 复用与存储边界

- 复用ML-003的Run/Submission、版本指纹、幂等与依赖检查。
- 复用ML-024的`opinion / reported_observation / reported_trial`反馈类型及`internal_research / public / training`授权。
- 复用ML-022的`supported / refuted / pending / inconclusive`结果状态，不推断模型准确率。
- GDRP的Execution引用MethodRun；后续反馈放入独立记录，不改原研究包。
- 第一实现采用本机私有、追加式Learning Store，通过精确ID关联旧Run；旧18/20/22工具入口及数据库保持不变。

## 核心记录

| 记录 | 必需内容 | 主要用途 |
|---|---|---|
| MethodRun | 任务、上下文、执行模式、资产版本、起止与终态 | 回答用了哪版、在什么任务上 |
| StepRun | 步骤、输入、事件、阻塞、返工、停止、耗时与成本 | 找到难用和失效位置 |
| ArtifactRevision | 草稿、提交稿、人工修订、证据、前后指纹 | 区分生成、修改与接受 |
| Review | 机器、AI、Host、客户或领域审核及具体理由 | 保存判断，不混成机器通过 |
| Feedback | 意见、现场观察、试验回报、依据、角色和授权 | 收集使用后的有界反馈 |
| Outcome | 决策变化、未知变化、假设结果、验证定义和证据 | 判断是否有帮助及适用范围 |
| ChangeProposal | 发现模式、证据事件、修改假设、回归与风险 | 驱动受控版本迭代 |

所有记录使用稳定ID、精确版本和SHA256。原始事件追加保存；列表、统计和仪表盘均为可重建投影，不回写原始记录。

## 统一事件信封

```json
{
  "schema_version": "method-event-0.1",
  "event_id": "evt_<id>",
  "event_type": "step_blocked",
  "occurred_at": "<timezone-aware ISO8601>",
  "run_id": "run_<id>",
  "step_run_id": "step_<id>",
  "task_ref": {"task_id": "<id>", "revision": "<rev>", "sha256": "<actual>"},
  "asset_ref": {"research_id": "R42", "content_version": "0.1.0", "skill_version": "0.1.0", "contract_version": "0.2.0", "evaluator_version": "0.1.0", "engine_sha256": "<actual>"},
  "actor": {"kind": "engine"},
  "execution": {"mode": "rule_only", "model_calls": 0},
  "authorization": {"internal_research": true, "public": false, "training": false},
  "payload": {"reason_code": "missing_requirement_baseline"},
  "payload_sha256": "<actual>"
}
```

规则：

1. `actor.kind`仅取`engine / host_agent / model / human / external_observation`；模型不得伪写人或试验身份。
2. `execution.mode`沿用`rule_only / host_agent / model_assisted`，实际模型失败与Host接管分别记录。
3. 模型调用保存实际模型标识、次数、延迟、可用用量与错误；没有数据则为null，不填0。
4. 授权是本次记录的处理范围，不是永久授权；公开和训练默认false。
5. 服务端生成事件身份并校验SHA、引用和顺序；调用方不能覆盖既有事件。

## 最小事件类型

- `method_selected`：候选、选择理由、是否人工改选及替代方法。
- `input_checked`：已绑定、缺失、未知、假设和需追问项。
- `step_started / step_completed`：步骤版本、实际执行者与产物引用。
- `step_blocked / step_returned`：原因码、目标步骤、所需证据或决定。
- `artifact_drafted / artifact_submitted / artifact_revised`：前后Artifact、修订字段和理由。
- `review_recorded`：审核角色、范围、发现、结论和证据。
- `feedback_recorded / outcome_recorded`：精确关联任务、路线、主张、方法和版本。
- `run_completed / run_failed`：终态、未完成项和错误；无推荐也是合法完成。

同一动作重试使用新事件和相同幂等键；相同载荷返回原结果，不同载荷拒绝，不能制造重复成功。

## 人工修改与真实结果

人工修订保存`before_ref / after_ref / changed_fields / reason / actor_role`。字段变化不自动代表质量提升，必要时应保留文本差异供授权复核。

Outcome至少区分：

1. 学习：哪个未知被减少，哪个仍未知。
2. 决策：哪个保留、改选、排除或不推荐决定发生变化。
3. 主张：`supported / refuted / pending / inconclusive`及检验定义。
4. 采用：研究计划、路线或产物是否被有权角色实际采用。
5. 工程结果：仅来自授权实测或现场记录，写明配置、范围和不可外推边界。

项目后来成功不能单独归因于某方法；方法贡献需要过程证据，效果比较沿用ML-024的A/B/C/D同任务、同预算、同模型配置对照。

## 指标与解释

指标必须按任务类型、输入就绪度、执行模式、资产版本和时间窗口分组，并显示样本量与缺失量。首批只看：

- 方法选择后的采用、改选和放弃。
- 输入澄清、步骤阻塞、返工和停止原因。
- 人工修订字段、重复修订模式和审核发现。
- 未知减少、决策变化及Outcome状态。
- 模型调用、耗时、失败和成本。

不建立跨方法统一“成功率”或综合价值分。小样本只描述本次记录，未评不画0，未知不纳入通过。

## 版本变更提案

```json
{
  "proposal_id": "mcp_<id>",
  "research_id": "R42",
  "base_asset_sha256": "<actual>",
  "evidence_event_refs": ["evt_<id>"],
  "pattern": "把验证计划覆盖误述为已经验证",
  "hypothesis": "增加计划与结果互斥检查和Skill停止提示可减少该错误",
  "change_scope": ["skill", "contract", "evaluator"],
  "expected_effect": "固定负例被阻断，既有正例无回归",
  "regression_set_ref": "<versioned-ref>",
  "holdout_set_ref": "<versioned-ref>",
  "risks": ["可能把合法的历史实测记录误判为计划"],
  "status": "draft"
}
```

单个反馈可以形成线索，但不能直接形成发布结论。聚合发现必须能回到原事件；提案作者与独立审核者分离。

## 发布生命周期

`draft → proposed → evaluating → release_candidate → released → deprecated`

1. 内容、Skill、Contract、Evaluator按各自语义版本升级；破坏性契约变更升大版本。
2. 候选版与基线使用相同任务、预算和模型配置回放固定正例、负例及留出任务。
3. 硬负例不得回退；效果无提升也是有效实验结论，不得挑选有利结果。
4. 独立审核确认变更范围、证据、兼容性和权限后，才可成为release candidate。
5. 先本机受控试用，再决定是否扩大；生产发布另立任务。
6. 回滚只切换新指针并保留事件，不删除或改写已发布版本；旧Run始终绑定原版本。

## 可选MCP扩展

新增学习能力使用独立可选入口，至少提供只读时间线/版本查询，以及受权限控制的反馈/事件追加和变更提案。旧工具不变；写工具必须标注副作用、授权、幂等和精确版本，不通过只读注解推断权限。

## 第一批验收清单

- [ ] 六个现有契约方法的选择、输入、步骤、产物、审核和终态可形成完整时间线。
- [ ] R48/R17/R42能回放割胶固定样例，所有事件和产物指纹可复核。
- [ ] 缺输入、未知、版本变化、重复提交、模型失败和Host接管均保留真实状态。
- [ ] 人工修改前后稿可对照，Feedback不改变原Artifact、ResearchPack或公共事实。
- [ ] public/training默认false，未授权记录不能进入公开聚合或训练导出。
- [ ] 以R42“计划不等于验证”历史问题形成ChangeProposal、固定负例和候选回归报告。
- [ ] 候选版未通过独立审核前不能released，旧Run读取结果保持不变。
- [ ] 至少展示一次“事件→提案→回归→审核决定”的完整证据链，不能只展示调用次数。

## 实现约束

先实现无模型的确定性事件、校验、存储和回放，再接现有Host/模型路径。聚合按需计算并缓存，不在每次读取时重放全库。真实企业数据只在私有环境验收；测试使用隔离临时副本并清理。
