# 129: 需求研究小好引导与画布交接

## 要什么

把 `/needs/` 从分步表单升级为“小好对话引导 + 实时研究任务卡”，保留真实问题 → 参考资料 → 研究路线 → 核对计划四段心智。用户只面对小好一个统一入口，结构化内容始终可见、可改、可返回、可跳过。

完成后可将研究任务包带入 `/canvas/`。画布使用独立工作区，保留用户陈述、目标、约束、参考和未知，不混入割胶演示的证据、子问题、概念或红队结论。

本轮是确定性前端引导与真实数据交接，不是在线多 Agent 研究系统。

## 交互契约

- 首屏突出一个真实问题输入，小好说明会帮助理清任务；动态案例和示例为次级入口。
- 保留 `#steps`、`#task`、`#status`，分别呈现轻量步骤、当前对话/结构化回复、实时任务卡。
- 问题必填，其余可留空或跳过；跳过不等于没有相关资料。
- 参考项目与方法仍为明确选择，不自动匹配；路线由用户选择，可暂不确定，不默认伪装成用户已选。
- 任务卡同步显示用户陈述、期待改变、约束、参考、路线、未知和下一步。
- 小好的提示由确定性状态生成，不宣称语义理解；显著保留“0 次模型调用”。
- 草稿刷新保留，返回不丢输入；存储不可用时保留内存编辑并提示导出。
- 核对页提供导出、复制和“进入推理画布”。交接写同源 localStorage 成功后才跳转。
- 画布导入后使用独立任务 ID 和本地存储键，标题、意图与边界来自任务包。
- 新任务从空证据、空子问题、空概念、空红队记录开始，参考仅为线索。
- 普通编辑只保存本地；只有点击“保存工作区”才写服务器。
- 重置任务只清当前本地任务，不删除服务器历史修订。

## 不做什么

- 不接在线模型，不实现真实多 Agent 编排，不伪造检索、思考或执行进度。
- 不将用户陈述自动写成事实、客户确认需求、专家结论或工程验证。
- 不在新任务中展示割胶演示证据、概念、红队或冻结引擎候选。
- 不为新任务套用割胶 GDRP 冻结包；未实现通用导出前明确禁用。
- 不改变公开路由、导航、源项目事实、MCP、权限或生产数据。
- 不引入框架或新依赖，不部署生产，不提交 Git。

## 实现约束

- 沿用 GoodDesign UI、现有品牌资产和原生 HTML/CSS/JavaScript。
- 改版模式为 preserve，设计参数：变化度 4、动效 2、密度 6；减少动态偏好完整降级。
- 保留现有动态案例及其独立状态，保留 074 的核心 DOM 和导出边界。
- 交接协议：`gooddesign-canvas-handoff-1.0`，内含随机任务 ID、创建时间和 `gooddesign-research-packet-1.0`。
- 导入必须校验 schema、状态、必填字段和边界值；失败不得静默打开演示冒充成功。
- 演示工作区兼容现有本地键与导出；新任务使用独立键。
- 静态资产与 API 同时兼容根路径、旧 `/inno/canvas/` 和本机预览。
