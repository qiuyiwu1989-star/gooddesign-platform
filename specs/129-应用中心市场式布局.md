# 129 应用中心市场式布局

用户判断：128 的商店化简化仍太复杂，本质是控制台思路（三栏、侧栏计数、状态筛选、常驻详情栏）。本规格推倒布局重来，按应用市场的人机交互重做：单一视觉流，详情按需出现。数据层（apps.json 的 value/developer 等 Manifest 字段）不变。

## 布局

```text
标题「应用中心」+ 一句话 + 搜索框
分类页签（全部/内容学习/创新研究/接入扩展，无计数）
卡片网格（auto-fill，无侧栏、无第三栏、无底部规划区与案例区）
点卡片 → 详情弹层（原生 dialog）
```

- 卡片：图标 + 状态徽章 / 名字 / 价值一句 / 底部「开发者 · 分类」。卡片即入口。
- 详情弹层：大名 + 状态徽章 + 价值 + 分类/状态/开发者三行 + 案例卡 + 主按钮进入应用。Escape、点背板、关闭按钮均可关闭，关闭后焦点回到来源卡片。
- 状态只靠徽章表达，不再有状态筛选器；分类页签不带计数。
- 页面内容宽降为 1200px（市场内容宽度，不再是 1680px 控制台）。

## 移动端

760px 以下双列紧凑网格；详情弹层变为底部抽屉（width 100%，顶圆角）。

## 实现要点（含踩坑）

- 弹层为原生 `<dialog>` + showModal；`aria-haspopup="dialog"`；reduced-motion 关闭入场动画。
- 踩坑：selectApp 引用了 `app-detail-badge` 但首版弹层 HTML 没有该元素，点击卡片静默失败（TypeError 中断在 showModal 之前）。修复后把 `app-detail-badge` 加入 101 标记锁定。
- 弹层 hero 内徽章须 `justify-items:start`，否则被 grid 拉成全宽条。
- 无 JS 时卡片不可点属预期降级；首案例链接服务端直出（/cases/chang-e/）。

## 测试

- 101/103/109 标记集改为市场结构（app-store、app-store-tabs、showModal、auto-fill 网格等）；095 改查 data-app-kind 与首案例链接；浏览器 096 改为弹层流程（打开/内容联动/关闭）+ 分类页签计数（2/3/2/7）。
- 25 项相关回归通过；全量 unittest 通过。
- 浏览器验收：1440 桌面（四列网格 + 居中弹层）、窄视口（双列 + 底部抽屉）、深色（色调与对比正确）、Escape 关闭并焦点返回。

## 不做

- 不改 apps.json 数据契约与 registry。
- 不恢复任何被删区域（侧栏、状态筛选、底部案例区、应用规划）。
- 部署沿用 128 收窄脚本（仅 inno/apps/ 三文件）。
