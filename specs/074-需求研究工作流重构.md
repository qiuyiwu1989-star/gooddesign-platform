# 074: 需求研究工作流重构

## 要什么

重新思考 `/inno/needs/` 的产品定义、布局和交互。它不再是四步表单，而是研究任务工作台：帮助用户把真实问题转为可验证、可交接的研究计划。

核心流程：真实问题 → 参考资料 → 研究路线 → 核对计划。首屏与每步都显示当前判断、未知和下一步。

## 产品原则

- 先理解任务，再选择方法，方法不得先于问题。
- 已知、用户陈述、待确认和平台模板分开，未知不得自动填值。
- 参考项目和方法只作为研究上下文，不证明迁移可行。
- 路线只提供不同研究机制，不给无依据最优排名。
- 每步可返回、保留草稿，允许跳过可选参考。
- 导出研究上下文，不宣称自动分析、客户确认或工程验证。

## 不做什么

- 不调用模型，不伪装语义理解、自动匹配或实时研究。
- 不把模板路线称为 AI 推荐或企业结论。
- 不改变现有生产页、研究数据、MCP 或权限。
- 不强制填写可选字段，不在离开步骤时丢失输入。

## 验收清单

- [x] 桌面左侧步骤/中间任务/右侧判断三层结构清晰，移动端自然单列。
- [x] 问题输入、参考项目与方法搜索/选择/移除、路线比较可用。
- [x] 未知与待确认补充可见且持久，补充不自动确认需求。
- [x] 草稿刷新保留、返回修改保留、空态与错误提示自然。
- [x] 可导出 JSON，并在原生对话框中预览、全选和用系统快捷键复制研究交接。
- [x] 无模型调用、无假进度、无链接箭头，完整浏览器回归通过。
