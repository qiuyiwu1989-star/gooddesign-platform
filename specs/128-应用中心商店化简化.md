# 128 应用中心商店化简化

用户反馈：应用中心复杂的字还是太多，要让人一眼看去就是应用中心。每个应用必须直接呈现五件事：分类、名字、价值、开发人员、案例。

## 设计规则（替代 109 的部分内容密度规则，三栏骨架不变）

### 卡片（商店式）

每张卡只承载：图标 + 状态徽章 / 应用名 / 分类（色调文字）/ 价值一句话 / 底部「开发者 · 案例」。删除用户·任务行、长摘要、交付物标签、"打开"幽灵文字。

### 详情面板

当前应用名 + 主按钮 + 价值一句 + 三行信息（分类/状态/开发者）+ 案例卡（标题/摘要/边界/完整案例链接）。删除适用人群/当前任务/应用状态 meta、交付物 chips、编号案例路径。

### 侧栏与结构

- 场景导航改名"分类"，状态计数保留（承载 现在可用/试点推进/规划建设 口径）。
- 共享底座框简化为一句话："所有应用使用同一份项目证据，不重复建设。"删除三枚链条 chips。
- 删除底部"应用规划"区（与侧栏状态重复）。
- 底部案例区标题简化：应用案例。
- 主标题：选择应用，直接打开。辅助：点选卡片，右侧查看价值、开发者与案例。搜索占位：搜索应用。

## 数据契约

apps.json 每个应用新增两个必填字段：`value`（价值一句话）与 `developer`（当前全部为好设计团队）。application.schema.json 同步加入 required 与 properties；registry 版本保持 gd-app-registry-0.1，完整 Manifest 字段（summary/inputs/capabilities 等）继续供 Agent 读取，简化只发生在展示层。

## 边界

- 价值一句话是新表达，不虚构能力：每个 value 与该应用真实状态一致（如画布"把每次推理和取舍存成版本"对应 113 持久化）。
- 案例名为纯文本展示，链接在详情面板；卡片仍是 button，不嵌套链接。
- 搜索 haystack 同步改为 title/value/developer/summary/output/分类。
