# 102 可视化报告模板结构 V0.1

状态：本地标准草案，未上线、未接自动渲染器。
关联：099 创新研究输出物标准（GDRP V0.1）定义 `research-pack.json` 的结构；本规范定义把该 JSON 呈现给人看的 HTML 报告模板结构。割胶填充示例见 `04-知识库/项目档案标准-v1/创新研究输出物标准-v1/templates/report.html`。

## 1. 定位

报告是研究包的"阅读层"，不是后台界面，也不是宣传页。它服务三类读者：决策者（30 秒）、审阅者（5 分钟）、复核者（深度）。模板只搬运 research-pack 的字段，不发明事实；未知、待审、未授权状态必须原样可见，不能因排版美观而省略。

## 2. 三层阅读结构

- L1 决策层（30 秒）：任务身份、一句结论、候选数量、无推荐原因、下一步动作、审核状态。
- L2 审阅层（5 分钟）：问题与边界、案例与机制、功能与概念、比较与推荐门禁、验证计划、领域扩展。
- L3 复核层（深度）：执行记录、证据清单、来源版本、权限与边界、文件指纹。

## 3. 固定章节骨架

0. 报告封套：任务名、任务 ID、版本、交付层级、引擎版本、执行模式、状态徽标。
1. 决策卡：`recommendations` 状态、判断矩阵统计（如 60/60 unknown）、无推荐原因、下一步（如 G0）。
2. 问题与边界：需求分组列表（硬性标记、状态、验收口径）、未确认条件、研究边界。
3. 案例与机制：每个来源案例一张卡，含可借鉴机制、关键差异、不能迁移、证伪路径、迁移状态。
4. 功能与概念：功能清单、流与接口、机制选项按功能分组、概念组合 C0 起的架构说明。
5. 比较与推荐门禁：候选 × 准则矩阵（紧凑单元格）、敏感性、未知说明、推荐必须满足的条件。
6. 验证计划：门禁序列 G0 起的阶段卡，含目的与状态；需求到验证方法的映射摘要。
7. 领域扩展：product / engineering / ai4s 三个标签页，字段来自 domain_extension，空数组如实显示为空。
8. 执行、审核与版本：执行模式、模型调用真实状态、方法版本、审核五状态、来源版本清单。
9. 附录：证据与来源：证据条目计数与示例定位方式、边界 notes 原文、manifest 说明。

## 4. 版式与视觉规则

- 浅色编辑式版式：浅灰页面底、白色内容面板、深色封套头、单一紫色强调 #5a4fe6。
- 桌面左侧固定章节导航（sticky），移动端退化为顶部横向可滚动章节条。
- 领域扩展用原生 button 标签页，JS 仅切换 hidden 与 aria-pressed，键盘可达。
- 比较矩阵用 CSS grid 紧凑单元，单元内只放状态字（如"未知"），说明文字放矩阵下方，不做 60 张大卡。
- 不使用箭头符号做装饰；链接无箭头后缀。页面正文不得出现 `—` 或 `–`，分隔用中文冒号、顿号、"至"或普通连字符。
- 打印友好：打印时隐藏导航，矩阵保持完整；支持 prefers-color-scheme 暗色变量。
- 不放图片占位、不放假数据、不放假截图；所有数字必须来自 research-pack。

## 5. 事实完整性门禁

- `recommendations=[]` 必须以文字明示"本次不给出唯一工程推荐"，不得弱化。
- 全部 unknown 的判断不得被颜色暗示为通过；unknown 用中性色。
- 模型调用失败（如 429 超时）必须如实写明，不得隐藏。
- 审核五状态（客户确认、语义复核、领域专家、工程验证、公开授权）逐项可见。
- hard=null、proposed、unknown 等原始状态值原样呈现，不升格。

## 6. 与后续渲染器的关系

本文件只定义模板结构与填充示例。将来实现 JSON 到 HTML 的渲染器时，渲染器必须逐字段消费 research-pack.json，校验 schema 与 manifest 后才允许生成；模板中的任何静态示例文字不得成为渲染器的兜底内容。
