# 070: 旧站资产迁移与 /inno/ 主项目区收口

## 要什么

用户明确：`opendesign.cc/inno/` 作为好设计唯一的主要项目区。`gooddesign.qiuyiwu.com` 不再承担长期平行频道定位，转为旧站资产来源；有价值内容、交互与服务逐项迁移并验收后，再退役旧频道。

迁移必须保持真实项目 ID、内容来源、公开/私有权限、既有深链和用户已验证功能，不因换域名复制出第二套长期内容真源。

## 不做什么

- 不现在直接关闭旧站、删除服务器文件、修改 DNS 或中断现有 Node API。
- 不机械复制整个旧站，不搬入会议原文、密钥、私有原件或内部工作文件。
- 不在迁移期间同时维护两套持续更新的栏目、导航和内容版本。
- 不用静态截图或预置动画冒充原互动展项、模型问答、教师工作台和企业提交能力。
- 未完成替代能力、重定向和回滚验收前，不宣布旧频道退役。

## 资产映射基线

以下目标路由为迁移建议，不代表已经上线：

| 旧站资产 | 目标区域 | 迁移要求 |
|---|---|---|
| 项目、奖项与知识页 | `/inno/projects/`、建议 `/inno/awards/` | 保持项目ID和详情深链，区分题录与研究版 |
| 数字馆、主题展区、互动展项 | 建议 `/inno/museum/` | 保留大屏与互动体验，逐展项验收，不强套阅读模板 |
| 科技教育、课例、课件 | 建议 `/inno/learn/` | 保留课堂、打印和学生使用场景 |
| 教师工作台与备课工具 | 建议 `/inno/teacher/` | 验证保存、复制、打印、导出和移动操作 |
| 企业创新 | `/inno/needs/` 与 `/inno/loop/` | 076已定义任务工作台；预置演示、实时研究和企业确认继续分开，生产迁移另验 |
| 智能助手 | 作为全站辅助能力，独立入口另评估 | 先升级为有项目版本和证据的回答，不直接平移启发式引用 |
| 企业提交与 Node API | 对应新应用服务 | 替代持久化、权限、通知和实际提交验收后再切换 |

## 验收清单

- [ ] 旧站资产按内容、交互、服务、媒体、权限、SEO 六类盘点，标记迁移/合并/归档/放弃。
- [ ] 每项有价值资产有唯一目标 URL、内容真源和验收人，旧新内容不双向分叉。
- [ ] 公开阅读、私有原件和管理权限分别测试，私有资产不进入公开构建。
- [ ] 关键旧功能用真实操作验收，不只检查页面存在。
- [ ] 建立旧 URL 到新 URL 的 301 映射，验证项目深链、锚点、资源路径和外部分享链接。
- [ ] 完成移动端、桌面、打印、错误恢复和浏览器回归。
- [ ] 保留旧站只读回滚版本，确认新主站可独立运行后再安排旧频道退役。
