# 041 工作区减负与阅读路径

## 要什么
用户反馈当前几个页面复杂，授权三小时自主安排与完善。本轮先收拢工作区，让人清楚知道在哪里、下一步做什么。
- 同一私有本地服务提供项目档案、资料管理、创新研究三个稳定入口，保留项目上下文。
- 资料管理默认只看文件；审核与处理记录按任务切换；项目筛选及文件元信息适当收起，列表分页。
- 创新研究默认简洁呈现结论，分析路径以三方法串联；细节/原文按需展开，证据原位查看。
- 档案继续沿用八模块阅读格式，不重新设计数据标准。人工整合底稿与管线研究版本清楚区分。
- 保留旧深链接、原始数据、事实/AI标记、原件下载、真实SDK重放和安全边界。

## 不做什么
不新增方法、全库研究、自动语义调度或生产部署；不以UI整理改变源案例、评分、审核状态；不把模拟建议当企业验证成果。

## 验收
- [x] 三入口在同一端口正常工作、当前入口清楚；跨项目不误展示嫦娥研究。
- [x] 文件/审核/记录同一时间只展示一个；刷新、旧锚点、前进后退及筛选保持。
- [x] 文件分页、上传/网络保存、原件/PDF/图片、审核流程保持可用。
- [x] 研究默认页无技术JSON与密集编号；三方法步骤与证据仍可查看，原位证据能返回原上下文。
- [x] 无JavaScript时仍可读取基本内容；键盘、390px与桌面布局无页面溢出。
- [x] 方法库/研究管线/私有归属/API回归通过；浏览器逐项测试。
- [x] 新运行记录/离线包使用新展示，历史运行文件不覆盖；数据与事实指纹保持。
