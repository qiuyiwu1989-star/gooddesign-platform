# 125：MCP 密钥申请、管理与使用回流 v1

## 状态
draft：2026-11-14 应用户要求编写。用户原话：要做密钥的申请与管理工作，通过密钥看得到使用情况与数据回流。依据 00-项目管理/密钥轮换台账.md 的流程与行动方案第 2 步缺口（吊销、审计日志）。

## 要什么

1. 密钥注册表（SQLite，服务器私有路径）：每把钥匙有归属（对象/用途/环境/期限）、状态（pending/active/revoked/expired）、签发与吊销时间。只存 token 哈希，不存明文。
2. 申请流：申请人提交四要素（谁用/干什么/在哪跑/用多久）→ 管理员批准即签发（明文只显示一次）或驳回留理由。
3. 管理操作：吊销、轮换（签新废旧）、延期；全部留操作记录。
4. 网关接入：每次调用按 key 归属记录使用（时间、工具、参数摘要如检索词与项目 ID、结果状态、耗时）；revoked/expired 返回 401。兼容现有 keys.json（导入迁移，哈希不变）。
5. 管理台（loopback 本机）：申请、密钥、使用三个视图；使用视图按 key 聚合（调用量、工具分布、最近活跃、在挖什么）。
6. 数据回流 v1：使用日志即回流信号（外部在检索什么项目、什么关键词、组了什么包）；研究包回传仍走 065 外部投递，本 spec 不新建回传通道。

## 不做什么

- 不建公网自助申请页（本轮申请经本机管理台录入）。
- 不改 MCP 八工具契约与返回内容。
- 不存密钥明文、不存完整请求体、不建远程管理员账号。
- 不动现有签名 Cookie 登录体系；本系统只管 MCP Bearer。

## 验收清单

- [x] 申请 → 批准 → 明文只显示一次 → 网关可用；驳回留理由。
- [x] 吊销与过期后网关 401；轮换后旧 key 立失效、新 key 可用。
- [x] 使用记录按 key 可查：调用次数、工具分布、检索词摘要、最近活跃。
- [x] keys.json 既有哈希导入后原 token 不间断可用（生产实测哈希一致）。
- [x] 新域名 mcp.haosheji.cc 进入网关 allowed_hosts/allowed_origins（DNS 与 nginx 待补，见台账）。
- [x] 管理台仅 loopback，POST 有 CSRF 与 Host 检查，无明文 token 出现在列表页。
- [x] 单测覆盖签发/吊销/轮换/过期/使用记录/兼容导入（12 项）。
