# 100：项目档案数据治理与双视图打磨

日期：2026-11-05  
状态：approved（用户确认按既定顺序执行）  
范围：560 个项目的资料、103 个已有原生研究版及后续新增档案

## 要什么

把项目库从“文件和来源数量已形成规模”推进为“真源明确、证据可查、质量状态诚实、人读顺畅、Agent 可安全调用”的项目档案体系。

执行顺序固定为：

1. 备份并验证私有资料可恢复。
2. 重建统一素材基线、统计口径和重复资产索引。
3. 定义最小可用档案（MVA）、sources、claims 与入库门禁。
4. 优先打磨已有 103 个原生研究版，先做 10 个试点。
5. 从同一真源生成人读视图与 Agent／维护视图。
6. 试点验收后逐批扩展，不把 457 个未研究项目包装成已完成档案。

## 不做什么

- 不直接批量改写 560 个项目的研究真源。
- 不删除重复文件；先建指纹、规范来源和引用关系。
- 不把机器抽取、OCR、Agent 初评或页面美化升级为人工核读、专家审核或工程验证。
- 不为了填满字段而补造事实；未知、冲突、未研究和未评分别保留。
- 不用来源数、字段数、文件数或测试数代替内容质量。
- 不在本任务中迁移数据库、对象存储或发布生产；这些另行授权与验收。
- 不收编或覆盖其他会话的未提交修改，不执行 Git 提交、推送或发布。
- 不公开私有原件、内部路径、凭据或未经公开授权的材料。

## 统一口径

- `catalog`：560 个项目题录，只代表收录。
- `native_research`：已有原生研究版本，不代表已审核。
- `source_asset`：登记的资料资产，必须区分原件、衍生可读件、摘录与 AI 整理。
- `claim`：一条可独立判断的项目陈述，必须能回到当前研究版本与证据。
- `known_cell`：已有值的字段，不等于已核实事实。
- `agent_assessment`：绑定具体档案指纹的机器评估，版本变化后失效。
- `human_review`、`expert_review`、`engineering_validation`：分别记录，不得互相推导。
- 公共统计必须带范围、分子、分母、快照时间和数据版本。

## MVA 最低要求

每个进入“已建立研究档案”范围的项目至少具有：

1. 稳定项目 ID、正式名称、奖项与年份。
2. 当前研究版本及不可覆盖的档案指纹。
3. 来源登记、资产类型、读取范围、项目关系和父子件关系。
4. 事实、平台解读、未知与冲突分层。
5. 每条已发布 claim 的来源定位与证据状态。
6. 机器整理、人工核读、Agent 评估、专家审核与工程验证的独立状态。
7. 人读入口与维护入口，二者读取同一真源。
8. 明确缺口和下一步，不用空白或 0 伪装已知。

## 验收清单

### A. 备份与基线

- [x] 原始资料与知识库存在独立副本，凭据类文件不进入副本。
- [x] 源与副本的文件数、字节数一致，关键真源 SHA256 一致。
- [x] 能从副本读取项目索引及至少一个研究版本，不依赖源目录。
- [x] 新素材总表使用最新实测数据，旧快照保留但不再标为当前。
- [x] 重复资产索引区分模板重复与内容重复，无删除动作。

### B. 真源与门禁

- [x] MVA、sources、claims 有版本化规范及 JSON Schema。
- [x] 路径越界、非法角色、未知来源、错误父子件关系会阻断入库。
- [x] 原件与衍生件不得仅凭相同文本登记成两个独立证据。
- [x] 评估指纹与当前档案不一致时，公共视图不显示旧分。
- [x] 未评、待复评、未研究、未知、冲突在数据和页面上分别呈现。

### C. 试点打磨

- [x] 10 个试点均有打磨前后清单，记录改动文件和事实／字段差异。
- [x] 纯阅读优化前后事实数、claim、证据、评分与研究版本不变。
- [x] 真源修订必须新建版本，旧版本不覆盖，并给出变更理由。
- [x] 人读主路径无研究编号、哈希、字符区间、内部路径和 Agent 工作指令。
- [x] 维护视图保留完整定位、版本、读取范围和机器状态。
- [x] 页面明确机器整理与人工／专家状态，不因美化自动升分。

### D. 回归与扩展

- [x] 每个试点运行对应结构测试、真源一致性测试和浏览器阅读检查。
- [x] 560 项目既有索引、路由和其他项目档案回归通过。
- [x] 试点验收后才形成下一批队列；457 个未研究项目继续标为未研究。
- [ ] 数据总览只从统一快照生成，人读与 Agent 数据不分别手填。
