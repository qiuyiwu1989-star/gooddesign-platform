# ML-028 方法能力地图与引擎调用

状态：approved（2026-11-05，用户确认继续；候选地图，未接生产路由）

## 要什么

建立64个方法与 specs/098 引擎S0—S10之间的能力语义层。引擎按能力缺口、输入就绪度和产物需求发现方法，而非只按名称、分类或固定六方法链调用。地图同时服务网页、Skill、MCP和后续运行反馈。

## 不做什么

- 不修改64份冻结档案、六契约或现有18/20/22 MCP入口。
- 不为58个非契约方法虚构标准Artifact、求解器或自动执行能力。
- 不把分类映射当成语义专家审核，不直接替换生产路由。
- 不让所有方法机械覆盖S0—S10，不建立固定“每个方法都必须执行”的流水线。
- 本轮不调用模型、不运行割胶应用案例、不部署。

## 核心调用逻辑

```text
Task + Evidence + Artifact
  → CapabilityRequest
  → 候选方法及精确版本
  → 输入/权限/成本检查
  → MethodPlan
  → S0读取 / S1引导 / S2契约执行
  → Artifact或受限研究草稿
  → 跨方法交接、运行事件和反馈
```

`CapabilityRequest`至少包含能力、任务版本、已有Artifact、目标逻辑产物、交付层级和未知保留要求。路由返回候选、缺失输入、执行等级、预期产物、关联方法及限制，不只返回方法名。

## 能力 taxonomy

首版28类：`process_orchestration`、`evidence_collection`、`need_interpretation`、`problem_framing`、`requirement_deployment`、`function_modeling`、`causal_analysis`、`concept_composition`、`analogy_generation`、`concept_transformation`、`contradiction_solving`、`architecture_analysis`、`mechanism_synthesis`、`material_selection`、`manufacturability`、`structural_optimization`、`concept_comparison`、`experiment_design`、`risk_analysis`、`verification_validation`、`sustainability_assessment`、`value_analysis`、`technology_intelligence`、`quality_evaluation`、`intelligent_system_design`、`method_governance`、`service_design`、`research_prioritization`。

每项能力声明中文名、可覆盖引擎阶段和逻辑产物。逻辑产物用于路由，不代表已有JSON Schema；六契约的Artifact类型以冻结Contract为准。

## 每方法映射字段

- 身份：research_id、method_id、kind、内容版本与SHA。
- 能力：一个primary_capability及必要secondary_capabilities。
- 阶段：可参与的S0—S10，不表示每次都必须执行。
- 档案输入/产物：从原Dossier提取键、必需性和输出键。
- 逻辑产物：供引擎路由的标准语义类型。
- 执行：S0/S1/S2、原execution_status、契约版本与SHA或null。
- 关系：原Dossier的替代、组成、前置、并行关系。
- 边界：内容、审核、工程验证和地图语义复核状态。

S0用于研究_only专题；S1用于可引导但无严格契约的方法；R48/R14/R17/R36/R44/R42为S2。计算型档案没有实际求解器时仍为S1，不能返回数值计算结果。

## 引擎阶段关系

- S0/S10：资产、权限、版本、运行和学习治理；不是设计要求所有方法参与的阶段。
- S1：证据、需求、问题与要求。
- S2：功能、接口与逻辑架构。
- S3—S5：检索、案例、机制抽象、迁移和矛盾。
- S6—S7：选项、组合、架构、材料、制造与优化。
- S8：比较、风险、价值、质量和研究优先级。
- S9：原型、试验、验证、确认与结果边界。

方法可以跨阶段，但调用时只执行当前能力对应的步骤。框架方法提供编排，不被误当成一个巨大自动计算节点。

## 产物与交接

首版生成`能力地图.json`和`能力矩阵.md`，保存于独立`能力地图-v0.1`目录。JSON包含能力定义、阶段索引和64方法条目；Markdown供人工审读，二者由同一脚本生成。

原Dossier输入输出与引擎logical_outputs分栏保存。后续建立正式执行契约时，再把logical_outputs绑定到具体Schema，不能反向把地图字段当成运行证明。
