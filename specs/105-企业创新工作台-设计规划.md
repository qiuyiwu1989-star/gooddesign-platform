## 节点数据模型 v0.1
每个节点：id、标题、AI 角色、方法引用、状态（待开始 / 进行中 / 已定稿 / 待复核）、痕迹（按节点类型的结构化 schema）、旁注列表。

状态机：已定稿节点被重新打开，则所有下游已定稿节点转为待复核；待复核经人确认「仍然成立」后回到已定稿。此规则直接产品化了企业创新协作要求的最小验收（纠正后旧研究显示待复核）。

痕迹 schema 按节点类型，并与企业创新交付结构对应：
- 发问：意图证据图（事实 / 需要 / 偏好 / 假设 / 待补证）→ 对应问题卡
- 查证：证据条目 + 逐条裁决（采信 / 存疑）+ 来源编号 → 对应证据卡，来源走 MCP 只读工具可回溯
- 拆问题：子问题分解 + 拆解理由
- 发散：概念卡集合 + 毙掉留痕（划线保留、可恢复）→ 对应方案卡，至少两种方向可比较
- 质疑：红队意见 + 逐条裁决（接受则写入免责声明 / 驳回须留理由）
- 取舍：逐概念优先级 + 取舍理由；AI 不介入
- 立约：逐路线验证方法与停止条件 + 签署状态 → 对应验证记录

## 交互模式清单（demo 已验证）
点选节点切换详情、证据采信/存疑、毙掉并保留痕迹、恢复方向、红队接受/驳回、优先级选择、取舍理由、承诺签署、三种身份旁注（我 / 顾问 / 专家）、导出 Markdown、确认后重置。状态当前为 localStorage 持久化。

## 风险与取舍
- 粒度：一个节点等于一次有意义的思考动作，不是每条 prompt；过细会把设计师变成填表工。
- 过度结构化：跳节点、回退、捞回被毙方向必须自由，否则结构杀死发散。
- AI 喧宾夺主：取舍节点不介入；红队意见人可驳回。
- 画布是视图不是真源：真源是痕迹数据模型，画布只负责渲染与采集。
- 与 098 的关系：七节点是人的思考模型，S0-S10 是机器执行骨架，二者在发散/质疑/立约处衔接，不做牵强的一一映射。
