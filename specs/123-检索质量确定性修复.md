# 123 检索质量确定性修复

110 评估结论规定：model_assisted 之前必须先完成两件确定性修复——匹配体归一化（换行缺口）与查询词源语汇化（抽象词零触达预警）。本规格只包含这两项确定性改动，不做语义召回、不扩库、不改任何事实/评分/冻结产物。

## 修复一：匹配体归一化（046 模块 innovation_knowledge.search）

问题：匹配体由 `json.dumps(value)` 生成，正文中的换行被转义为两字符 `\n`，含换行的自然语言查询必丢。基线自召回 318 项检查 15 项未中，未中窗口全部含换行。

修复：匹配前对匹配体与查询项做同一种归一化——先移除 JSON 转义空白序列（`\n`、`\r\n`、`\r`、`\t` 的两字符形式），再移除全部空白字符（含全角空格），最后 casefold。

性质与边界：

- 单调性：旧命中不会丢失。旧命中 Q 是匹配体 B 的子串，归一化在两侧移除相同位置的字符，故归一化后仍是子串；召回只增不减。
- 这仍是逐字匹配，不是相似度、不是语义召回；归一化只消除排版空白差异，不引入任何新事实或新候选语义。
- match_reason 如实更新为空白归一化后的逐字匹配。
- 影响面：ik.search 的全部调用方（file_admin、archive_mcp、expo_agent_server、innovation_application、innovation_retrieval_v1、retrieval_eval_v1）共享同一修复，无需各自改动。

## 修复二：查询词源语汇化预警（innovation_retrieval_v1.build_queries）

问题：功能抽象词（verb_object）是任务侧语言，不是源语汇；110 基线显示割胶 7 个抽象词全库零触达，而此前无 hints 时静默空结果。

修复：build_queries 为每条检索计划增加确定性标注：

- `source_vocabulary: true/false`——query_terms 是否来自人工 query_hints。
- 无 hints 时附加 `zero_recall_warning`，说明 110 基线抽象词全库零触达、预期零召回、应先补源语汇 hints 或词汇映射。

边界：预警只是标注，不改变检索行为本身；query_terms 的回退逻辑（无 hints 用 verb_object）保持不变；engine_run.queries 会带上标注，不影响 research-pack 的 Schema 与指纹锁定段。割胶冻结样例 run-20261105T140200Z 不重算、不覆盖。

## 不做

- 不做语义召回后端（110 结论：有价值但属第二路召回，只能扩召回，另立任务）。
- 不解决 460 个不可检索项目的扩库问题（100 治理线负责，本任务不动）。
- 不改评估集与冻结基线报告；修复后重新测量并另存新报告（生成即冻结）。
