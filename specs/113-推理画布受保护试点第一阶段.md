# 113: 推理画布受保护试点第一阶段

## 要什么

把本机推理画布从 localStorage 原型推进到可恢复、可导出研究包的工作台雏形。实现 RC-08 的第一层状态服务与 RC-11 的第一层 GDRP 映射：画布状态以 SQLite 不可覆盖修订持久化，当前状态可恢复；按当前痕迹生成合法 `gdrp-0.1` 研究包。

## 不做什么

- 不做用户登录、企业账号、多租户或生产部署。
- 不改变 076 loop 接口，不把本机画布写成云端企业空间。
- 不接在线模型，不重跑引擎，不让 Agent 写入 approved、confirmed、engineering_validated、expert_reviewed、recommendations 等禁写字段。
- 不覆盖既有冻结研究包；画布导出包独立生成并附指纹。

## 范围

1. `scripts/reasoning_canvas_server.py` 增加本机 workspace 状态 API：
   - `GET /api/rc/state?workspace_id=...` 读取最新状态。
   - `POST /api/rc/state` 追加新修订，携带 `base_revision` 防覆盖。
   - `GET /api/rc/revisions?workspace_id=...` 读取修订列表。
   - `GET /api/rc/gdrp?workspace_id=...` 按当前状态生成研究包。
2. 新增 `scripts/canvas_gdrp_mapper.py`：
   - 以 GD-CRE-0.1 冻结割胶包为领域骨架。
   - 将画布当前证据裁决、毙掉方向、优先级、取舍理由、签署状态、检索留痕、引擎候选确认和推理运行记录映射到 GDRP。
   - 先过 JSON Schema，再输出。
3. 前端增加工作区保存状态与 GDRP 导出入口；本地不可用时保留 localStorage 降级并如实提示。

## 验收清单

- [x] 状态 POST 后生成新 revision，旧 revision 字节不变；重复 base_revision 冲突返回 409。
- [x] 服务重启后 GET 最新状态恢复一致。
- [x] 空 workspace 返回 404，未知端点仍 404，非法 JSON 返回 400。
- [x] 当前状态生成的 research-pack 通过 `research-pack.schema.json`。
- [x] `recommendations=[]` 保留，画布签署状态只影响草稿/待审状态，不冒充真实审核。
- [x] 前端有保存与 GDRP 导出入口；服务不可达时提示且 localStorage 保留。
- [x] 新增专项测试与 RC-01/03 回归通过。
- [x] 不部署生产，不提交 Git。

## 实现约束

SQLite 数据库写入 `output/reasoning-canvas-private/canvas-state.sqlite3`，该目录不入 Git。所有时间使用 UTC ISO；状态 JSON 使用 canonical JSON 和 SHA256。服务仍仅监听 127.0.0.1。
