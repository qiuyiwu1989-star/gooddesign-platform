# 104：企业创新工作台「推理画布」· 产品定义 v0.1

## 状态
v0.1：2026-11-05 起草，当日用户确认方向（"这是好设计的项目，先从好设计创新设计大模型做企业创新工作台应用"，随后确认基于此定义继续）。功能描述见 specs/106，开发任务拆解见 specs/107。

## 一句话
推理画布是好设计创新设计大模型的人机协作工作台：企业设计师与工程师借助大模型做产品创新，整个推理过程变成一张看得见、回得去、改得动的思考轨迹图。

## 在大模型体系中的位置
创新设计大模型是领域智能系统（097 模型页：三层两环一网络，不宣称自研基础大模型）。推理画布是这个系统面向企业创新场景的交互层：

- 098 引擎算法 V1（确定性骨架 + 设计案例推理 + 可选模型辅助，割胶固定样例）是机器侧的推理骨架。
- 推理画布是人的侧的工作台：节点是设计师的思考动作，AI 在节点内有角色，节点之间由人驱动。
- 099/102 GDRP 创新研究包是输出物标准：画布导出的推理档案应能生成 research-pack 与人读报告。
- 076 /inno/loop/ 与 ML-024 企业创新研究闭环是运行底座；推理画布最终与之汇合。
- 能力接入走现有 MCP 只读工具（项目、方法、证据），符合行动方案决策 B「外部小应用 + 现有 MCP」的验证路径。

## 解决什么问题
`00-项目管理/企业创新协作要求.md` 已规定：原始事实、平台假设、专家判断、验证结果四类可辨认；用户纠正后旧研究显示待复核；至少两种方向可比较；验证要有停止条件。今天这些靠文档纪律维持，推理画布把它产品化为交互：

- 推理过程不可见：AI 辅助创新困在聊天记录里，依据丢失、无法复盘。
- 改主意被当异常：企业创新中需求修正是常态，旧结论需要可追溯地失效，而不是被覆盖。
- 评审只看交付物：服务方与专家无法看到判断依据，无法做过程评审。

## 用户与场景
- 企业设计师 / 工程师（主用户）：在画布上推进创新推理，逐节点留下思考痕迹。
- 创新顾问（服务方）：组织企业与专家意见，用推理档案交付与复盘。
- 专家 / 评审：读推理档案，看证据裁决与取舍理由，不只看方案。

## 核心模型：七个思考动作
发问（AI 是书记员）→ 查证（检索员）→ 拆问题（陪练）→ 发散（点子库）→ 质疑（红队）→ 取舍（不介入）→ 立约（档案员）。每个节点回答三个问题：人做什么、AI 帮什么、留下什么痕迹。模型从割胶机器人案例反向抽取（36 次 MCP 检索台账、A-F 六张概念卡、红队免责声明、逐路线 test/stop），只搬运不发明。

## 产品原则
1. 节点是人的思考单元，不是机器任务；图不自动流转，图记录人想到哪了。
2. AI 只在节点内有角色，节点之间由人驱动；取舍节点 AI 不介入。
3. 被毙掉的方向保留痕迹、可恢复，不删除。
4. 每个决定挂理由；证据逐条裁决（采信 / 存疑），来源编号可点击回溯。
5. 改主意是一等公民：重新打开已定稿节点，下游自动标为待复核（与企业创新协作要求的最小验收一致）。
6. 立约：每条路线必须写下验证方法与放弃条件，由人签署。
7. 审计的对象是人的判断依据，不是机器运行日志。

## 不是什么（边界）
- 不是自动化工作流引擎（Opero 式 If/Else 流水线），是人的思考画布。
- 不是项目管理画布（MindSculpt 式任务卡），节点是推理动作不是待办。
- 不是聊天界面；AI 输出未经人确认不写入痕迹。
- 不宣称自主训练基础大模型；不宣称已接在线模型，当前 demo 的 AI 输出为割胶案例真实研究内容。
- 用户体系、状态服务、写路径不在静态站仓库内生长（行动方案决策 B）。

## 验证锚点
- 割胶机器人案例推理已重建为可交互 demo：`割胶机器人创新概念设计/推理画布/index.html`（本仓库外，单文件零依赖）。节点选中、证据裁决、毙掉保留、红队裁决、重开触发下游待复核、导出 Markdown 已在浏览器实测通过。
- 七节点与企业创新协作要求的六类交付结构（企业画像、问题卡、证据卡、方法记录、方案卡、验证记录）可对应，映射关系在设计规划中展开。

## 成功标准
- 一个企业创新项目的完整推理可导出为档案（未来即 GDRP 研究包），他人在不看交付物的情况下也能评审推理质量。
- 企业或顾问修正需求、约束后，相关节点与旧结论自动标为待复核，且能展示实际更新内容。
- 顾问与专家能在任意节点留旁注；每条路线都有签署的放弃条件。
