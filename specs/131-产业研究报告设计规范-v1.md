# 131 产业研究报告设计规范 v1（好设计 · 小好深研）

适用对象：`/expo/` 产业创新 Agent 每次研究产出的正式建议报告（屏幕深色版 + 打印 A4 版）。
读者：地方政府/产业园区/企业决策者（第一层 3 分钟）、产业研究者（第二层 30 分钟）、核查者（附录回查）。

## 1 报告定位

这是一份面向地方政府领导与产业部门的**决策参考报告**，不是技术系统说明：

- 每一节回答"产业基础是什么、关键问题是什么、案例有何启示、下一步如何验证"；
- 核心表达：**先开展验证，再研究推广**；
- 所有判断注明依据情况（依据较充分/部分印证/待进一步核实），所有方向附试点第一步与需要检验的条件；
- 不给推荐排序、不写"最优"、不写无来源数字。这是硬纪律，模板层面保证。

## 2 文档身份

| 项 | 规范 |
| --- | --- |
| 报告编号 | `GD-DR-{YYYYMMDD}-{中文地名}-{深度码}-{版本短码}`；每份报告另有全拼 slug + 独立版本 ID 链接 |
| 标题 | 《{地名}产业 × 好设计创新研究报告》 |
| 副题 | 产业调研与创新路径研究 |
| 研究支持 | 好设计 · 小好深研 |
| 性质 | 决策参考 · 内部研究稿；静态案例明确标为案例演示 |
| 深度 | 速览=快速梳理 / 标准=公开资料核查 / 深研=重点企业逐项核查 |

## 3 结构（章序固定）

1. **封面**：编号、标题、副题、研究支持、日期、研究方式、路径与使用说明。
2. **管理层摘要**：核心判断 ≤5 条（注明依据情况）；附实际资料与研究工作量。
3. **目录**：章节锚点，屏幕版左侧固定。
4. **1 研究思路**：研究问题、研究方法、研究路径、资料口径和研究范围。
5. **2 产业发展基础**：写明研究范围；核心观点注明依据；呈现板块、驱动、关键事实与对标地区。
6. **3 产业链与重点企业**：上中下游结构；每家企业说明研究意义与公开依据，不只罗列。
7. **4 企业需求与主要制约**：企业类型卡与需求表；需求统一标为"待企业确认"。
8. **5 优秀案例的借鉴价值**：本地需求与获奖案例对照；可借鉴做法与适用条件、差异同列；只用真实检索项目。
9. **6 创新方向与试点建议**：章首"先开展验证，再研究推广"；每个方向写依据、试点第一步和需要检验的条件；工作建议为"建议先行试点"。
10. **7 主要资料来源**：公开资料与平台案例分标；来源表带链接，无链接如实说明。
11. **8 需要注意的问题**：企业走访、案例适用条件、平台覆盖与研究方式的相关边界。
12. **附录 A 参考案例索引**：项目名、奖项、档案链接与项目二维码。
13. **附录 B 研究工作说明**：各环节真实计数与耗时，使用"智能分析"等领导可读口径。
14. **附录 C 阅读说明**：依据情况、案例借鉴和智能分析的使用边界。

## 4 措辞规范

- 建议句式："初步判断：……。依据：……。建议先在……开展试点，若……则调整或停止该方向。"
- 案例启示写清可借鉴做法，适用条件与差异必须同段出现；
- 禁词：最优、首选、应该上马、必然、前景广阔（空话）；
- 数字必须有出处或标"待进一步核实"；
- 保持咨政报告的短句与明确判断，不在领导正文暴露 proposed、hard=null、确定性层、逐字召回等内部术语。

## 5 工作量可视化规范

原则：**只展示真实计数，不渲染努力感**。工作量是研究的透明度证明，不是表演。

- 过程态：节点连线标注各环节产出计数（假设数/板块+来源/环节+企业/需求+核证结果/检索词+扫描档案数+召回数/方向数/章节数）。
- 成稿态：管理层摘要一行汇总 + 附录 B 明细表。
- 附录 B 字段：各环节产出计数、库内扫描档案总数、检索词数与轮次、模型调用次数、联网阶段数、总耗时。
- 任何计数必须能从服务端事件流复算；编不出来的量（如"阅读字数"）不写。

## 6 版式规范

屏幕深色版（现有 rdoc 体系细化）：

- 封面独立成屏：编号小字在上、标题大、元信息竖排细表；
- 章节编号 `1`–`8` + 附录 `A/B/C`，h2 带编号，目录同步；
- 表格：发丝线、无竖线、斑马纹关闭、数字右对齐；
- 证据状态徽标三色：支撑（绿）/部分（金）/未知（灰），圆形描边胶囊；
- 引用项目一律给档案深链。

打印 A4 版：

- `@page` A4、页边距上 17mm / 左右 15mm / 下 18mm；封面标明报告编号与密级；
- 封面独占一页；每个一级章另起页；表格避免跨页断行；
- 打印转浅色（白底黑字），状态徽标保留三色（打印可辨）；
- 封面保留本报告专属二维码，扫码可打开该报告并保存独立 HTML；通用导航二维码不进入报告。

## 7 与引擎/合规的接口

- 报告字段全部来自服务端 pack（模型只起草，确定性层才有写入权）；
- `recommendations` 恒为空是合法完成态，模板不补"推荐"位；
- 未知、待核、失败（如某阶段模型调用失败）必须在报告中如实留痕，不得省略；
- 本规范只约束 expo 产业研究报告；GDRP（099/102）是引擎输出物标准，两者字段可对齐但互不替代。
