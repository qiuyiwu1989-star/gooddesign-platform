# 114: 推理画布受保护试点第二阶段

## 要什么

在 113 的本机状态服务与 GDRP JSON 导出基础上，把推理画布推进到可被指定用户试用的最小形态：加入本地三角色权限视图，并把画布导出的 research-pack 渲染成可阅读报告。目标是形成可交接、可审阅、可恢复的研究工作区。

## 不做什么

- 不做真实登录、账号系统、企业租户数据库或生产部署。
- 不把前端角色选择写成真实身份认证；本地阶段只约束界面操作。
- 不接在线模型，不修改 076 loop，不改变冻结研究包。
- 不让顾问或专家角色写入客户确认、工程验证、专家审核或授权字段。

## 范围

### RC-09 最小角色权限视图

- 顶栏提供角色选择：设计师、顾问、专家。
- 设计师：完整编辑、裁决、毙掉、取舍、签署。
- 顾问：可编辑发问意图、子问题和旁注，可导出；不能定稿、改证据裁决、毙掉方向、设置优先级或签署。
- 专家：只读，可添加旁注；不能改任何节点状态或方案内容。
- 旁注默认身份跟随当前角色，不再只靠手选。

### RC-12 GDRP 人读报告

- `GET /api/rc/gdrp_package?workspace_id=...` 返回 research-pack、report.html、report.md 与 manifest。
- 使用 `build_gdrp_report.py` 的现有 render/render_md，不另写事实。
- 未签署画布在导出摘要中明确为 draft；已签署也仅为 review_pending。
- 前端提供“导出完整报告”，下载一个 JSON 包描述四类内容。

## 验收清单

- [x] 三种角色在权限矩阵测试中有明确操作边界。
- [x] 专家角色不能修改节点状态、证据、方向、优先级或签署；可以添加旁注。
- [x] 顾问角色不能定稿、毙掉、改优先级或签署；可以编辑发问意图、子问题和旁注。
- [x] 角色切换后界面立即生效，旁注身份跟随角色。
- [x] GDRP package 端点返回四类内容，report.html 与 report.md 由同一个 pack 生成。
- [x] package 端点未保存 workspace 返回 404；Schema、renderer 自检和浏览器流程通过。
- [x] 新增专项测试与 RC-01/03/08 回归通过。
- [x] 不部署生产；Git 提交只包含本轮明确文件。

## 实现约束

角色状态保存为界面会话状态，不冒充身份认证。服务端暂不依赖角色做安全判断；安全边界在部署阶段由登录与租户隔离承担。所有生成内容只来自当前画布状态与冻结研究包。
