# 从“方法说明”升级为“能指导判断的方法资产”

2026-10-27，ML-017。建议继续深化全部64份内容，但采用逐法不同的研究任务，不能统一扩写篇幅。目标是：读者能跟着做，Agent知道何时用、怎么改变问题表示、需要什么证据、何时停止，并能留下可复查的产物。

本轮实际完成：核对64份第一轮报告指纹、复看相应方法内容及现有教学展示范围；针对64项分别编写深化分析、关键判断、研究包、失败反例与方法交接。对80个公开URL进行取得尝试，64次取得了文件/网页、15次失败、1次为维护页；取得的内容中仍包括空壳和错误跳转，不能称64部有效文献。具体选段核读范围、文件指纹及身份问题见来源复核台账。另完成NIST公开32行数据的局部模型复算，以及材料指数在两种工况下排名反转的构造模型复算。未完成64部原典逐页精读、真实现场试验或独立专家审核，线上正文及执行契约未改。

## 一、现状：哪些已有基础，哪些仍要补

库中是52个方法档案与12个闻邦椿谱系专题，不是64种同层级算法。此前已具备基本结构、来源及第一轮研究。当前阅读构建器对R01、R02、R03、R04、R14、R17、R36、R42、R44、R48接有固定教学展示；相应审核仍有各自限定范围，不能重新把它们统称为“都没有完整例子”。其余方法不能仅凭结构齐全被认为已经可以独立执行。

证据深度最不均衡：有的原典可读，有的只核过摘要或目录，有的理论明确而客户输入缺失，有的已有数学教学复算但没有工况校核。闻邦椿体系的2003论文、2007可视优化论文、后期本人自述与尚未取得的专著章节，应分别标注。

## 二、建议每个方法形成十个部分

|部分|要解决的问题|应留下的资产|
|---|---|---|
|身份与版本|到底是哪种方法、哪一版，和邻近方法有什么区别？|原典身份、版本差异、别名及包含关系|
|问题与禁用条件|什么任务值得用，哪些输入缺失时不能继续？|触发、前提、反向触发与补证路径|
|推理机制|输入表示经过什么变换，为什么能推进设计？|状态或表征转换图，解释作用与局限|
|关键判断|哪一步不是照抄步骤就能完成？|保留/排除/返回/停止条件及理由|
|证据|这个判断实际依据哪段原文、哪条观测或哪个模型？|逐主张定位和适用范围；不以链接数量替代支持度|
|操作与工具|人要做什么，计算工具要算什么？|输入表、操作说明、单位、依赖工具和错误处理|
|完整实例|从开始材料到中间产物再到结论，能否跟做？|固定输入、完整表格/模型、运行记录、最终交接|
|反例与边界|哪里会误用、算错或产生无依据的结论？|正常、缺材料、不适用、边界、冲突五类检查设计|
|迁移与组合|从已知案例迁来需要改变什么？下一方法接什么？|相似机制、工况差异、数据字段、未知和版本绑定|
|阅读与调用|如何让人看懂、让Agent可靠取用？|简明正文、图解、详细研究附件、机器契约分别维护|

这是平台建议的深化标准，不是把各原典都改写成同一种十步算法。框架类应突出角色、承诺与回返；启发式应突出变换、发散和筛选；工程方法应突出方程、单位、求解与校核；需求方法应突出事件、解释及样本情境。

## 三、四种深度应分别记录

1. **来源深度**：题录/摘要/正文选段/全文取得/全文核读，分开记录；取得全文也不是每段结论都已核实。
2. **操作深度**：概念说明、具体动作、完整产物、可复算示例。框架不必伪装成数值求解器。
3. **证据成熟度**：构造教学、公开数据复算、真实任务研究、独立专业审核、现场验证，注明覆盖范围而不混成一个总分。
4. **调用成熟度**：可检索内容、可组织上下文、可检查输入、可执行特定契约、可记录审核。当前内容库可读不等于全部有执行器。

## 四、下一轮研究的组织方式

每项顺序为：核定版本与问题 → 对照原典及实证研究 → 列出争议和替代方法 → 设计完整教学产物 → 执行适用的计算/结构检查 → 做反例与跨情境测试 → 专业复核 → 才整合阅读页和调用规范。

机器检索和初稿编制可以辅助，来源身份判断、专业结论和客户事实不能交给模板自动批准。研究草稿放独立层，经过核对才发布，不覆盖冻结内容，不把已发布教学升级降回旧基线。

实际短板应决定优先级。建议先贯通R48/R08/R09/R14/R49/R17/R22/R26/R36/R38/R42/R52十二项关键链，覆盖需求、功能、原理、选择和验证；同时推进所有其余档案的具体补强项。WB各项先建立逐版本主张表，专著正文受阻的部分明确保留，不用通用知识冒充原著。

## 五、专家级质量怎样验收

“专家级”应针对具体任务与工况评价，不能由方法页总分自动推出。建议采用以下尚待校准的验收规则：

- 事实、案例采用关系、法规/标准适用性及工程数值须有可定位依据；关键错误不允许被文风或点子数量抵消。
- 输入充分性、适用性、机制推理、替代方案、技术可行性、验证设计与可实施性分别评审；重大未知必须显式保留。
- 用未参与编写的任务做盲测；与同一模型不调用方法库的基线比较，记录专家修订次数、无依据断言、关键遗漏、有效方案及所需补证成本。
- 至少覆盖正常任务、不适用任务及缺材料任务。拒绝错误调用和提出必要追问同样是正确表现，不能只奖励总能输出方案。
- 方法生成者与审核者分离；两名评审有分歧时保留原评分和理由，不能只取平均掩盖重大技术分歧。

这些是平台研究设计，不是已经跑完的评测，也不是专家认证。NIST的TEVV-Athlon可作为定制评测结构的参考；本轮官网仍明确标为初始公开草案，不当成熟强制标准。[NIST官方说明](https://www.nist.gov/artificial-intelligence/ai-research/tevv-athlon-framework-evaluating-ai-systems)

## 六、对方法引擎的直接影响

先判断问题是否清楚，再检查材料是否足够；合适的方法与证据不足可以同时成立。路由应分开给出匹配理由、缺口、下一动作和可调用能力。基于同一机制的案例只是迁移线索，必须携带介质、尺度、载荷、环境与责任差异。

每次交接应绑定需求版本、项目档案版本、方法版本、依据和产物指纹。输出有用的方案假设时，同时交代最危险的假设与最便宜的区分性验证，不因前端漂亮或MCP请求成功就标“专家级”。[NASA的要求编写清单](https://www.nasa.gov/reference/appendix-c-how-to-write-a-good-requirement/)可参考其追溯与可检验性要求；平台接口是我们自己的适配。
