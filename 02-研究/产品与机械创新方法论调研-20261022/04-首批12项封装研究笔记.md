# 首批12项封装研究笔记

日期：2026-10-22｜平台改编建议，尚未作为新方法卡接入。示例均为说明性假设，不是真实企业案例、获奖团队原始决策或工程结果。相关方法的执行前提仍须按原典、任务和专业判断细化。

## R08 用户观察与需求证据化

**原典与适配状态：** 需真实研究材料；方法步骤为平台建议，真实采集不能由语言模型替代。

**触发：** 愿望与真实使用困难混杂。

**最小输入：** 观察记录、访谈原话、使用场景。

**建议操作：**

1. 按真实任务选择使用者、操作者、维护者等角色，不只找采购人。
2. 记录具体行为、原话、工具与异常；保留时间和材料出处。
3. 把观察事实、受访者解释和平台解释分别编码。
4. 检查反例和人群差异，再形成需求候选及待验证问题。

**产物：** 需求证据及问题简报。

**停止/降级条件：** 没有访谈或观察时只生成提纲、采样计划与假设。

**说明性例子：** 记录操作者频繁垫纸保护工件是观察；“怕夹坏”需原话或进一步验证。

**应拒绝的输出：** 合成几段访谈后写成用户调研结论。

**来源：** [S04 Stanford d.school](https://dschool.stanford.edu/tools/design-thinking-bootleg)；[S11 ASQ](https://asq.org/quality-resources/kano-model)。

## R12 质量功能展开

**原典与适配状态：** 已核ISO范围；质量屋具体构造与采用量表需补读相关原典后再设执行版。

**触发：** 用户语言需要转成工程参数。

**最小输入：** 有证据需求、重要度、工程特性。

**建议操作：**

1. 接收有来源的需求清单，去掉把某个方案当成需求的措辞。
2. 为每个需求提出能测量的工程响应，允许一对多。
3. 由证据或专业判断标注关系强弱，缺信息留空。
4. 核查工程响应之间的相互影响，连接验证方式。

**产物：** 需求到指标映射。

**停止/降级条件：** 重要度、关系强度未知时不计算伪精确排名。

**说明性例子：** “容易开启”可连接开启扭矩、抓握尺寸和操作时间，但指标阈值由人群与测试决定。

**应拒绝的输出：** 把所有关系默认设强，或把质量屋当作完整QFD。

**来源：** [S12 ISO](https://www.iso.org/standard/74103.html)。

## R14 功能分解与接口分析

**原典与适配状态：** 复用现有IM-FA-001；明确NASA分解与TRIZ作用建模的适配边界。

**触发：** 需求尚未转成可替代的功能结构。

**最小输入：** 问题简报、边界、要求。

**建议操作：**

1. 确定处理对象、系统输入和预期输出。
2. 用动词与对象写必要功能，先不锁定零件。
3. 说明物质、能量、信息如何跨功能和接口传递。
4. 记录不足或有害作用的证据；未知情况记作风险假设。

**产物：** 功能结构与接口风险。

**停止/降级条件：** 系统边界不清不画确定性现状图。

**说明性例子：** 把“电机、丝杆、夹爪”转成“产生运动、传递作用、约束工件”等功能；具体表达由实际系统校核。

**应拒绝的输出：** 只列零件名称却声称完成了功能分析。

**来源：** [S15 NASA](https://www.nasa.gov/reference/4-3-logical-decomposition/)。

## R16 根因分析

**原典与适配状态：** 已取得ASQ资源入口；所选RCA具体流程、证据检验方式需深化。

**触发：** 已有故障或异常，需要定位原因。

**最小输入：** 异常定义、时序、工况、测量。

**建议操作：**

1. 定义可观察异常及正常对照，核对测量可靠性。
2. 按工况、阶段、材料和变化建立候选原因。
3. 用数据、对照或试验检查候选，保留竞争解释。
4. 把尚未排除的原因交给验证计划，不强选唯一根因。

**产物：** 因果假设、证据与验证任务。

**停止/降级条件：** 仅有时序或相关性，不输出因果确定结论。

**说明性例子：** 加工后划伤可能来自夹持、搬运或杂质；用工序前后检查和对照缩小原因范围。

**应拒绝的输出：** 连问五个为什么便把最后一句当作已证明根因。

**来源：** [S17 ASQ](https://asq.org/quality-resources/root-cause-analysis/tools)。

## R17 形态学分析

**原典与适配状态：** 已核形态学与交叉一致性概念；工程子功能组合步骤为平台适配。

**触发：** 想系统产生不同原理组合。

**最小输入：** 子功能、各自解法、接口约束。

**建议操作：**

1. 选择彼此尽量清晰的子功能及不可改变的接口。
2. 每个子功能列多种原理解法，注明出处或原创假设。
3. 用成对和整体兼容性筛除冲突组合。
4. 保留不同原理路线，补关键未知和验证计划。

**产物：** 可追溯的概念组合。

**停止/降级条件：** 硬约束冲突排除；兼容性未知保留待验证，不记已可行。

**说明性例子：** 定位、夹紧、释放分别列解法；组合后核对供能、空间与锁止要求。

**应拒绝的输出：** 直接做笛卡尔积，把几百种排列说成几百个创新。

**来源：** [S18 Swedish Morphological Society / Tom Ritchey](https://swemorph.com/ma.html)；[S02 Springer / Pahl & Beitz](https://link.springer.com/book/10.1007/978-1-4471-3581-4)。

## R22 技术矛盾与发明原理

**原典与适配状态：** 现有IM-CA-001已有候选分析；矩阵数据实际获取、版本和许可未在本轮完成。

**触发：** 改善某性能导致另一性能恶化。

**最小输入：** 改善参数、恶化参数、关联依据。

**建议操作：**

1. 描述某具体改进动作带来的好处与不利影响。
2. 为改善—恶化关系提供机理或试验依据，缺证据标假设。
3. 只有需要且适配时才映射指定版本的通用参数。
4. 真实查询并保存坐标、结果、空结果和映射理由。
5. 把启发转成具体作用机制，列代价与验证条件。

**产物：** 映射理由、查询记录及概念。

**停止/降级条件：** 不存在关联时不硬套；未实际查表则不得报告命中。

**说明性例子：** 增加夹紧力可能减少滑移但增大表面损伤，需核压力分布、材料和观察。

**应拒绝的输出：** 只见“轻量化”一词就声称矩阵给出了某个最优原理。

**来源：** [S24 MATRIZ](https://wiki.matriz.org/docs/triz/problem-solving-tools-5890/contradictions/)；[S25 MATRIZ](https://wiki.matriz.org/docs/triz/problem-solving-tools-5890/contradictions/engineering-contradiction-5995/contradiction-matrix-6026/)。

## R23 物理矛盾与分离

**原典与适配状态：** 已核MATRIZ条件与分离途径；采用版本必须明确，不混并所有流派的分类。

**触发：** 同一属性有相反要求。

**最小输入：** 同一对象属性、双向需求及条件。

**建议操作：**

1. 确认是同一对象的同一属性受到相反要求。
2. 分别写出两项要求的必要性与作用条件。
3. 探索空间、时间、条件、系统等适用分离方式；具体分类随来源。
4. 把分离方向转成结构或过程，检查新增问题。

**产物：** 分离机制及验证假设。

**停止/降级条件：** 不同对象、不同指标或没有必要性的矛盾不进入此工具。

**说明性例子：** 某元件在承载时需要刚，在通过狭小空间时需要可变形；是否构成有效问题须看系统约束。

**应拒绝的输出：** 普通的开机与关机状态切换，被包装成解决重大物理矛盾。

**来源：** [S24 MATRIZ](https://wiki.matriz.org/docs/triz/problem-solving-tools-5890/contradictions/)；[S26 MATRIZ](https://wiki.matriz.org/docs/triz/problem-solving-tools-5890/contradictions/physical-contradiction-6056/algorithm-for-resolving-physical-contradictions/)。

## R26 功能裁剪

**原典与适配状态：** 最高补证优先：本轮仅体系层线索，不能按本笔记直接注册可执行卡。

**触发：** 需减少部件同时保持必要功能。

**最小输入：** 有用功能、承担者、受体、约束。

**建议操作：**

1. 建立组件—有用功能—受体的关系。
2. 提出删除、合并或转移功能的候选。
3. 逐项说明必要功能由谁接替以及需要什么条件。
4. 评估接替后的接口、控制、可靠性、维修与制造代价。

**产物：** 裁剪方案和功能接替记录。

**停止/降级条件：** 任何必要功能没有接替或证据不足，候选不判成功。

**说明性例子：** 减少一个支撑件，必须说明承载与定位怎样保持，不能只说零件更少。

**应拒绝的输出：** 用降件数替代性能、装配和寿命验证。

**来源：** [S23 Altshuller Institute / MATRIZ / ETRIA](https://www.aitriz.org/triz/triz-body-of-knowledge)。

## R27 功能导向检索与科学效应

**原典与适配状态：** 已核MATRIZ功能导向检索；可连接项目库，但匹配策略仍是平台设计。

**触发：** 行业内方案枯竭，需跨行业迁移。

**最小输入：** 抽象功能、对象、约束、工况。

**建议操作：**

1. 把行业专名改写为功能、对象和物理作用。
2. 保留硬约束检索多行业案例和科学机制。
3. 对比源与目标的材料、尺度、载荷、环境、接口和目标。
4. 保存迁移差异与排除理由，输出待验证机制。

**产物：** 机制候选及适配差异。

**停止/降级条件：** 证据只支持相似功能，不得输出目标场景已验证。

**说明性例子：** 按“在接触条件变化时限制作用力”找机制，比只搜同类夹具能拓宽候选；不是给定机制可直接采用。

**应拒绝的输出：** 源项目有恒力功能就断定目标的位移精度或表面损伤也达标。

**来源：** [S27 MATRIZ](https://wiki.matriz.org/docs/triz/problem-solving-tools-5890/function-oriented-search-fos/)。

## R36 Pugh概念筛选

**原典与适配状态：** 已取得MIT概念比较教学原文；评分量表与未知处理由平台另定。

**触发：** 已有多个概念需初步比较。

**最小输入：** 基准、候选、准则和依据。

**建议操作：**

1. 先排除违反明确硬约束的方案。
2. 选基准和共同准则，写清可比较口径。
3. 逐项相对比较，每格标数据、判断或未知。
4. 检查基准和准则变化是否改变结论，保留有价值的方案组合。

**产物：** 比较矩阵与保留/合并理由。

**停止/降级条件：** 关键维度未知时不靠总分唯一选型。

**说明性例子：** 几种夹紧方案比较装卸时间、损伤、成本与维护；缺真实成本时保留待查。

**应拒绝的输出：** 用漂亮的分数表掩盖输入来自猜测。

**来源：** [S35 MIT OCW](https://ocw.mit.edu/courses/ec-720j-d-lab-ii-design-spring-2010/pages/projects/ideas/)。

## R42 验证与确认

**原典与适配状态：** 已读NASA V&V方法主体；试验操作与门槛需领域人员依据目标制定。

**触发：** 方案需判断是否符合要求和实际用途。

**最小输入：** 要求、使用情境、验收口径、测试条件。

**建议操作：**

1. 把每条要求和关键假设变成可判定问题。
2. 区分符合指标的验证与在真实用途中的确认。
3. 选择分析、检查、演示或测试及相应环境、样本和测量。
4. 预先写接受与停止条件，保存资源和责任人。
5. 执行后另存原始数据、偏差与结论，必要时回到问题定义。

**产物：** 指标到证据的验证矩阵。

**停止/降级条件：** 没有实际执行只输出计划；没有验收口径不声称通过。

**说明性例子：** 夹具承载测试符合指标，不等于操作人员在生产节拍和维护条件下能够满意使用。

**应拒绝的输出：** 把一次样机展示当成量产可靠性或完整生命周期验证。

**来源：** [S41 NASA](https://www.nasa.gov/reference/5-3-product-verification/)；[S42 NASA](https://www.nasa.gov/reference/5-4-product-validation/)。

## R48 问题定义与要求管理

**原典与适配状态：** 可映射现有IM-PD-001；扩展前保留旧版与运行兼容。

**触发：** 需求只有愿望、对象边界不清。

**最小输入：** 原始需求、对象、工况、约束、未知。

**建议操作：**

1. 识别操作者、对象、期待变化与当前替代方案。
2. 写出系统内外边界、使用阶段和工况；分开目标与现状。
3. 为要求记录量、单位、阈值、依据和未确认项。
4. 核对硬约束是否互相冲突，确认允许的决策层级。

**产物：** 版本化问题简报。

**停止/降级条件：** 对象或核心目标未知时追问；缺阈值可探索概念，不能判达标。

**说明性例子：** 对“做一个更好用的夹具”，先补工件、装卸动作、空间、载荷、允许损伤与节拍，而非直接输出机构。

**应拒绝的输出：** 将AI补写的目标当作企业已确认要求。

**来源：** [S03 Design Council](https://www.designcouncil.org.uk/resources/framework-for-innovation/)；[S15 NASA](https://www.nasa.gov/reference/4-3-logical-decomposition/)。
