# STPA：判断某个控制动作在什么情境下会造成危险

部件都按规格工作，系统仍可能因控制信念、反馈时点、权限和顺序而进入危险。STPA围绕不可接受损失、系统危险、控制结构、不安全控制动作和致险情景展开。本文核John Thomas2025作者讲义控制环与四类UCA选段，2018完整手册尚未核；以下局部构造例不声称完整机器安全分析。[作者讲义，PDF69—73](https://psas.scripts.mit.edu/home/wp-content/uploads/2025/2025-03-24-0900__STPA_Introduction__PUB.pdf)

先写损失与边界，再写可能导致损失的危险状态，避免把一个故障名当危险。指定控制器、被控过程、控制动作、反馈和控制器维护的过程模型。人可以是控制器的一部分，维修协调和授权也应进入结构；不能只画电路箭头。将动作与上下文组合后，分别问：该给却未给、给了反而不安全、过早/过晚/顺序错误、持续过短/过长是否导致危险。四类是分析提示，不是四格填完就穷尽。

完整构造例定义L1为人员或对象受到不可接受接触损伤，H1为人员/未确认对象处在作用区时仍有相对接触作用。操作协调者向本地控制器发恢复请求；控制器向执行过程发enable/inhibit；反馈为实际运动、有效时点与残余状态。控制器过程模型含“区域是否清空、实际是否停止、恢复是否授权”，每项都可能过时或未知。

写一张上下文表：C1区域占用且作用仍在，C2区域已清但实际状态未知，C3区域清空/状态已核/授权齐全。对C1不发抑制是UCA1；在C2发enable是UCA2；在相关停止核查之前发enable是UCA3；危险条件仍在却提前解除inhibit是UCA4。在C3，不能仅凭enable这个词就说它不安全，须说明其他条件。重复动作可关联多个危险，但每行保留控制器、动作、情境与危险引用。

致险情景SC1不是“传感器坏”四字：网络暂存旧的停止反馈，时间标记未被门禁解释；协调者看到绿色，以为已停止；本地控制器过程模型仍将旧清空状态视为当前；于是恢复请求触发enable。竞争情景SC2是两控制者同时拥有写入权，较早的维护禁止被后来的运行使能覆盖。前者需要反馈有效性及过程模型更新研究，后者需要权限/交接协议；增加第二传感器并不自动解决二者。

教学行动是先派生约束候选：未知/陈旧状态不得用于新的恢复使能；控制权切换须有明确唯一写入及恢复审查。再给验证问题：分别注入旧反馈、缺反馈、矛盾反馈和控制权竞争，观察是否仍发新授权以及实际执行状态。本例选择优先研究时效与控制权机制，而不是只降低某个部件故障率；所有情景和结果身份是构造/计划，不编事故频率或安全认证。

两类误用是把UCA写成无上下文的“控制器失效”，以及把派生约束当已实现防线。还要防止用“请求停止成功”证明残能安全。迁移到文档发布时，动作publish在未审版本/授权情境可不安全；已提交不等已审核，权限竞争也需控制结构，但不把机械损失原样迁入。

R40从失效链补充原因与共因，R41从人员任务/能量补危险，R05细化接口，R42形成约束证据。输出应保留损失—危险—控制情境—UCA—情景—约束—验证的追溯，以及哪些角色和条件尚未覆盖。

## 局部构造控制环

```mermaid
flowchart LR
  O[操作协调者] -->|恢复请求与上下文| C[本地控制器及过程模型]
  C -->|enable / inhibit| P[接触执行过程]
  P -->|实际运动、时点、残余状态| C
  C -->|未决状态与确认需求| O
```

箭头表示需要研究的关系，不证明已存在完备传感器或安全控制实现。
