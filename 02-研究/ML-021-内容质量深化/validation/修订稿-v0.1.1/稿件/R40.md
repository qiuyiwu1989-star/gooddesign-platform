# FMEA：沿功能—失效—影响链，把措施变成可复核的行动

FMEA用于逐项分析既定系统/配置的功能怎样失效、影响如何传播、现有控制能提供什么证据、下一步该由谁处理。它不能凭部件故障清单穷尽系统危险，也不因写了“加强检测”就降低剩余风险。本文依据GSFC-HDBK-8004 Baseline2024-08-20已核适用性、因果识别、表1及单点/共因选段；该任务专用量表不是割胶通用评分，完整55页不声称逐页审核。原出处与定位见底稿来源档案。

操作先固定配置、任务阶段、功能与接口。每行把模式、机制、原因和影响分开：模式是功能怎样偏离，原因是为何发生，影响分局部、上级和最终后果。不要一行只写“传感器坏”。把检测控制与预防控制区分，给证据身份；未实施措施单列拟议行动，不填成现有防线。

完整构造例为代理作业头CONFIG-A、异常介入前的状态观察功能。模式M1为陈旧状态被当成当前；原因候选C1时钟不同步、C2共享供电扰动；局部影响为无效观察持续，上级影响为未请求抑制，最终接触后果待评估。两个观察通道S1/S2及控制器共用PWR-A，不能仅按数量宣称冗余独立。

给三条完全构造的故障注入记录，而非真实实验：T1切断PWR-A，S1/S2均无新数据但界面仍显示旧绿色；T2保持供电而注入旧时间戳，旧门禁继续接受；T3改版B将陈旧/无效状态拒绝用于新动作，并显示“停止请求已发送、实际状态待核”，相同输入下不再输出新动作授权。由T1/T2可以决定优先行动是调查共享失效域并修时效门禁，先于优化显示颜色。T3只关闭教学中的“陈旧数据仍被接受”问题，尚未证明驱动实际停止或残能安全。

行动记录应写来源行M1、假设、负责角色、所需试验、配置、结果、未覆盖边界与复核者。只有有证据支持适用防线后才重评；重新评分仍不等风险接受。若评分量表未适用批准，就保留后果与不确定性，不把未知赋最低分。即使评分可用，也不能让不同严重后果因相同RPN而被视作等价。

两种实质失败是“新增一个同源传感器就降低发生/探测等级”和“拟议超时停止被记成已验证控制”。还应检查潜在故障、维护导致的失效与共因，而不是每个部件独立打分。另一情境同一硬盘两个目录并非独立备份，需实际恢复和失效域证据。

与R51相比，FMEA从功能/失效链逐行展开，STPA从控制情境识别不安全控制；两者互补。R41处理任务危险与降低风险，R42承接行动证据。交付物是可追溯失效链和优先行动依据，不是一个看似精确的风险总分。
