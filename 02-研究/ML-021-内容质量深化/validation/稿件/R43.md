# 生命周期评价与生态设计：先定义同等服务，再比较全链负担

一台设备用料少，不等于提供同样服务时环境负担更低。LCA先明确目标与范围、功能单位和系统边界，再建清单、评价影响与解释不确定性；生态设计把发现的问题带回材料、寿命、维护或服务方案。本文依据GSA官方LCA术语页的功能单位、参考流和边界选段，不声称完整实施ISO14040/44。[GSA，Life Cycle Perspective—Key Terms](https://www.gsa.gov/governmentwide-initiatives/federal-highperformance-buildings/highperformance-building-clearinghouse/integrative-design-strategies/life-cycle-perspective/key-terms)

功能单位应描述提供多少、多久、什么水平的服务，不只是“1台机器人”。参考流才是为完成这项服务需要多少台设备、耗材、能源和维护活动。两方案服务质量/容量不同，先解决等效性，不能直接相减。边界要说明生产、运输、使用、维修、末端，以及基础设施、备件和替换是否纳入；排除理由必须一致。

完整构造例规定10年、10万次同等夹具服务，假设容量与质量等效。A寿命5年，生产100BU/台；B寿命2年，生产60BU/台。BU是人为负担单位，不是kgCO2e。只看单台B较低；参考流换成A2台、B5台后，生产负担为200与300。再明确所有阶段的构造输入：A运输10、使用30、维修20、末端4，合计264BU；B运输25、使用20、维修10、末端10，合计365BU。本教学选择优先研究A的全服务方案，而非推荐单台生产更低的B。

若新证据把B寿命改为5年，则B需2台，其运输10、使用20、维修10、末端4，合计164BU，结论反转。由此确定下一研究动作是获取可信寿命/维修证据，而不是先优化差异很小的末端项。上述数字全为构造；现实比较须由材料/能源清单、适用因子与影响方法形成，不能把已汇总BU例子说成完整LCA。

操作中为每项清单记录活动量、单位、地域、年代、技术、来源、分配规则和缺失。需要影响表征时，确认不同物质与能源如何映射到所选影响类别；不要把毒性、资源和气候变化未经价值模型直接相加。副产品分配、回收系统和避免负担可能改变结果，应先说明方法并做敏感性，而不是对有利方案换一套算法。零使用负担若只是缺数据，必须记未知；本例输入均明确构造，不用缺值冒零。

两类实质误用是把功能单位写“每台”导致寿命替换被隐藏，以及宣称减碳却只把负担转到维护耗材或其他影响类别。另一种是不同供应链年代/地域数据拼接成精确差值而不说明质量。迁移到云端文档服务时，功能单位可能是一定数量可用交付，需重建服务器、存储、网络与重试边界，不能套设备寿命参考流。

交付应包括服务等效条件、边界图、参考流、清单/方法、结果贡献、数据质量与敏感性、不能支持的主张，以及生态设计改动和验证计划。R45讨论必要功能与全寿命资源价值，R43讨论环境负担，两者不能互相替代；公开比较与真实环境收益仍需相应专业审查与证据。
