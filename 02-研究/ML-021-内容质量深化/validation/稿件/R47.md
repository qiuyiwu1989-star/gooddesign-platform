# 集合式并行工程：保持可行域、按证据缩窄，并知道何时重新打开

多个团队各自优化一个点，接口相遇时常被迫返工。集合式并行工程让各专业表达一组可能的设计及其边界，通过耦合条件和学习逐步收敛。LEI官方词条强调范围/权衡知识、证据性淘汰和信息充分后的承诺；本文是离散教学，不冒充完整Toyota原论文流程或连续可行域求解器。[LEI，Set-Based Concurrent Engineering](https://www.lean.org/lexicon-terms/set-based-concurrent-engineering/)

输入不能只有A/B/C名称。至少要给变量、单位、范围、专业拥有者、证据等级、耦合关系和未知；一个领域认为可行，不代表全系统可行。连续上下限也不一定形成矩形：质量与功率可能相关，不能任意组合上下界。把约束来源与版本和淘汰原因逐点/逐区域保存，条件变了才知道该重开哪些部分。

完整构造例离散质量m∈{1,2,3}kg，功率p∈{10,20,30}W。机械假设m≤2，电气假设p≤20，接口教学条件m×p≤30kg·W。九点交集为(1,10)、(1,20)、(2,10)；其他点分别记录哪个条件排除。单位kg·W只是这个人工耦合式的单位，不是物理定律或割胶预算。

再引入教学响应f=2m+p/10及“f≥4”的新条件。三个点响应3、4、5，因此淘汰(1,10)，保留(1,20)/(2,10)并继续学习两者的真实代价。这完成一次有依据的缩窄，不需要强选唯一冠军。若接口条件经新版本改成m×p≤40，(2,20)重新进入交集，响应6；它过去只因旧接口条件被排除，所以应恢复为候选，而非永久留黑名单。m=3和p=30的其他失败仍然存在，不能全部重开。

承诺条件应事先约定：必要作用、专业/接口约束及关键证据达到何种程度，剩余未知由谁接受，何时需要不可逆资源。教学中的“满足方程”不等工程可行；真实乳胶边界与制造维护尚未知，所以只能承诺下一项研究，而非采购定型。长期保留所有名字且没有学习/缩窄计划，也不构成集合开发。

两种实质误用是每个专业只报最优点后要求其他人迁就，以及接口改版仍沿用旧排除结论。另一种是把未试验当不可行，过早丢失选项。另一情境文档格式集合{PDF,HTML}与读取集合{PDF,DOCX}交集PDF，只说明格式声明相容，不证明权限或实际可读。

输出为域及证据、交集、排除/重开历史、待学习项、承诺条件和责任。R31帮助接口依赖，R37在剩余可行集合中解释价值取舍，R06承接资源承诺。引擎应保留“为什么现在缩窄到这里”，而不只返回一个点或一张备选卡片。
