# TRIZ体系：先选择问题表示，再选择工具

TRIZ不是一个收到需求就自动吐出发明原理的黑箱。它包含不同抽象层和前提的工具。对方法引擎而言，最有价值的是保留“现实症状→可检查的问题模型→对应变换→现实方案→验证”的完整路径，而不是对每个问题强行贴矛盾标签。[E21-1]

## 工具路由的判断依据
先写对象、作用、工况、希望改变什么，以及不能破坏什么。若连有害作用是否存在都未知，路由到观察/测量；若可以用已知参数直接满足要求，先作常规计算。得到具体冲突后，再区分：两项工程结果相互牵制可进入R22；同一参数在明确条件下要求相反状态可进入R23；有作用结构的缺失/有害关系可进入R25；想移除载体而保留作用用R26；已知所需作用但不知道哪里有成熟机制用R27。上述路由表是平台适配，不是MATRIZ提供的通用自动分类器。

## 同一个卡滞问题，四种表示怎样分流
构造输入：惰性板宽10.0mm，槽宽10.6mm，目标横向总间隙0.1–0.3mm；法向载荷5N，推进能力1N，当前摩擦系数假设0.4。真实割胶需求的允许损伤等仍未知，本例不代替它。

|问题表示|当前证据|可做什么|不可越过什么|
|“机器不好用”|无工况/量纲|先补观察|不能查询矩阵|
|减槽宽提高定位，但摩擦/卡滞变差|只是一条机制假设|R22建立改善/恶化及因果链|尚无完整矩阵命中|
|同一接触面既需要强接触定位又希望小阻力推进|已有同场作用模型|R25检查有用+有害作用，探索第三物质|先核是否允许改界面|
|导槽多余，删掉它|导槽承担定位|R26核其他载体是否接管|不能把“减少件数”当完成|

本例选R25支线，因为作用双方和有害接触已经足够具体，允许增加衬片也已经设定；并行保留R22问题表述，但不伪称查出原理。两侧各0.2mm衬片使总间隙10.6−10−2×0.2=0.2mm；假设低摩擦衬片μ=.1，则推进阻力μN=.5N<1N，原来为2N。得到局部有根据的方案候选，接着验证磨损和卡滞，而不是宣称TRIZ使整机创新成功。

```mermaid
flowchart LR
 S[现象与边界] --> M[问题模型]
 M --> T[核前提 选择工具]
 T --> I[机制变换]
 I --> V[现实约束检查]
 V -->|新冲突| M
```

这个流程里的关键回返是：若衬片污染导致清理成本不可接受，则更新问题模型，不是继续给原点子找支持。保留被放弃分支的理由，以便后来的Agent知道它是前提不满足，还是已经实验证伪。

## 两个常见失败及跨领域使用
把“轻且强”直接当物理矛盾会混淆两个参数；应先判断同一参数是否真的要求相反状态。把“加传感器”当标准答案会把观测、供电、校准和恢复成本全部藏起来；须回功能/资源账。迁移到报告生成时，“有来源但核对很慢”可以成为作用和信息流程模型，物理接触的材料定律不能照搬，尤其不能凭机械类比推导文本真实性。

TRIZ体系负责组织问题与知识工具，R48负责需求有效性，R14负责作用结构，R36/验证负责候选证据比较，四者不能互相代签。输出最小应包括现实问题版本、所选模型、满足前提的证据、未选路线及原因、具体候选、待证新问题。
