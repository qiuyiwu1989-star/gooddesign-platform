# 领先用户法：围绕一条需要趋势寻找提前经历者

本方法适用于普通目标用户尚未大量遇到、但某些人已经承受的需要。领先用户的两个特征是相对所研究趋势提前经历需要，以及解决它可带来显著收益；先购买、专家身份或已自研都不能单独代替定义。它不同于泛访谈，也不同于把VIP客户邀请来投票。

依据为Churchill、von Hippel、Sonnack《Lead User Project Handbook》168页版本，前言2009、主体修订说明1998，非另一份2026案例册；本轮补读PDF第85页推荐网络与第153页共创准备，承接原定义选段。旧作者稿还说明“已经创新”不是定义门槛。以下筛选与交接组织是平台适配。

## 先证明“领先于什么”

输入研究领域、相关角色、待解决需要及趋势材料。趋势不能只写“AI发展很快”；要说明哪一种需要在何种群体/条件中增长或提前出现，以及比较的普通群体。材料可来自实际任务变化、专业资料或历史记录，记录支持与不确定性。趋势仍只是设想时，输出寻找线索计划，不给真实领先用户认证。

再把候选的两项依据分栏：已在何时/何条件经历需要，相比谁更早；解决后由谁获得什么收益。自制或改装单列为经验线索。若收益归经营方、负担由操作者承受，分别核角色，不把“公司有利”当个人有动机。

## 从五候选到研究安排

沿用**全构造**TREND-TEACH-01“变化条件下持续作业需要”。A名气大且购买早，但两资格均否，排除本趋势匹配；B提前经历且收益高，虽未自研仍在定义上匹配；C有改装且收益高，但提前经历未知，返回补证；D在类比领域两项匹配，保留但需迁移核查；E有作品与收益却不领先，不在本趋势匹配。

这一步已经决定不同动作，不是给五人一起打专家分：先研究B的实际需要，追查C的时间与比较条件，将D用于机制线索，并保存A/E可能适合其他问题的理由。由于人物与趋势都构造，结论只教资格判别，没有真实邀请。

## 推荐网络不是通讯录越大越好

手册的推荐网络从已有相关作者/专家线索继续问“谁对这个问题更有经历或了解”。平台工作稿记录推荐者、被推荐线索、推荐理由、涉及哪种需要、联系/核证状态及停止理由。沿同一圈重复推荐不等独立支持；要关注相关领域和相似极端条件，避免只得到知名人物名单。专家可帮助找到经历者，专家本人未必是用户。

共创前分别整理用户需要、既有尝试、可迁移原理及目标域差异。会上保留是谁提供了既有方案、谁提出新概念、哪些假设仍未经证实；真实补偿、保密和成果权利需实际各方确认，旧手册建议不是今日统一合同。最终让普通目标用户检验可采用、维护和经济条件，不能拿领先者能用证明普遍可用。

两个反例：把未自研的B排除会误用定义；将极端工况下的D方案直接搬给普通用户会忽略成本、技能和环境。资料交接的提前高负荷使用者可提供版本管理线索，但这不等所有小团队都需要同样复杂系统。

交接为趋势依据、两资格证据、推荐链、需要/机制贡献、权利状态、迁移差异和普通用户验证问题。真实趋势、人物与共创仍是外部输入，不用构造人名包装为调研完成。
