# 六西格玛设计：先使关键质量特性可定义、可测量

DFSS是一组面向设计质量的方法，不是“经过五步即达到六西格玛”的算法。本页选DMADV作为组织线索：定义、测量、分析、设计、验证。NIST公开说明区分新设计DMADV与既有过程DMAIC；NIST量具研究的Design considerations与Uncertainty支持测量研究的对象/操作者/配置及代表性。以下CTQ工作稿为平台适配，未实施完整标准。

## 五类工作怎样形成承诺

定义阶段明确客户结果、对象、边界、责任和CTQ候选；测量阶段把CTQ变成操作定义并检查量测系统；分析阶段区分响应差异、误差和影响因素，比较可能的设计原理；设计阶段落实参数、接口、稳健性及检验方式；验证阶段在确定规格、配置和适用条件下取得独立证据。发现测量不可信就回测量，发现目标不成立就回定义，不为保持阶段顺序而继续计算。

输入至少需要客户语言及情境、设计目标、规格来源、测量对象和可取得的原始记录。没有规格不能算能力，没有稳定且适用的测量/过程资料不能从一个漂亮分布给出等级。

## 从含混语言到测量计划的例子

割胶构造语句为“边界信息可理解并可核对”。第一份CTQ稿写“边界信息与允许作用的对应”，随后拆两个不同研究：物理上信号是否对应目标对象；人是否正确理解表示。两者需要不同量测，不将满意度当组织边界精度。

沿用3件×2操作者×2重复的12空格，作为**教学准备练习**：每格要有对象/操作者/重复身份、配置、环境、时点和数值。现在12格皆空，只能说明计划覆盖，不能估计重复性、再现性或偏差。新核[NIST 2.4.2](https://www.itl.nist.gov/div898/handbook/mpc/section4/mpc42.htm)还提醒操作者、器具及配置选择要匹配目标群体；其中大操作者群的代表性设计要求多于两名，因此本小表不能被称为完整代表性R&R研究。

为使量测决策可练习，新增**完全构造的非实体示例**：任务协议要求确认资料版本ID，而系统只记录“导出成功”。操作定义是“导出件版本ID与请求ID相同”，在请求v2、产物v1时，可明确判该项不满足；这不是需要计算Cp/Cpk的连续过程。由此决定先补版本身份记录，而非对“成功率”做六西格玛包装。

## 把DMADV后半程走完：身份链改版与独立确认练习

以下所有行均为本轮新编的**构造软件记录**，没有真实客户、导出系统或测量活动。为使分析可复查，先固定属性CTQ：“只有请求任务ID、请求源版本、产物归属任务与产物源版本相符时，才允许标记该请求已交付。”可用来教属性质量设计，不将它当真实项目的规格批准。

**定义与测量。** 研究对象是交付身份一致性，而非文件内容正确或可读性。每条记录含request_job、requested_version、selected_version、artifact_job、artifact_version和交付决定；缺字段要单独标缺失，不能补成相符。学习记录如下：

|学习行|请求/源版本|选择记录|实际回传产物归属/版本|按CTQ判断|
|---|---|---|---|---|
|D1|J101 / v1|v1|J101 / v1|一致|
|D2|J102 / v2|v2|J101 / v1|不一致：旧产物被回传|
|D3|J103 / v3|v3|J102 / v2|不一致：归属与版本均错配|

**分析。** 比较两个解释：H1“选择器拿错源版本”应出现selected_version≠requested_version，但D1—D3均相同，不能用这组记录支持H1；H2“回传产物没有与请求绑定”与D2/D3的artifact_job错配相符。记录足以将设计工作聚焦于回传绑定，不足以断言真实代码根因就是缓存或并发——这些实现机制未在表中给出。

**设计响应。** 候选A只把界面提示改成请求版本，产物仍可能来自旧任务，不能满足给定CTQ；候选B让回传携带任务ID和源版本，在交付边界核对，缺失或不符则保留未交付并安排调查。按CTQ选择B作为本练习的设计改版，保存门禁规则及异常分支。这不是用展示文案修饰失败，也不是“有一个测试通过”就默认所有设计质量改善。

**独立构造确认。** 在上述规则确定后，使用未参加学习分析的另一组构造记录核规则；它是独立测试输入，不是另招募用户或新做生产试验。

|确认行|请求/选择版本|回传归属/版本|预期及按规则得到的决定|
|---|---|---|---|
|C1|J201 / v4，选择v4|J201 / v4|相符，允许标记身份交付|
|C2|J202 / v5，选择v5|J201 / v4|拒绝交付标记，保留错配|
|C3|J203 / v6，选择v6|归属缺失 / v6|拒绝交付标记，返回补证|

三条分别覆盖正常、旧结果错配、身份缺失，按已固定规则的结果均与预期一致；完整输入/规则与本地复算保存在本轮`R07-构造闭环.json`和`R07-闭环复核.py`。可声明范围是“这三个构造输入下，身份门禁没有误把已知错配/缺失标成交付”；不能声明真实缺陷率下降、内容正确、无并发漏洞、文件可读或达到六西格玛。若要验证这些更广声明，必须各自增加CTQ、模型与实际证据。

这条工作线从定义、记录、竞争解释走到设计选择与新输入确认；12个空量测格仍只是另一项物理量测准备，不被拿来计算能力。

## 实际量测研究怎样准备

确认被测量、参考方法、对象是否可重复、是否破坏性、覆盖的量程与工况。安排合适人员和器具、重复/重装/日期效应，保存实际顺序；盲化或随机化用于减少特定偏差，不是填一个字段就成立。校准、分辨力、偏差、稳定性和不同操作者差异分别考虑。若对象在重复间改变，需改研究设计，不能将变化全部算量具误差。

分析时先看原始记录和条件，再选合适模型；原始重复缺失时不凭均值反推全部误差。设计阶段把主要变差来源交R38/R39研究，目标规格仍应来自客户/风险/工程依据。验证应检查新配置与真实用途，不沿用学习数据自证。

两个失败反例：量具偏差大但重复性极好，重复读数一致不能证明准确；只测熟练者和常温，不能声称现场所有人员/环境可用。资料导出例则说明属性一致性问题未必适合连续能力指数。

交接包括CTQ定义与来源、测量准备/原始记录、误差模型与假定、设计响应和独立确认计划。真实目标、测量系统及稳定过程资料缺失时，保留研究协议而不填sigma_level、Cp或Cpk。
