# FAST功能逻辑：沿HOW展开手段，沿WHY检验目的

FAST适合团队对系统“为何需要这些作用、还有何种方式”没有共同理解的场景。它不是把流程图横放，也不是功能树的另一个名字。VA Canada官方“How to Create／Steps／Is there a correct FAST”选段支持HOW、WHY及伴随关系的组织；本页采用简化经典局部视图，不声称复刻所有技术型或顾客型FAST。

## 工作坊先定范围与基本功能

输入任务目的、功能草稿、研究对象与已选或未选原理。先确认讨论整个系统还是某个候选实现。用主动动词和对象写功能，避免“安装传感器”把部件方案偷成目的。把高阶目的和低阶范围外手段明确标注，防止越问越大或在细节里失去目标。

逐问“怎样实现此功能？”把回答放HOW一侧；再反向问“为什么做这件事？”要求回答回到上位目的。如果只能答“因为它下一步发生”，说明是时序而非目的—手段，需要改图。对伴随/支撑作用问“做这件事还必须同时做什么”，WHEN不表示钟表顺序。

## 一个完整摩擦原理练习

**构造范围：仅研究摩擦约束切向滑动。** 范围外高阶H0稳定工件状态；基本B1约束切向滑动；次级S1产生接触摩擦；范围外低阶L0施加法向作用；支撑SUP保持接触条件。

H0的HOW答B1，B1的HOW答S1，S1的HOW答L0；反向WHY为“施加法向作用，为形成所选接触摩擦；形成摩擦，为约束滑动；约束滑动，为稳定状态”。每条边都附所选原理的前提，而不宣称法向力足够或无损伤。SUP不在主链仍影响条件，不能因它不是顺序一步就删掉。

中间工作稿应保留被否决答案。例如“先拧螺钉再检查”回答的是程序，改成“施加法向作用”才能参与这一逻辑层；“使用夹具”过宽，继续问作用；“加大摩擦”若没有对象/条件，仍需具体化。最终得到一条有范围的逻辑路径，并把摩擦、材料、允许载荷列为工程问题。

## 替代原理怎样改变图

提出形状嵌合作为另一方式时，B1可以保留，HOW不再必经“产生接触摩擦”。应另画“通过几何接触限制相对运动”的路径，再核方向、间隙、接触应力和解除方式。这样FAST真正帮助打开方案，而不是将当前摩擦路线说成唯一答案。若两条路径所需目标不同，先核基本功能与范围，不能为了图对称硬凑。

两个实质误用是把“供电→检测→执行”时序当HOW/WHY必然关系，以及用所选零件当唯一基本功能。另一个风险是用全组共识替代物理成立；图逻辑通顺仍可能需要载荷试验。迁移到资料回查，“保持可定位来源”可由版本ID/索引等手段实现，“先扫描后上传”本身不回答WHY。

交接产物为范围、基本/支撑功能、逐边HOW/WHY问答、前提、替代路线与未决工程问题。R14可接职责和接口，R45可研究功能价值；真实团队工作坊和工程效果未在此发生。读者可以据例主持一次有记录的逻辑讨论，不必把图画满才算结束。
