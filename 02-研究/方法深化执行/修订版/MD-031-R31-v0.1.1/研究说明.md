# DSM：先读懂依赖，再讨论模块和顺序

本包实际核读 DSM Web 入门正文的矩阵、方向约定、顺序及回路选段。没有取得或复刻全部DSM算法。承接ML-017/R31；0.1.0待独立复核，无项目进度收益、优化最优性或工程认证。

## 一张矩阵只能先回答一种关系

本构造案例是任务信息依赖：A参考研究、B几何研究、C集成研究、D测试计划。A的结果供B，B又反馈A，B供C，C供D。边由本教学作者声明，不是访谈记录。物理接触、能量流和工作先后不能混成同一个“1”；多种关系应各有一层与方向图例。模块化产品的空间、材料、维修接口仍要另外研究。

我们采用行提供给列：M[A,B]=1表示A输出是B的输入。来源同时解释两种转置惯例，因此与别的系统交换时必须携带约定。本脚本把输入转换成“提供者→接收者”的统一图，再逐边与证据索引核对；只转置矩阵不改图例会被拒绝，同时转置和改图例则得到同一语义。

```mermaid
flowchart LR
  A[参考研究A] --> B[几何研究B]
  B --> A
  B --> C[集成研究C]
  C --> D[测试计划D]
```

## 不是给矩阵换个漂亮顺序

脚本用可达关系的传递闭包识别互相可达节点，求得强连通分量{A,B}、{C}、{D}；缩点后得到{A,B}→C→D。A/B组内必须计划假设、交互与迭代，不应随意选一个先做然后宣称没有反馈。缩点顺序描述所给图，不估计迭代次数或项目工期。工作节点数仅四个，算法是清楚可复算的教学实现，并非大规模DSM优化器。

重排不会删除边，也不会降低真实接口成本。接口成本在本例未知，保持null；不能给组间边自动赋0。若补入一个未知的D→A关系，已知子图仍可分析，但完整顺序返回null，因为该关系若存在会让整个图成环。这个分支让“有一份图”与“依赖已调查完整”分开。

## 何时用，何时停

当问题是信息依赖、研发返工来源或模块接口候选时适用。若不知道节点范围、方向和边类型，先补模型定义；若未知会改变回路结构，先做敏感性与信息调查。物理耦合、产品可制造性、资源日历及安全验证不能由拓扑排序给出。R30输出可提示功能关系，但不能未经解释直接当DSM任务边；与R05接口、R47并行研究交接时保留边的类型、依据、版本和未知。

另一情境把作者/审阅者互相反馈视为迭代组，再向发布者传递。它是桌面映射，不证明某组织效率提高。本包8项实际结构检查与迁移记录均可读；调用说明为建议契约，未新增MCP服务。
