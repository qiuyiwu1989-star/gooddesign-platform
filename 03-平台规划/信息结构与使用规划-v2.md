# 好设计：信息结构与使用规划 v2

2026-09-07｜讨论及后续整合基线。本稿承接五大板块结构定义v1，调整推进顺序与首页原则。用户明确偏好原版；当前保留馆首页、原视觉、原导航与交互。本文是结构和使用规划，不代表功能已建设，不发布网站变更。

## 一、平台定位与结构边界

以真实创新设计项目为核心，将获奖资料整理成知识，供参观、教学和企业研究使用。

前台以用户任务组织；后台以内容对象组织。五板块是能力分工，不要求立即重排五个同等大小的导航项。保留原馆首页作为品牌与体验入口，企业与教师可直接进入各自页面，助手继续跨页服务。

```text
好设计（原版馆首页）
├─ 奖项与项目：奖项背景 → 名录 → 项目档案 → 相关知识
├─ 好设计馆：主题展区 → 展项 → 互动任务 → 延伸探索
├─ 科技教育：课程目录 → 课程包 → 教师备课 / 学生任务 → 反馈
├─ 企业创新：企业画像 → 问题卡 → 案例证据 → 机会卡 → 验证与跟进
└─ 智能助手：找项目 / 解释 / 比较 / 辅助应用，贯穿以上路径
```

## 二、已有入口如何承接

| 板块 | 保留入口 | 后续整理重点 | 使用结果 |
|---|---|---|---|
| 奖项与项目 | award.html、laureates.html、project/、atom/ | 档案与知识页关联，奖项记录按届次保存 | 找到一个项目并理解其设计依据 |
| 好设计馆 | index.html、categories.html、hall.html、x-ray.html、playground.html | 展区、展项和项目对应；明确任务顺序 | 看懂一个原理，完成一次体验或创作 |
| 科技教育 | learn.html、lesson/、teacher-workbench/、courseware/ | 单课/单元/课件归入课程包，保留不同课件版本 | 获得可试教的课例和可评价的学习产出 |
| 企业创新 | connect.html、industry-demo/ | 从预置双环演示推进到一个真实企业问题 | 有依据的研究方向与可执行验证清单 |
| 智能助手 | assistant.html、当前页侧栏 | 带入当前项目、用户任务和证据范围 | 辅助理解和组织工作，不替代资料审核 |

这是整合去向，不是立即替换页面。旧版已有局部功能可继续使用，精确检索、联网企业研究和跨用户数据管理另行建设。

## 三、五个核心内容模板

### 1. 项目档案
项目ID、正式名称与别名、单位/团队、获奖记录、问题背景、设计方案、取舍与过程、实际应用及证据时间、来源与审核、关联知识与应用。

第一屏回答“是什么、为什么值得看”；深层内容回答“为什么这样设计、依据是什么、能如何借鉴”。空内容可以待补，不能用AI写满。

### 2. 知识条目
知识ID、关联项目、知识类型、独立陈述、来源定位、适用条件、局限、事实/解读标记、审核与版本。

类型首批限于：问题、约束、原理、结构、方法、效果。新标签进入词表审核，避免同义词不断扩散。先从完整项目抽取，不机械切割所有长文。

### 3. 展项包
展项ID、主题、关联项目与知识、目标观众、核心看点、体验任务、操作说明、讲解、延伸问题、资源及版本。

同一项目可以有多个展项；展区归属属于策展表达，不是项目唯一分类。

### 4. 课程包
课程ID、学段/学科/课时、关联项目与知识、学习目标、活动、学生任务、评价、课件/工作纸、教师说明、试教反馈与版本。

单元引用多份课程包，单课引用多个知识条目。学习者个人记录另行管理，不能混在公开课程内容里。

### 5. 企业研究档案
研究ID、企业主体与公开画像、企业确认的问题、目标/约束、相关项目及证据、迁移假设、缺失资料、验证计划、负责人、进度、结果。

其中“问题卡”记录真实需求；“机会卡”表达研究假设；“验证记录”描述实际发生的结果。三者不能互相替代。

来源资料、获奖记录、组织和审核记录作为上述模板共用对象，避免重复录入。

## 四、准备怎样用

### 公众与参观者
馆首页→选择主题→看展项→问助手→进入原项目→完成观察或创作任务。首个体验目标是能用自己的话解释一个设计选择。

### 教师与学生
教育入口→按课堂目标找课例→查看关联项目与证据→调整课程包→课堂使用→记录学生产出和教师反馈。先跑通一节课再扩大课程目录。

### 企业与服务团队（近期重点）
产业入口→确认企业主体与业务→建立问题卡→检索有依据的案例→提出两三个机会→选择一个验证→记录结果。双环作为首个演示和需求验证样板；预置研究不等于企业已确认需求。

### 内部内容团队
收到资料→登记来源→归属项目→补事实/提炼知识→审核→关联展项/课程/研究→发布→接收反馈。前期可以使用台账与文件夹，工作流程明确后再做内容后台。

## 五、内容整合工作表

每份旧内容记录：旧路径、类型、所属板块、关联项目ID、拟用模板、信息来源、有效内容/占位内容、冲突/缺项、处理方式、负责人、状态。

处理方式限于：保留并关联、合并同源重复、保留不同版本、待补证据、仅内部留档。合并先确定主对象，不重写原始资料。所有旧内容应有明确去向或暂缓原因。

“无”“暂无”“待补充”等属于缺资料；字段有值、来源存在、事实已核验是三种不同指标。旧URL先保留，用户路径需要优化时局部调整。

## 六、按成果推进的四阶段计划

| 阶段 | 做什么 | 交付物 | 进入下一阶段的条件 |
|---|---|---|---|
| A 结构打样 | 用1个项目、1个展项、1份课例、1个双环问题检验模板 | 四份按模板组织的样本、旧内容映射表 | 归属清楚、能互相链接、缺项可记录 |
| B 核心内容整合 | 扩到10个资料相对充足项目，主目录保留全量 | 10个项目知识包、关联展项与课程目录 | 核心事实有来源，审核状态明确 |
| C 三条使用路径 | 试用一次参观任务、一次课堂任务、一次企业研究 | 用户反馈、改动清单、企业待确认事项 | 使用者能完成任务，关键卡点有处理方案 |
| D 底座深化 | 按真实卡点建设内容后台、检索、研究任务和权限 | 可维护数据与研究服务、评测集 | 更新可追溯，回答有依据，企业资料隔离 |

以上是建议规模，无固定日期或未经确认的人员承诺。企业真实资料若未到位，继续推进公开项目整理和馆/教育试用，不虚构企业验证结果。

## 七、责任与验收

需要明确内容编辑、专业审核、场景运营三个职责，可兼任。企业问题另需企业确认人和研究负责人。

内容验收看来源、归属、关联及审核；使用验收看任务完成和反馈；技术验收看可维护、可恢复与资料访问边界。以这些标准决定开发范围，不以新增页面数量作为进度。

## 八、下一项具体工作建议

先做“一项真实项目的完整样本”，用来校准档案、知识、展项和教育之间的关系；并将双环Demo的一个方向整理成独立的问题卡与机会卡，清楚列出需要企业确认的条件。样本可讨论后再批量整合，不再先进行全站视觉重做。
