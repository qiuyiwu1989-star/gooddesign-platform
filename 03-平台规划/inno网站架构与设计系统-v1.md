# /inno/ 网站架构与设计系统 v1

2026-10-27。品牌统一“好设计”，OpenDesign作为站点标识。既有视觉资产可继续使用，用户界面不再并列造物云品牌。

## 站点目标和当前栏目

用同一个网站连接“看真实项目→学研究方法→带入自己的问题”，并让来源、研究判断和应用假设可核对。页面共用导航、页脚和设计基础，内容布局随阅读任务变化。

| 栏目 | 当前入口 | 状态与边界 |
|---|---|---|
| 首页/探索入口 | /inno/ | 当前以项目探索为起点，后续可逐步升级为综合入口 |
| 项目库 | /inno/projects/ | 当前可用；年份/奖项/搜索，进入稳定项目ID档案 |
| 项目详情 | /inno/dossier/?project=ID | 当前可用；来源、研究解读和评价状态分开 |
| 方法库 | /inno/methods/ | 当前可用；A—G分类、方法/谱系专题、结构与操作阅读 |
| 方法详情 | /inno/methods/methods/ID.html | 当前稳定链接保留；不为美化URL破坏既有引用 |
| 数据总览 | /inno/report/ | 当前可用；整理状态与方法/工程质量不能混淆 |

## 共用设计基础

- 色彩、字体、卡片圆角、内容宽度和控件高度以extensions/inno/system.css为统一变量源。当前浅色背景、白色内容面、紫色主操作与既有项目库一致。
- 网站导航/页脚以scripts/inno_site_chrome.py为单一结构源；项目库和方法页通过同一函数生成。页内目录、筛选和方法操作不进入全站主导航。
- 同类控件共享尺寸、焦点、选中和禁用表达；44px最小操作高度。移动导航按既有项目库的响应式规则处理，保留键盘跳到正文。
- 方法长文可使用较窄阅读宽度，项目卡可用多栏。统一不意味着所有内容都套同一个卡片网格，也不应改变内容事实与评审状态。
- 项目库特定布局样式仍在project-portal/portal.css；方法正文样式仍在method-reader/reader.css。两者不能再各自新增一套品牌色或全站头尾。

## 内容和链接规则

项目、方法、需求、研究运行分别保留稳定ID和版本。跨库链接应说明关系类型：明确采用、机制参考、教学类比或待验证迁移；没有来源不能把关联推断成项目实际使用了某方法。

公共阅读中主要展示问题、原理、操作、例子、依据和未知。内部任务ID、工具JSON和审计信息放在需要核对/开发的区域。研究稿、教学演算、实测和专家审核按真实状态呈现，不因统一视觉自动提高可信等级。

## 逐步建设顺序

1. 当前：统一既有公开页面的站点外壳和设计变量，保持可用链接。
2. 随后：把项目与方法之间有证据的关系做成可阅读的双向导航。
3. 再接需求研究：自然描述→问题理解→少量关键追问→用户核对；前台不要求填完方法字段。
4. 接创新工作台：在任务版本下选择方法/案例、产生研究产物、记录审查和验证；本机执行能力不等于云端已上线。
5. 最后按实际多人使用需求完善站内账户、权限与协作；公开阅读保持无原生登录弹窗，后台能力不因页面统一自动公开。

## 发布和维护

当前案例服务和方法静态快照保留独立release，复用相同站点结构与变量。发布前核对路径、资源、活跃导航、移动端和阅读/管理边界，发布后做跨栏目检查。新建栏目必须更新这份路由表和共用导航，不能在某页独自添加品牌外壳。
