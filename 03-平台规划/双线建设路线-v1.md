# 好设计：平台底座与企业创新双线建设

日期：2026-09-07。依据用户授权“完善平台建设、深入企业创新板块”。

## 共同目标
让一个企业问题能使用有依据的项目知识，形成可比较的创新方向，并进入验证。保留原版网站风格，以局部工具验证结构。

## 本轮交付（005）
- 560条项目统一索引：项目ID、奖项、年度、单位、原文与项目/知识页关联；96条描述缺失，全部历史档案仍未独立复核。
- 三条机制样本：可重构机器人、混联加工机器人、复杂内腔抛光；保留原文位置与哈希，分析另存。机制审核数为0，不等同完整知识库。
- 企业课题工作台：企业与问题、方法与取舍、案例与知识、方向比较、验证与成果。
- 多课题本机保存、切换、导出；问题修改会令人工复核状态过期。

## 接下来的平台底座建设
1. 校准机制包：从3条扩展至5—10条完整机制包，增加问题、约束、机制、效果测量条件、不可迁移边界；专家审核作为独立记录。
2. 建立可评测检索：先字段与全文检索，再比较语义检索是否改善命中。检索结果必须保留来源；缺资料的项目可作为线索但不支撑方案结论。
3. 方法工具：固定TRIZ规则版本；改善/恶化参数方向校验；矩阵查询由程序完成，模型解释与映射另存；无匹配应明确返回。
4. 企业持续使用：账号和企业隔离、服务端课题版本、导入恢复、审核记录、数据删除/导出及备份。完成权限测试后再接收企业私有资料。
5. 运营验证：建立问题理解、引用可靠性、方案可验证性、工程师修改耗时的评测任务；依据失败样本优化。

## 企业创新深化：双环首个课题
演示范围：机器人关节平台化；目前未获企业确认，不代表企业存在技术缺陷。

需要企业工程师补充的最小资料：
- 一个明确的机器人任务及关节位置；现行配置和尝试。
- 载荷、空间、精度、热、寿命等关键工况及约束。
- 优先改善目标、当前基线、通过门槛及本轮负责人。

访谈顺序：确认主体与产品范围 → 复述问题让工程师纠正 → 区分硬约束与可调整条件 → 确认主要取舍 → 选择案例机制 → 比较候选方向 → 决定一个验证任务。

候选方向：统一核心接口与配置规则、按任务工况划分模块族。两者为平台假设；需要比较接口复用、配置复杂度、性能约束与维护代价，不能预填收益百分比。

TRIZ研究参考：02-研究/TRIZ-GPT与AutoTRIZ-好设计平台应用分析.md。模块化问题可先用功能分析；明确技术矛盾后再映射TRIZ。平台映射不能改写为原获奖团队使用过TRIZ。

## 下一轮完成标准
一个经企业确认的问题卡；至少两条经审核的相关机制；两种可比较方向；一个包含基线、指标、负责人和停止条件的验证计划。企业尚未提供资料时，只能称作演示或研究假设。

当前不承诺新模型训练或自动完成工程设计。先评估普通问答、案例检索、案例加方法和人工确认三种方式的实际差异。
