## 二、库内发现与知识价值

按问题—方法而非仅按“齿轮/机器人”关键词组织研究：

| 方向 | 库内参照 | 可探索的知识价值 | 必须确认 |
|---|---|---|---|
| 机器人关节平台化 | 2021-s03 可重构机器人模块及系统；2021-02 高性能混联加工机器人 | 把部件、接口与整机任务结合，建立配置方法 | 目标任务、负载、接口、企业现有产品方案 |
| 精密零件工艺探索 | 2025-04 高性能零件复杂内腔抛光磨料介质与装备；2021-02 | 从难达表面光整方法研究特定复杂结构件工艺 | 材料、热处理、去除量、公差、残留要求；不得直接用于齿面量产 |
| 从任务反推传动需求 | 2021-02；2021-s03 | 形成任务→工况→部件与接口→验证的需求链 | 工况数据、寿命/热/精度边界及工程审核 |

这些是平台研究假设，不是双环当前缺陷或已验证解决方案。Demo展示档案节选、原项目链接、类比路径、边界、需补资料和试验建议。库内项目本轮未独立重新官方核验。

重要质量纠正：2017-08高速列车齿轮传动系统、2017-n14精密摆线针轮减速器描述为“无”；2020-c35滚子包络超精密减速器为“待补充”。此前560项描述“有值”仅指字符串非空，不能等同有效资料覆盖。以上条目仅列补证据线索，不支撑具体技术推论。后续质量规则必须把无、待补充、暂无等占位词识别为缺资料。

## 三、交互设计

目标产品流程：输入企业→主体消歧→自动研究公开来源→用户纠正画像→选择问题与约束→检索库内事实/方法→组织机会→生成验证方案→人工审核与跟进。

本轮实现五步：
1. 识别企业：输入双环名称，展示公开业务及来源，用户确认主体；其他企业明确不支持，避免错套画像。
2. 澄清问题：三条研究路线可选，补充目标与约束。
3. 匹配证据：不同路线关联不同案例，显示原文节选、单位、奖项及资料不足线索。无虚构匹配分数。
4. 知识融合：企业能力×案例方法×场景问题，形成研究假设、资料缺口、验证设计与观察指标。
5. 验证简报：汇总并下载文本，支持打印。用户补充仅记录为未核验信息，不伪装已经由AI分析。

Demo为预置公开研究快照，非实时全网调研、非实时模型推理；所有步骤和输出明确说明。数据不上传，没有商务通知、内部企业资料或自动工程决策。

## 四、平台技术建设路线

| 顺序 | 持续建设 | 最小交付与验收 |
|---|---|---|
| P0 可维护工程 | 逐步把历史快照构建转为维护源码；现阶段extensions是新功能源文件，构建时叠加 | 新内容不会被重建覆盖；保留首页和历史地址；版本发布、回滚、健康检查可重复 |
| P0 数据质量 | 项目/获奖/来源统一ID；识别占位文本、重复和冲突；建立字段来源 | 项目关联完整，不能把非空当完整；资料不足能被检索层排除 |
| P0 内容维护 | 原始资料登记、片段定位、事实/分析分层、审核、版本、影响追踪 | 一条修改能查到依据及受影响课程、展项和报告 |
| P1 企业研究服务 | 企业名称消歧、可信源抓取、研究日期、引用、用户纠错；联网任务异步执行 | 同名不同企业不会混合；研究失败明确提示，不回填虚构结论 |
| P1 知识检索 | 字段过滤+全文检索起步，按需要加向量与重排；事实案例/方法案例分开召回 | 用固定问题集检验找得准、有证据；资料不足的项目不能贡献技术结论 |
| P1 研究任务编排 | 画像、需求、证据、假设、验证、产物分阶段存储；人工可修订 | 可重试、可恢复、可比较不同方向；避免长提示词一次生成整个报告 |
| P1 企业工作区 | 企业资料隔离、权限、需求负责人、处理状态、删除和导出 | 一个企业不能检索另一个企业私有资料；公开案例需单独发布 |
| P1 服务可靠性 | 模型时延/失败/成本记录，超时与限流、服务监控、数据备份恢复 | 实际模型失败能发现；备份能恢复；健康标志不能只看是否配置密钥 |
| P2 评测与反馈 | 企业识别、证据支持度、迁移合理性、缺证据处理和专家反馈 | 每次更新运行约30个代表任务；明确哪些结果需人工复核 |
| P2 专用模型能力 | 据评测缺口决定领域微调、工具与模型分工 | 有持续难题和合格训练资料再投入，不把网页整理称作模型训练 |

建议技术演进：现有Node与静态页面继续运行；进入多用户阶段引入关系数据库管理主数据与任务，文件存储管理原件，后台队列处理长研究任务；检索索引可重建、知识来源不可丢。选型在明确并发、数据规模与预算后定，不在此次Demo提前堆叠基础设施。

## 五、下一轮最有效的验证

请企业研发/工艺负责人选择一个业务和一个实际问题。优先用“机器人关节平台化”演示方法碰撞，但要先确认这不是企业已经完成的工作。获取允许使用的任务与接口条件后，将当前机会卡改成真实需求卡，再判断是否补充访谈、台架或专家服务。每项成果记录：已知事实、案例依据、迁移假设、验证结果。
