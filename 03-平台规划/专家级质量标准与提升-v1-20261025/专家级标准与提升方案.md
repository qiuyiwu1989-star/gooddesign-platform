# 专家级标准与提升方案 v1

性质：平台质量标准提案，尚未行业专家标定。当前库统计及逐项缺口已从冻结JSON重新读取；没有因本报告生成而提升内容评级。

## 定义及交付等级

专家级指在约定任务阶段、工况和证据范围内，输出达到有经验的领域专家可审查、可用于下一步工作的水平，关键判断可解释，知道哪些结论尚不能作出。它不等同语言专业、篇幅长或工程认证。

分别标注：研究分析、概念方案、工程方案、验证结论。概念级任务可以达到专家级概念分析，但不能标为工程已验证。领域、阶段、复杂度及交付用途共同定义评审范围。

每份产物附质量护照：任务和输入版本、方法版本、关键主张与来源定位、事实/假设/推断、已完成与未完成验证、评审者及专业范围、问题闭环、可使用范围。客户案例研究还须区分作者报告、原始工程证据、平台推断和本平台实际复现。

## 先过硬门槛，再谈评分

出现以下任一项不得发布为专家级：关键引用伪造或错归属；关键计算/单位/机理错误；明确硬约束被违反却仍推荐；把教学或推断写成真实事实；用无关案例证明可行；重要未知被隐去；关键结论超出实际验证范围；核心反对意见未闭环。未知但坦诚保留可以合格，未知却给确定结论不合格。

系统不承诺每次都产出专家级答案，而应保证每份标为专家级的产物经过相应门槛。达不到时交付条件性研究或补证任务，不能通过措辞升级。

## 八项评审指标

| 维度 | 评审要问什么 | 可检查证据 |
|---|---|---|
| 问题定义 | 是否抓住真实目标、对象边界、工况与硬约束 | 需求来源、成功判据、冲突与未知 |
| 原理正确性 | 机理、方法、公式、单位和适用条件是否正确 | 原典、推导、独立计算或专业复核 |
| 证据质量 | 每个关键主张是否被合适证据直接支持 | 主张到原文定位、来源身份、限制 |
| 推理深度 | 为什么这样选，替代解释及反例是否处理 | 决策链、比较、敏感性、反证 |
| 覆盖充分性 | 关键功能、接口、生命周期及失效是否遗漏 | 覆盖矩阵与不适用理由 |
| 创新价值 | 改进是否针对目标，是否优于合理基线 | 机制差异、基线比较、代价；无依据不称首创 |
| 工程可用性 | 能否指导该阶段的下一步，资源与实现约束是否清楚 | 参数、材料/工艺、工具、验证与责任安排 |
| 可复核性 | 其他专业人员能否重走判断并定位分歧 | 版本、输入、过程记录、可重算/可追溯产物 |

建议0—4级锚点：0缺失或根本错误；1有表述但缺依据；2局部成立且重要缺口仍影响使用；3在当前任务范围内充分且可复核；4在3基础上经独立复核或适当验证并处理主要反例。它们是有序等级，不默认可加成总分。

暂定专家级门槛为所有适用维度至少3、硬门槛全部通过、无未关闭严重问题，并有与任务相符的领域专家独立评审。涉及工程性能的4级必须有相应计算/实验等证据，不能只靠另一个LLM赞同。创新维度如属事实研究可判不适用并解释，不强造创新。此门槛须试点标定后才能作为正式认证口径。

## 如何校准而不是自我打分

首批建议12个任务，覆盖新产品概念、既有机器改进、降本制造、复杂机电，每类3题，并混入信息不足和错误前提。题目、证据包与允许资源先冻结。由至少两名相关领域专家独立匿名评审，任务作者不能担任唯一评审者；分歧需回到证据并由合适第三人裁决。

在相同输入与预算下比较普通Agent、方法引擎Agent和专家参照产物；参照不是唯一标准答案。开发集与留出任务分开，避免按试题写提示词。记录关键错误漏检、合理停止、证据支持、下一步可用、专家接受度及成本，不只看平均分。样本12题用于发现问题和标定，不能据此宣称普遍达到某百分比。

生产指标按领域和任务阶段分层报告：专家级发布合格率、关键错误漏出率、关键主张证据覆盖、严重问题关闭、错误输入正确阻断、独立复核通过、真实下游采用反馈。小样本必须带分母及不确定性。关键错误按严重度审查，不能用大量轻微正确项稀释。

## 当前深度、广度、准确度的基线

2026-10-25重新读取60份档案：48方法+12谱系专题，149来源记录。全部60份状态为未专家审核、未工程验证；57份documented_not_runtime_integrated，3份research_only_not_runtime_integrated。178条evaluations是预期情境描述，不是178次已执行测试。

深度：已有原理、步骤、判断、产物和例子，能支持解释与计划准备；部分计算法已有教学模型。但输入object等类型、文字关系绑定、缺失工具和真实任务闭环，使其尚不能支撑普遍可靠执行。篇幅提醒不等同质量不足，也不能作为达专家级的证明。

广度：七类均有覆盖，但任务分类计数不是覆盖率。当前档案主分类为A9/B8/C9/D4/E10/F8/G12，含WB专题，不能据此判断D类一定不足。需要建立“行业/对象×研发阶段×问题类型×交付等级×工况风险”的覆盖矩阵，再找实际客户高频任务缺口。详细机构、控制、接触摩擦、疲劳、制造工艺等深度是否足够，应由具体任务验证，不能仅凭有一个方法族名判覆盖。

准确度：已有出处核读与交叉纠错，但149来源不是149个独立验证；摘要、目录、正文的支持范围不同。现有结构和文件完整性测试证明可读取、可追溯，不能证明事实准确率。当前无法给出可信的准确率百分数或专家级达标率。

逐方法提升底账.json保留每档原理、来源核读范围和原有缺口，可作为编辑工作入口；它是基线提取，不是专家打分结果。

## 第二轮提升工作包

P0准确度：建立关键主张台账，逐条区分原典规则、平台适配、教学推导与工程主张；核对作者/版本/定位和实际支持范围。先处理会改变方法选择、计算或验收结论的主张。WB12分类对应、WB10公式与例值差异保留为专门问题，不擅自补全；未解决时限制调用能力。

P1执行深度：先选问题定义、功能分析、形态学、概念筛选、原型测试、验证确认六节点；补字段Schema、语义前提、主张—证据要求、单位/工况检查、错误输入与回返规则。每节点建立正常、缺输入、误选方法、错误工况任务及专家预期，不能把统一提示词当成契约完成。

P2证据加工：从案例MCP读取可定位记录，构建“事实—机理解释—可迁移条件—差异—不可迁移部分”证据包；做同外形不同机理、同机理不同尺度的反例。先勘查真实接口与许可，再开发适配器。

P3广度扩展：按首批客户任务覆盖矩阵选缺口，优先影响结论的专业子法和数据/工具，不先追求方法数量。新增方法仍须原典、契约、案例、反例和专业评审。

P4专家基准：组织上述独立评审与对照评测，按问题类型归因到内容、匹配、案例证据、推理、工具或验证环节。修正后在留出题复测，避免只修当前示例。

## 引擎架构增补

加入质量策略注册、证据/主张图、阶段适用的检查器、独立评审工作流、发布门禁与质量护照。方法选择不仅返回相关性，还返回允许输出的结论层级与未就绪条件。

拟议MCP新增method_quality_requirements、method_check_claims、method_quality_report；发布状态由应用责任流程管理，不让自评工具自行认证自身产物。运行持久记录评审版本、证据版本及未决问题。需求或证据变化后使相关评审失效，并重新检查受影响结论。

实施顺序是先标准和基准，再六节点闭环，再扩库和工具。以上为本轮开始时的标准与基线；冻结内容库的原有状态不因引擎升级而被覆盖。
