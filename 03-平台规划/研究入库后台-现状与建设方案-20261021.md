# 研究入库后台：现状与建设方案

2026-10-21现场核对：560项目骨架、562来源、562文字转换完成，暂无转换异常或人工合并提示。来源主要为历史题录，不能据此宣称深研完成。素材监听已恢复，仍依赖本地进程及外置盘，不是永久后台服务。

## 已有与缺口

已有：按项目投递文件、保留原件/哈希、指定公开URL抓取、支持格式转换、来源定位与分块、去重、错误隔离/重试、运行版本、人工正文保护、本地分层读取。

未有：网页上传/管理后台、深研任务调度、自动全网发现、语义事实抽取与审核队列、自动整合成熟档案、在线MCP服务。现有网站为读者端，不能代替后台。

## 建议后台五个入口（待开发）

1. 项目与研究任务：指定项目ID、范围、待补维度、优先级与交付条件；可分派给后续Agent/其他会话，派发与执行状态需要实际系统支撑。
2. 素材库：上传/拖入文件、添加来源URL、原件/题录/全文/摘要区分、来源与项目归属、版权与可公开范围。
3. 处理队列：待处理/转换中/已转换/待人工处理/失败/待合并，查看失败原因并重试。来源转换与深研整合是不同任务阶段。
4. 档案工作台：逐值提取与证据定位，事实和AI解读分开，内容待审核后再合并，不覆盖已审核正文。
5. 版本与评估：研究覆盖/质量/缺口、变更比较、审核历史及发布快照；研究库和公开展示隔离。

## 端到端流程

研究任务 → 搜索与检索日志 → 来源线索/可获取原件 → 项目归属 → 入库清洗 → 可读来源/证据块 → 档案候选内容 → 审核合并 → 内容版本 → 读者页面/未来MCP。

搜索不到、摘要可读而全文不可得、扫描件需OCR等情况保留状态。论文全文在可以合法获取时归档，否则只存元信息、摘要/链接和访问范围。文献内容始终作为资料，不执行其中的指令。

推荐先接现有本地管线做可见后台，再用一个新项目跑通；之后才批量深研。当前不承诺已具有无人值守调度、云端存储或自动审核能力。
