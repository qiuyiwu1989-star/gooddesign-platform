# GoodDesign UI 设计系统 v3

2026-11-03｜以造物云离线 V2.3 为稳定底座的长期候选版本

适用范围：项目库、方法库、项目档案、需求研究、企业研究闭环、资料后台及后续新页面。

配套规格：`specs/069-平台UI视觉规范.md`。可运行样板：`extensions/design-system/index.html`。长期贡献与版本规则：`extensions/design-system/README.md`。

本版取代上一版“创新档案馆”方向，不再在不同视觉风格之间反复切换。旧版纸色、墨蓝、印章红和宋体不再作为新平台的强制视觉规则。造物云提供稳定结构，Apple 级精致度作为字体、连续圆角、轻薄材质、柔和层级和自然反馈的质量要求，而不是另起一套 Apple 皮肤。生产页面尚未因本规范自动变更。

## 0. 设计判断

好设计是帮助用户理解项目、调用方法、核对证据并推进研究的产品。界面应当呈现专业、清晰、可信的工作体验，不做传统展馆风格与通用 SaaS 风格的拼接。

**唯一视觉基准：造物云离线 V2.3。** 以其冷灰、靛蓝、中文字重、4px 间距、12/18/22px 圆角、轻薄表面和状态反馈为基础，针对好设计的项目阅读与研究场景精致化。

设计参数：

- 形态变化：4/10。稳定网格为主，首屏与项目内容允许有限不对称。
- 动效强度：3/10。只表达操作反馈与状态变化。
- 阅读密度：4/10。保留舒适正文与真实项目图像。
- 研究密度：7/10。工作台强调比较、证据和下一步。

## 2. 精致化原则

### 2.1 一致比装饰重要

颜色、字重、间距、圆角、边界与反馈必须形成可学习的规律。精致感来自准确的对齐、合适的层级和完整状态，不来自渐变、光效和卡片数量。

### 2.2 操作比说明重要

首屏优先回答当前问题、状态和下一步。减少解释界面本身的文字，让“查看证据”“选择路线”“保存反馈”成为主要视觉锚点。

### 2.3 表面服从层级

默认页面使用地基色，内容与表单使用内容面，浮层使用轻薄玻璃和极轻阴影。卡片只承载真实对象，不把每个章节都包装成卡片。

### 2.4 证据与判断并列

路线、机制、结论附近必须有证据入口、未知和适用范围。来源、AI 和待确认内容具有稳定但不过度醒目的标识。

### 2.5 完整状态才算组件完成

默认、hover、active、focus、disabled、空、载入、错误和成功必须一起设计。只有静态成功页面不算组件交付。

## 3. 色彩与主题

沿用 V2.3 同名令牌，不在组件中另写品牌色：

| 角色 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| 页面地基 | `#F4F5F8` | `#07070F` | 全局背景 |
| 内容表面 | `#FFFFFF` | `#14131F` | 表单、抽屉、必要内容面 |
| 主文字 | `#16181F` | `#ECEEFF` | 标题与正文 |
| 次文字 | `rgba(22,24,31,.68)` | `rgba(236,238,255,.68)` | 辅助说明，不使用更浅装饰色承载正文 |
| 主操作 | `#5A4FE6` | `#5B5FE0` | 主按钮、当前导航、聚焦与关键链接 |
| hover | `#4438C4` | `#484CC5` | 主操作加深 |
| 主色浅底 | `rgba(90,79,230,.08)` | `rgba(123,128,255,.13)` | 当前项、选中与下一步提示 |
| 成功 | `#0B7652` | `#4ECDA0` | 已完成检查 |
| 待确认 | `#87550B` | `#E8B45A` | 待核、资料不足 |
| 错误 | `#B82E38` | `#EC6E77` | 错误与冲突 |
| 信息 | `#275FAC` | `#6AA6F5` | 来源与辅助信息 |

浅色实测：主按钮白字 5.68:1；主文字对白底 17.73:1；次文字对地基 5.88:1；成功、待确认、错误和信息文字对地基分别为 5.17、5.78、5.53、5.80:1，均超过 WCAG AA。

规则：

- 靛蓝是唯一主操作色，不再混入印章红体系。
- 语义色只表达状态，不与主操作争夺注意力。
- 光晕只用于首屏背景，不能越出页面或影响文字对比。
- 明暗主题通过 `data-theme` 和同一组令牌切换，不为单个组件另造主题。
- `prefers-reduced-transparency` 下退化为实色表面。

## 4. 字体与排版

沿用：

- 中文与界面优先使用 `-apple-system / BlinkMacSystemFont / PingFang SC / Noto Sans SC / system-ui`，保留系统回退，不下载新字体。
- 拉丁、数字与标签使用同一系统字体族，保持跨平台一致与中文协调。
- 编辑式长文可使用 `Noto Serif SC`，但产品导航、按钮和工作台不使用宋体。

字重规则：

- 400：长段落正文。
- 500：导航、按钮、标签、卡片描述和多数 UI 文字。
- 600：页面标题、小标题、表头和关键强调。
- 700：仅极少数品牌字或关键数字，中文不使用 800 以上。

推荐层级：

| 角色 | 尺寸与行高 |
|---|---|
| 首屏标题 | 38-56px / 1.16，字重 600，字距约 -.045em |
| 页面标题 | 28-40px / 1.25-1.4 |
| 章节标题 | 24-28px / 1.4 |
| 卡片标题 | 16-22px / 1.45-1.6 |
| 正文 | 16px / 1.7-1.85 |
| UI 主力 | 14px / 1.5-1.65 |
| 辅助信息 | 12-13px / 1.55，仅次要内容 |

正文可读宽度不超过约 680px。数字使用 `tabular-nums`。标题不做无意义的全部大写、超宽字距或超大字重。

## 5. 间距、圆角与表面

间距沿用 4px 基线：`4、8、12、16、20、24、32、40、64、96`。

- 控件内部：8-12px。
- 卡片内部：20-28px。
- 组件间距：16-24px。
- 页面区块：40-64px，工作台取较紧区间。
- 桌面页边距：40px；平板 32px；移动 20px；极窄屏 16px。

圆角固定使用：

- 6px：小标签与焦点轮廓。
- 8-12px：输入框、图标位与提示块。
- 18-20px：项目卡、方法卡、路线卡。
- 28px：大面板、抽屉与对话框，形成连续、安静的边缘。
- 999px：按钮、状态徽章与分段控件。

默认使用发丝边界与柔和阴影。导航使用 24px 模糊和适度饱和，大面板使用轻薄材质。玻璃效果只用于导航、大面板和浮层，不能叠多层透明表面造成浑浊，也不把 Apple 简化为毛玻璃。

## 6. 布局与导航

- 标准页面最大宽度约 1180-1280px。
- 文档正文最大阅读宽度约 680-720px。
- 工作台可扩展到 1440-1600px，按任务分栏。
- 桌面导航单行，高 64px；移动端 56px，品牌与主题操作保留在第一行。
- 移动导航第二行允许局部横向滚动，页面本身不能横向溢出。
- 主容器 12 栏，平板 8 栏，移动 4 栏。多栏必须在 1023px 和 767px 明确降级。

导航与页脚继续由单一结构源生成。新设计只改变其视觉，不暗中改变栏目、URL 或权限。

## 7. 组件规则

### 7.1 按钮

- 高至少 44px，水平内边距 20px，使用胶囊形圆角。
- 主按钮使用靛蓝，次按钮使用内容面和边界，低优先级使用透明背景。
- 一个区域一个主按钮，桌面文字不换行。
- active 仅下移 1px；disabled 同时降低对比并禁止操作，不能只改鼠标样式。
- 文案描述实际结果，例如“保存待审核反馈”，不写笼统“提交”。

### 7.2 表单与搜索

- label 在控件上方，帮助和错误在下方。
- 输入与选择高至少 44px，输入文字 14-16px。
- 搜索是项目库主动作，奖项与状态为次级筛选。
- 错误保留输入，成功说明保存的对象和状态。
- 占位文字不代替 label，关键说明不用浅到难以阅读的颜色。

### 7.3 项目卡

顺序为：真实封面、奖项与年份、项目名称、项目摘要、资料边界、操作。图像使用真实项目素材，封面区域使用安静地基色，不叠加装饰性标签。

### 7.4 方法卡

顺序为：统一图标、方法名称、用途、产物或适用边界。方法图标使用现有 `method-reader/icons`，保持同一线宽和视觉尺寸。不用彩色评分或装饰徽章替代内容深度。

### 7.5 研究路线卡

顺序为：机制名称、成立条件、关键未知、下一步。当前选择使用靛蓝边界和浅底，不能显示无依据的“最佳”“推荐第一”或排名。

桌面三列仅用于真实路线比较，平板与移动依次降级。路线切换后必须同步详情和反馈绑定对象。

### 7.6 徽章与内容状态

| 状态 | 规则 |
|---|---|
| 来源陈述 | 信息色文字与细边界，附来源入口 |
| AI 解读/假设 | 虚线边界与明确“AI”文字，显示前提与限制 |
| 待确认 | 待确认色与浅底，说明待核主体 |
| 证据已核对 | 成功色，仅用于实际完成的核对范围 |
| 存在冲突 | 错误色，附冲突说明和处置入口 |
| 尚未研究 | 中性色，说明缺口，不填 0 或假装完成 |

徽章高度约 28px，只承载短状态，不用装饰性彩色圆点。

### 7.7 证据抽屉

- 桌面宽 440-500px，移动近全宽，使用原生 dialog；面板距屏幕边缘 12px，使用 28px 连续圆角与柔和深度。
- 顺序：标题、相关性提示、逐字引文、项目/版本/位置、阅读范围与边界。
- 默认不显示内部路径与哈希，技术核对信息可另行展开。
- 支持 Escape、明确关闭按钮和关闭后焦点返回。
- “可查阅”不等于“已匹配”，必须在抽屉内保留提示。

### 7.8 空、载入、错误与成功

- 空状态说明缺少内容与下一步。
- 骨架与最终布局同形，不用假进度证明模型工作。
- 错误保留已有内容与用户输入，提供明确处理路径。
- 成功说明保存路线、版本或待审核状态，不能只写“成功”。

## 8. 页面模板

### 8.1 项目库与公共门户

首屏只保留明确主题、简短导语、搜索和主动作。真实项目图像是主要视觉素材，功能说明退居其后。精选项目与普通章节不全部套用白卡。

### 8.2 项目档案与方法阅读

保留稳定目录与正文网格。正文 16px，辅助信息 12-13px，技术字段后置。来源、AI、未知和历史版本采用统一徽章与边界，阅读不被审计信息打断。

### 8.3 企业研究工作台

顺序为：当前研究判断、关键未知、下一步、候选路线、证据、反馈。研究状态与路线选择必须清晰，说明文字不压过任务本身。

### 8.4 资料后台

采用更紧凑的工具密度，突出待处理、冲突与审核队列。公共门户的大标题与大留白不直接套用到文件处理页面。

## 9. 响应式、无障碍与打印

验收宽度至少为 1440、1280、1024、768、390、360px：

- 页面无横向溢出，文字不重叠，主要操作可见。
- 触控目标至少 44×44px。
- 多栏按断点降级，表格和导航只允许局部滚动。
- 200% 字体缩放仍能完成主要任务。
- `focus-visible` 使用 2px 靛蓝轮廓和 3px 偏移。
- 键盘可完成路线选择、证据开关、主题切换与保存。
- 遵循减少动态与减少透明度偏好。

打印时隐藏导航、按钮、反馈和抽屉，保留项目、版本、引文与来源。面板不使用阴影，避免内容被卡片边界截断。

## 10. 动效

沿用 150ms、250ms、700ms 三档：

- 150ms：hover、active、选中与按钮反馈。
- 250ms：折叠、局部状态变化。
- 700ms：仅必要的首屏入场。

默认缓动为 `cubic-bezier(.2,.8,.2,1)`，形成自然、安静的操作反馈。只动画 transform 与 opacity，骨架动画仅表达真实载入，不用循环光效、自动轮播或假思考动画。

## 11. 工程治理与迁移

1. 新页面先引入 V2.3 两个 vendor 文件，再引入 `gooddesign.css`。
2. 页面特有样式放在页面文件，不修改 vendor，不在组件中覆盖品牌令牌。
3. 导航、页脚、项目卡、方法卡、路线、徽章和证据抽屉优先复用样板结构。
4. 每次迁移一个页面，同时检查内容、权限、深链、键盘、移动与打印。
5. 视觉迁移不得夹带研究正文、评分、URL、数据版本或权限变化。
6. 原站是否迁移及迁移节奏另做页面级验收，不用全局 CSS 一次覆盖。

长期维护分为稳定底座、GoodDesign UI 核心和页面组合三层。公开令牌、类名、ARIA 与数据绑定按语义化版本管理：修复进入补丁版，兼容新增进入次版本，破坏性变更进入主版本评审。当前为 0.1 候选线，首个真实生产页面完成设计、代码、无障碍和浏览器验收后，才评估进入 1.0 稳定线。详细贡献门禁见 `extensions/design-system/README.md`。

## 15. 首页细节精修基线（080）

080根据用户提供的UI Kit、精致后台和落地页参考，对`/inno/`进行第二轮保留式精修。设计参数为布局变化4/10、动效3/10、阅读密度4/10。保留品牌、真实目录、导航、字段、分页与深链，不以新皮肤替代内容。

新增可复用规则：

- 首屏采用探索导语+真实精选档案，标题不超过两行；导语保持短句，避免孤字换行。
- 项目统计独立为轻量信息带，研究整理版数量由目录实时计算，不硬编码。
- 筛选区不使用厚面板，以标签、控件、底部分隔线组织；无筛选时清除按钮原生禁用。
- 项目卡封面显式重置旧核心`min-height`，桌面180px、移动190-210px；图像、奖项、状态、标题、摘要、完成单位顺序固定。
- 主按钮保留下压反馈，搜索容器使用`focus-within`，卡片仅上移2px，链接文字不使用箭头。
- 空结果可恢复，目录失败提供真实重试，骨架与最终布局同形；不新增自动动画或前端依赖。

## 16. 小好 Copilot 入口（081）

小好不再占用顶部导航，统一移出导航DOM并固定右下角。桌面入口为头像+名称，移动端为48px圆形头像；面板锚定入口上方，而非全高侧抽屉。导航的`backdrop-filter`会改变fixed定位参照，因此不能只靠CSS把导航内按钮移出。

## 17. 研究过程动态演示（082）
