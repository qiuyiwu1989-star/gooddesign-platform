# 金奖档案标杆就绪与批量验收规范 v1

适用：051十小时全金奖深化。参考嫦娥的文档结构、读者体验与挖掘维度，不预设它已通过全部新证据契约或专业审核。

## 两张表一起看

1. **结构深度库存**：按八模块列出已入档事实记录、事实字段和AI项，并对照嫦娥标杆的库存。数量只是定位线索，不是质量比例；“已有记录”仍需判断内容是否充分。某模块只有AI解读时明确写“事实待补”，不能用AI撑满档案。
2. **数据契约与证据就绪**：独立检查原件、当前归属、发布版、冻结证据、对象和工况、成果关系、导读评估、版本与MCP数据契约。旧人工引用单列，不伪装新协议通过；这不抹去旧档案的阅读和研究价值。

把二者混成一个百分比，会把“资料多”误读成“结论可靠”，也会把有价值的旧档案误判成一片空白。因此本规范不自动给总分。

## 分层状态

| 层 | 检查内容 | 通过后可以说什么 | 仍不能说什么 |
|---|---|---|---|
| 题录范围 | 项目ID、原始名称、原始年份/奖项 | 已登记于本次金奖范围 | 已核准历届金奖全量或正式年份 |
| 原件与机器可读 | 本项目归属原件存在、MD/chunks可读 | 原件/机器文本可用 | 全文已核读、内容真实、版权允许再发布 |
| 研究发布版 | 当前指针、项目身份、文件SHA及历史manifest链 | 有固定研究版 | 所有问题已研究完整 |
| 项目身份 | 项目名称及奖项记录有值 | 身份字段已有记录，待内容复核 | 对象/单位/跨届日期已专业确认 |
| 冻结证据 | 已知事实和AI的原件/块/逐字引用/当前归属，AI性质与边界 | 指定版本引文可追溯 | 原文所有主张真实、独立实验成立 |
| 方法上下文 | 问题、约束、技术事实及机制或有前提/限制的AI解释 | 可供创新方法作有边界的研究上下文 | 工程迁移已验证、团队实际使用某命名方法 |
| 指标与验证 | 试验方法/结果/环境；指标对象、单位、条件 | 有可继续审查的验证记录 | 试验独立复现、效果可外推到目标企业 |
| 成果关系 | 完整清单声明及逐项项目关系与证据 | 有待内容复核的清单和关联声明 | 同团队专利=型号采用、现权属/法律状态已核 |
| 阅读层 | 八模块AI导读、六维研究评估绑定当前研究版 | 当前研究版可阅读与追索缺口 | AI评估代替专家审核 |
| MCP数据契约 | 稳定ID、固定研究版与可读结构 | 数据可供调用验收 | 本工具已跑真实协议/权限/端到端调用 |
| 专业审核 | 独立专家身份、范围与签署，不由本工具推断 | 本工具只保留“未核定” | 根据expert_reviewed标志或AI评分自行封通过 |

“研究可读”“冻结证据可追溯”“方法上下文可研究”“标杆候选”“专业核定”分开统计。标杆候选要求全部内容门槛具备且无已知完整性异常，仍必须做独立内容与适用边界评审，不能直接改成已完成或专家通过。

## 成果与指标的保守门槛

- 专利/论文`project_relation`只有明确登记的 `confirmed_project_result`、`confirmed_project_adoption`、`本项目成果已确认`、`项目实际采用已确认`，并具备`relation_evidence`时，才被机器列为“已登记明确关联声明”。**这仍不是本工具批准关联真实性。**
- `same_team`、候选、待确认、同团队技术、后续型号不自动通过；论文公开或专利授权不说明本项目采用，也不说明当前权利状态。
- 全部清单有无，与“公开报道说有多少件”分别管理。`item_list_obtained=true`且`count_basis`有值只是完整性声明的存在，仍需核逐项清单与统计口径。
- 数值为0可以是真实已知值；`value_state=unknown`即使有0也不计已知。已知指标必须有对象、单位、工况，记录在独立字段或值单元的object/unit/conditions均可。
- AI单独有机制解释不补齐原项目的需求、技术与验证事实。相关论文作为背景可以继续阅读，但不因此封标杆候选。

## 草稿单列

读取约定：`output/research-051/deep-drafts/<project_id>/<job-id>/manifest.json`。

只识别schema=`gold-deep-draft-1.0`，状态`draft_ready_for_review`或`draft_ready_with_rejections`，且`published=false`、`expert_reviewed=false`。清单必须列且仅列`输入快照.json`、`模型草稿.json`、`校验结果.json`、`研究草稿.md`，逐文件SHA一致且路径不越界。

通过后只记“有可复核草稿”，不算研究发布版、正式MCP可读、事实审核或专业就绪。损坏、自封专家、缺清单、路径越界均不计草稿就绪。即使草稿文件指纹一致，候选内容仍要经历既有证据审核和正式发布工作流。

## 工具接口与副作用

`scripts/gold_benchmark_audit.py`：

```python
report = audit(library, benchmark_id='2025-00', drafts_root=...)
project_report = audit_project(library, catalog_row, benchmark_modules=None, draft_status=None)
draft = read_draft_status(drafts_root, project_id)
export(report, report_output)
```

- `audit`/`audit_project`/`read_draft_status`只读；不调用`rw.current`，不恢复指针，不改归属、不写模型/事实/评分，不发网络请求，不执行来源。
- 当前指针之后若存在新的不可变目录，只报告需正式恢复，不悄悄采纳。当前与最多128个历史版本逐版检查；超出128则显式标记未全检。
- 来源统计按读到的当前登记快照；原件存在不等于本工具逐份核SHA，冻结证据实际引用的原件才按证据契约复核。批量采集期间登记文件变化会显式标记，不能当一个全局原子快照。
- `export`仅写调用者指定的报告目录，生成JSON/Markdown/HTML；不写项目库。默认私有输出在`output/research-051/quality/`，不可自动放公网。
- 嫦娥旧人工HTML阅读页单列为人工入口；未把它当成新的版本绑定导读。故“阅读入口可用”数量可大于“新契约导读可读”数量。

执行：

```sh
.runtime/pipeline/bin/python scripts/gold_benchmark_audit.py
.runtime/pipeline/bin/python scripts/gold_benchmark_audit.py --library 私有库 --drafts 草稿区 --output 报告区
```

## 首轮实测与后续

首轮真实98金奖中7个有研究发布版；6个有当前研究版绑定导读，另有嫦娥人工阅读页，因此阅读入口7个。6个严格冻结证据可追溯、4个有问题/约束/技术与有界机制上下文；标杆候选0、专业核定0。数字会随资料/发布变化，应以报告`generated_at`和逐项目`checked_at`为准。

这不是“只有4项有价值”，也不是“其余档案无效”；它帮助安排下一步：无结构化内容先做事实提炼，有内容无引用先补证，有机制无工况先补约束，有参数无试验配置先补验证，有论文/专利无关系先补归属。别因新协议不完全，抹去人工底稿的真实深度。
