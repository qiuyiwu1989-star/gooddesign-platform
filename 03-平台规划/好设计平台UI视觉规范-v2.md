# 好设计平台 UI 视觉规范 v2

> 本文仅保留方向探索过程，已被 [GoodDesign UI 设计系统 v3](好设计平台设计系统-v3.md) 取代。当前长期方向以造物云为稳定底座，不再采用本文的“创新档案馆”和印章红主视觉。

2026-11-03｜设计规范，未直接实施生产迁移

适用范围：好设计原站、`/inno/`、项目档案、方法库、需求研究、企业研究闭环、资料后台及后续新页面。

对应验收规格：`specs/069-平台UI视觉规范.md`。

## 0. 设计判断

好设计是面向设计研究者、企业工程师、教师和公众的知识工作平台，不是通用 SaaS 营销站，也不是单纯的作品集。

**设计方向：创新档案馆。** 让真实项目、设计取舍和证据成为主角，界面负责建立秩序、解释状态和引导下一步。

设计参数：

- 形态变化：4/10。以稳定网格为主，展馆与项目故事允许有限的不对称构图。
- 动效强度：2/10。只表达反馈与状态变化，不做装饰性运动。
- 阅读密度：3/10。公共页面强调留白、图像和连续阅读。
- 研究密度：7/10。工作台强调比较、核对、定位和高效率，但不拥挤。

本规范采用保留品牌的渐进统一，不采用全面推翻式重设计。

## 1. 现状审计与取舍

审计依据：现有 CSS、`/inno/` 与原站真实页面、ML-025 桌面及 390px 截图。

| 表面 | 必须保留 | 逐步改进 |
|---|---|---|
| 原站与数字馆 | 纸色、墨蓝夜景、印章、宋体大标题、项目摄影、展馆沉浸感 | 不为统一而改暗色展区；新组件减少局部硬编码 |
| `/inno/` 项目库 | 单行桌面导航、搜索优先、项目封面、清晰入口、响应式基础 | 紫色不再是主品牌色；减少 eyebrow、重复卡片与过小文字 |
| 方法库 | 64 项检索、分类过滤、方法图标、长文阅读 | 统一字体和控件；图标服务识别，不做无意义多彩徽章 |
| 项目档案 | 左侧目录、八模块、证据反查、版本与未知状态、打印 | 减少层层嵌套卡片；提升正文尺寸；进度条不表达研究质量 |
| 企业研究闭环 | 当前判断、三路线比较、证据侧栏、就地反馈、待核补充 | 首屏减少说明性废话；路线突出差异与下一步，不做营销式三卡模板 |
| 资料后台 | 文件、审核、研究版本和原始资料的明确边界 | 采用高密度工具规则，不套用公共落地页的大标题与大留白 |

### 品牌与界面问题

1. 原站和 `/inno/` 目前像两个品牌：前者为纸色、墨蓝、印章和宋体，后者为冷灰与紫色。
2. 当前大量 10-13px 文字承担正文、状态和操作，长时间阅读与移动使用不够友好。
3. 圆角 8、9、12、14、18、22px 与胶囊形并存，但缺少明确使用条件。
4. 卡片被用作通用分节容器，导致视觉层级变平，真正的项目与路线反而不突出。
5. 事实、解读、AI 假设、待确认和未知已有数据边界，视觉上还需要形成稳定、可学习的语言。

## 2. 设计原则

### 2.1 内容先于界面

先让用户看见项目、问题、机制、证据和下一步，再看见容器。装饰不得抢走项目摄影、图纸和原文的注意力。

### 2.2 品牌统一，场景分化

统一品牌、字体、色彩语义、控件和状态，不要求所有页面拥有相同密度。展馆可以沉浸，档案应当耐读，工作台必须高效。

### 2.3 证据始终可达

涉及研究判断的内容必须能定位来源、版本、适用条件和未知。默认隐藏内部哈希与工具细节，但不能删除核对入口。

### 2.4 一个区域一个主动作

每个页面区域只保留一个最主要动作。按钮文字描述实际结果，例如“保存待确认补充”，不使用含糊的“提交”“继续探索”。

### 2.5 状态必须被解释

颜色只辅助识别。所有状态同时使用文字，必要时配图标、边框或位置，不能只靠红绿区分。

### 2.6 渐进披露

默认显示阅读与决策所需信息。原始 JSON、版本链、内部 ID、哈希、审核日志和研究工具放入按需展开区域。

## 3. 品牌表达

### 3.1 核心识别

- **纸与墨**：来自原站的档案感和可信感。
- **墨蓝**：平台主操作、链接和当前位置。
- **印章红**：品牌印记与少量关键强调，不是通用按钮色。
- **奖项金**：仅用于奖项、获奖记录和展馆强调，不与警告混用。
- **宋体标题**：用于品牌页、项目故事和章节标题；工具界面使用无衬线。

### 3.2 不再作为主语言的方向

- 通用 AI 紫色、霓虹渐变、玻璃拟态和发光按钮。
- 每个区块都放 eyebrow、编号、徽章和装饰状态点。
- 无实际层级需要的大阴影、浮动卡片和连续自动动画。
- 用“科技感”替代证据、可读性和操作效率。

## 4. 设计令牌

### 4.1 色彩

| 令牌 | 值 | 用途 |
|---|---|---|
| `--gd-canvas` | `#F6F5F2` | 默认页面背景，轻纸色而非浓重米色 |
| `--gd-surface` | `#FFFFFF` | 表单、项目卡、抽屉和必要内容面 |
| `--gd-surface-soft` | `#F0F2F4` | 图片底、局部辅助区，不承载主文字 |
| `--gd-ink` | `#172C3C` | 标题与正文 |
| `--gd-secondary` | `#59656D` | 次要文字、说明和元信息 |
| `--gd-line` | `#D9DDE1` | 分隔与边界，不代替文字层级 |
| `--gd-primary` | `#244875` | 主按钮、链接、当前导航 |
| `--gd-primary-hover` | `#1B385B` | 主操作 hover/active |
| `--gd-primary-soft` | `#EAF0F7` | 当前项和轻量选中背景 |
| `--gd-seal` | `#A83B2E` | 印章、焦点、少量品牌强调 |
| `--gd-seal-soft` | `#F8ECE8` | 品牌红浅底，不作默认错误背景 |
| `--gd-award` | `#8A681F` | 奖项文字与获奖标识 |
| `--gd-success` | `#2F654D` | 已完成检查、有效状态 |
| `--gd-warning` | `#805B24` | 待确认、证据不足、注意 |
| `--gd-danger` | `#A43B36` | 错误、冲突、破坏性操作 |

已计算的关键对比度：墨色对白底 14.36:1；次文字对白底 5.99:1、对纸色 5.49:1；白字对墨蓝 9.30:1；白字对印章红 6.31:1；奖项金、成功、警告、错误文字对白底均超过 4.5:1。

规则：

- 页面只设一个主操作色，即墨蓝。旧紫色在迁移时映射为墨蓝，不再新增紫色组件。
- 印章红不大面积铺底，不与奖项金竞争，不单独承担错误含义。
- 状态浅底必须与深色文字配套，禁止浅灰字放浅灰底。
- 暗色展馆沿用原站夜景体系，按实际背景重新验收对比度，不能直接套浅色令牌。

### 4.2 字体与排版

| 角色 | 字体与尺寸 | 行高与用途 |
|---|---|---|
| 展馆展示标题 | Noto Serif SC / Songti SC，48-72px | 1.15-1.3，仅展馆与品牌主视觉 |
| 页面主标题 | 宋体 36-44px；工具页无衬线 28-32px | 1.3-1.45，明确一个页面主题 |
| 章节标题 | 宋体 24-30px；工具页无衬线 20-24px | 1.4-1.5 |
| 导语 | 无衬线 17-18px | 1.8，最多约 65 个汉字宽 |
| 正文 | 无衬线 16px | 1.75-1.85，长文每行约 32-40 个汉字 |
| UI 文字 | 无衬线 14px | 1.5-1.65，按钮、导航、表格、筛选项 |
| 元信息 | 无衬线 12px | 1.5-1.65，只用于次要信息，不承担关键操作 |
| 数字 | Space Grotesk 或系统等宽数字 | 使用 `tabular-nums`，不另造超大指标装饰 |

字体栈沿用现有本地/系统字体，不新增在线字体依赖。正文不使用 Inter 替代中文系统字体。标题字重以 500-600 为主，避免全页粗体。

### 4.3 间距

采用 4px 基线：`4、8、12、16、20、24、32、40、48、64、80`。

- 控件内部：8-12px；表单字段间距：16-20px。
- 卡片内部：20-24px；内容区块：32-48px。
- 公共页面大区块：64-80px；工作台区块：16-32px。
- 不用增加空白解决层级不清，先调整字号、顺序和分组。

### 4.4 圆角、阴影与层级

| 类型 | 规则 |
|---|---|
| 小控件、标签 | 6px |
| 按钮、输入框 | 8px |
| 项目卡、路线卡 | 12px |
| 大面板、抽屉 | 16px |
| 胶囊形 | 仅筛选 chips、状态标签和分段控件 |

阴影仅用于抽屉、对话框和确有浮层关系的元素。默认卡片使用 1px 边界，不使用悬浮大阴影。层级固定为：内容 0、吸顶导航 20、局部浮层 30、抽屉 40、对话框 50、紧急提示 60。

## 5. 布局与页面骨架

| 页面类型 | 最大宽度 | 核心结构 |
|---|---|---|
| 公共门户 | 1200px | 标题与搜索、精选项目、项目目录 |
| 项目/方法阅读 | 1200px | 208px 左目录 + 最宽 760px 正文 + 必要辅助区 |
| 企业研究 | 1280-1440px | 当前判断、路线比较、证据侧栏、反馈 |
| 资料后台 | 1440-1600px | 导航/文件或流程/上下文检查器，按宽度逐级降级 |
| 数字馆与互动展项 | 按既有展项 | 保留全屏、暗色和专用画布，不套普通正文容器 |

断点统一参考 640、768、1024、1280px。桌面导航保持单行，高 64-72px；移动端可使用第二行导航或菜单按钮，但不能挤压品牌与关键操作。

## 6. 核心组件

### 6.1 导航与页脚

- 导航结构继续使用 `inno_site_chrome.py` 单源，不在各页面另写品牌、主菜单和页脚。
- 当前项使用墨蓝文字与 2px 下划线，hover 不改变布局。
- 外链明确标注，登录要求以简短文字说明，不用原生登录弹窗替代页面设计。
- 页脚负责跨站入口和资料说明，不重复整页导航。

### 6.2 按钮

- 主按钮：墨蓝底白字；次按钮：白底墨蓝字与边界；低优先级：无边框文字按钮。
- 高度至少 44px，水平内边距 16px，桌面标签不换行。
- 每组最多一个主按钮。危险操作必须使用明确名称，不能与主保存动作并列成同样权重。
- 必须实现 default、hover、active、focus-visible、disabled、loading。禁用时说明原因，不只降低透明度。

### 6.3 表单与筛选

- label 位于控件上方，帮助文字在控件下，错误紧邻字段。
- 输入框高 44px，多行输入可增高；placeholder 不代替 label。
- 搜索是项目库的主要动作，年份、奖项和状态作为次级筛选。
- 已选条件可读取、可清除；结果数、空结果、载入失败均有明确反馈。
- 移动端筛选项可进入抽屉，不能为了塞下一行而缩成 10px。

### 6.4 卡片与分节

卡片只用于真实重复对象：项目、方法、路线、经验、资料文件。普通章节优先使用标题、留白和分隔线，不全部装进白卡。

项目卡顺序：封面、奖项与年份、项目名称、单位、简介、资料状态。图像使用真实项目素材，不在图片上叠加装饰标签。

路线卡顺序：机制名称、成立条件、关键差异、未知、下一步。路线卡不是营销特性卡，不用图标和标题凑齐三列。

### 6.5 标签与内容状态

| 状态 | 视觉表达 | 禁止 |
|---|---|---|
| 来源陈述 | 文档图标 + 中性标签 + 来源入口 | 不写成平台已证实 |
| 平台解读 | 墨蓝文字 + “平台解读” | 不混进原文字体与引用块 |
| AI 解读/假设 | “AI”文字 + 虚线边界 + 前提与限制 | 不用紫色冒充 AI，不计入事实数 |
| 待确认 | 警告色文字 + 明确待核主体 | 不显示成已完成 |
| 冲突/错误 | 错误色 + 冲突说明与处理入口 | 不仅显示红点和红框 |
| 未知/未研究 | 正常次文字 + 缺口原因 | 不填 0，不用过浅灰色隐藏 |
| 历史版本 | 版本号 + 时间点 + 当前/历史说明 | 不让旧版看似当前结论 |

### 6.6 证据与引用

- 引文正文 16px，保留原文，不用 AI 改写后的句子代替。
- 来源元信息 12px，默认显示项目、来源、位置和阅读范围。
- SHA、chunk、内部路径等放在“技术核对”展开区。
- 证据抽屉桌面宽 440-520px，移动端近全宽；支持 Escape、焦点返回和明确关闭按钮。
- “可查阅证据”不等于“与当前路线匹配”，提示必须与证据同屏。

### 6.7 表格与数据

- 表格文字 14px，行高至少 48px，数字右对齐并使用等宽数字。
- 表头说明字段含义，未知留空并给原因，不填 0。
- 宽表只在表格容器内横向滚动，页面本身不产生横向滚动。
- 数据总览优先分组与筛选，不用一排彩色进度条制造完成感。

### 6.8 空、载入、错误与成功

- 空状态说明缺什么、为什么、下一步能做什么。
- 载入骨架匹配最终布局，不用全屏旋转 spinner。
- 错误保留用户输入和已有内容，提供可执行的重试或核对路径。
- 成功提示说明保存了什么版本与状态，不能只写“成功”。
- 临时提示可用 toast；需要用户处理的问题必须在上下文中持续显示。

### 6.9 折叠、抽屉与对话框

- 折叠用于次级内容，不隐藏当前关键错误和主要下一步。
- 手风琴标题区至少 44px，状态通过 aria-expanded 暴露。
- 对话框只用于需要打断当前任务的判断，普通阅读优先使用页面或抽屉。
- 关闭后焦点回到触发元素，背景不可继续误操作。

## 7. 页面模板

### 7.1 公共门户

目标是“找到项目并理解平台能做什么”。首屏只保留主题、简短导语、搜索和一个主动作。精选项目使用真实封面，后续列表按项目内容组织，不增加重复功能卡。

### 7.2 项目档案

目标是“读懂一个项目”。默认顺序：项目概览、问题与系统、设计思路、指标与验证、资料与来源、应用与质量。八模块按需展开，研究工具后置。正文与资料/评估切换时保持同一目录和正文网格。

### 7.3 方法库

目标是“找到方法并理解怎样使用”。先搜索和分类，再读输入、步骤、产物、边界和来源。方法图标服务识别，正文深度不转成装饰评分。

### 7.4 企业研究工作台

目标是“判断下一步研究什么”。首屏优先：当前问题、确认状态、关键未知、下一步。随后比较路线并核对证据。原始需求、待确认补充和反馈必须在视觉上可区分，不能自动改写成企业确认。

### 7.5 资料后台

目标是“处理资料并解决例外”。使用 14px UI 文字、紧凑行距和清晰队列状态。默认突出待处理与冲突，不让研究档案的宣传性内容占据工作区。

### 7.6 数字馆与教育

保留原站夜景、宋体和项目摄影。教育材料优先考虑投影、打印、课堂阅读和学生操作，不能直接复用企业后台的高密度布局。

## 8. 响应式、打印与无障碍

### 8.1 响应式验收

至少检查 1440、1280、1024、768、390、360px：

- 页面无横向溢出，文字不重叠，主要操作可见。
- 多栏在 1024/768px 有明确降级规则，移动端最终为单列。
- 触控目标至少 44×44px，字段与按钮不依赖 hover。
- 抽屉、表格、图谱和证据长文本有局部滚动策略。
- 200% 字体缩放时仍能完成主要任务。

### 8.2 无障碍基线

- 正文与关键控件达到 WCAG AA；正文目标 4.5:1，大字与非文本控件至少 3:1。
- `focus-visible` 使用 2px 印章红轮廓和 3px 间距，不能移除焦点。
- 键盘可完成导航、筛选、路线反馈、证据开关和保存。
- 图标按钮有可访问名称，图像 alt 说明项目内容而非“图片”。
- 状态不只靠颜色，错误与结果使用合适的 live region。
- 遵循 `prefers-reduced-motion`，不自动播放轮播和循环动效。

### 8.3 打印

打印时隐藏导航、交互按钮和抽屉，展开当前所需档案内容，保留项目名、版本、来源和缺口。避免卡片被截断、深底大面积耗墨和 URLs 丢失。教师活动单与项目档案分别走查。

## 9. 动效

只使用 120ms、180ms、240ms 三档，推荐 ease-out：

- 120ms：hover、active、按钮反馈。
- 180ms：选中、折叠、局部状态变化。
- 240ms：抽屉与对话框进入退出。

只动画 transform 与 opacity。动效必须回答“发生了什么变化”，不得用假处理进度、循环 shimmer 或自动滚动证明 AI 正在思考。

## 10. 工程与迁移规则

### 10.1 令牌契约

新组件使用 `--gd-*` 语义令牌，组件不得直接写品牌 hex。旧 `--inno-*`、`--pp-*`、`--ui-*` 只在单个迁移页面中映射，禁止一次全局替换影响原站。

### 10.2 组件完成定义

每个组件至少包含默认、hover、active、focus、disabled、空、载入、错误和移动状态；涉及保存时还要有成功与版本反馈。只有静态成功截图不算完成。

### 10.3 推荐迁移顺序

1. 建立真实组件样板页，覆盖本规范的核心组件与两类密度，用户先走查。
2. 将 `/inno/` 公共导航、按钮、表单和项目卡迁移到语义令牌。
3. 迁移项目档案的正文、模块、证据和状态，不改变深链与阅读结构。
4. 迁移 ML-025 工作台和资料后台，分别验收研究与高密度场景。
5. 原站只在新组件和明确局部改进中采用规范，保留既有展馆整体视觉。

不得一次性全站换肤，不得在视觉迁移中夹带研究正文、评分、路由或权限变化。

## 13. 深色展厅与浅色工作区的关系（2026-11-12 增补）

平台存在两种色域，不是主题切换关系，而是场景分工：

- **浅色工作区（默认）**：项目库、档案、方法库、应用中心、需求研究、数据总览、MCP 与全部工具页。以阅读和操作为目标，白底、单一紫色强调 #5a4fe6。
- **深色展厅（博物馆专属）**：好设计馆及 interactive-exhibit、legacy 展陈页（data-gd-family 为 museum）。以观看与体验为目标，近黑底色承载展品图与叙事，是"馆"的空间感，不是另一种皮肤。

过渡规则：

1. 公共导航与底部始终保持浅色 chrome，不随页面色域翻转；用户在任何页面都有稳定的定位锚点。
2. 从浅色区进入展厅时，深色只能从 hero 边界开始，不允许出现"半页深半页浅"的过渡带；展厅页 hero 上边缘与导航下边缘直接相接。
3. 展厅内的链接、按钮、表单控件对比度按深色主题令牌校验；从展厅点回工作区（项目档案、方法页）视为"离开展厅"，不做渐隐动画，直接切换。
4. 用户手动切换的深色主题（theme-toggle）只作用于浅色工作区，不覆盖展厅本身的深色；展厅页不显示主题切换的视觉差异属预期。
5. 新增展厅页必须归入 museum family 并复用 museum-hero.css，不自造第三种色域。
