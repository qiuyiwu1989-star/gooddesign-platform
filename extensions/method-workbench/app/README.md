# ML-006 / ML-007 创新工作台

启动：双击项目 `scripts/启动创新工作台.command`，浏览器打开 http://127.0.0.1:8786/ 。关闭终端停止服务；重新启动保留已保存版本。
也可在项目根运行 `python3 scripts/method_workbench_server.py`。

- 四个连续视图：研究任务、需求档案、方法与案例、方案与验证。
- 完整读取冻结目录的48方法+12谱系专题；支持名称/英文/别名/关键词检索和分类。六项执行契约单独标识。
- 需求支持新建、编辑、条目追加、硬约束待定、方法选择、保存新版本、读取历史、历史另存、JSON导出。没有删除操作。
- 数据唯一存储：`output/method-workbench-private/demands.sqlite`（私有、不入Git）。需要迁移时关闭服务后复制整个目录；不要删除数据库。
- 保存使用版本冲突检查，旧版本无法覆盖新版本。冲突时当前表单保留，可导出后再载入比较。切换任务/刷新未保存内容会提醒。
- 割胶导入版本绑定原ML-005研究包，报告仍绑定原实验r1；编辑后不会自动变成新研究结论。新任务没有对应已执行的方案。
- 案例关键词检索通过实际案例MCP返回最多12条题录；五个已读案例另可在实验来源报告阅读。题录匹配不等于证据已深研。
- 方案视图通过实际方法MCP创建六节点计划，绑定完整需求快照、版本和SHA。同任务版本重复点击复用计划。
- ML-007新增逐节点生成、草稿阅读/高级JSON修订、校验提交与下一步。每次生成只调用一次模型，不自动重试；提交仍是研究稿，不代表专业审核。
- 后台任务独立运行，刷新/关闭页面后仍可读取。失败可手动再次生成；当前运行同时仅一个活跃任务。卡住超过300秒标中断，不自动扣费恢复。
- R48新增需求基线门禁：原需求ID、硬度、验收设想与研究状态不能静默改变。模型改写验收设想会阻断，可修订后再提交。
- 可读取案例来源目录并绑定首块最多800字符摘录，来源多文本版本需明确选择；原文引用与迁移有效性分开。
- 评审备注追加保存；真实已提交产物可按内容展开阅读，导出Markdown研究报告及完整运行JSON。
- 造物云离线V2.3令牌和组件复用上层vendor；旧方法深度阅读器保持冻结原样。
- 仅限可信本机单用户，无远程用户认证或多人权限。服务绑定127.0.0.1，并检查Host/Origin/CSRF及静态资源路径。
- 模型生成消耗当前配置的模型额度；失败不自动更换模型、不自动重试。用户或Host Agent需审查草稿，系统不冒充独立领域专家。
- 已有割胶完整演示：两份真实模型草稿（R48经Host恢复验收原文），一次R17模型超时，后四份Host续写/适配。主工作台按完全相同任务复用并重新校验六份产物；不是六份全自动新生成。
- 迁移数据时关闭服务并复制整个私有目录，包含需求、引擎及执行任务三个数据库。私有模型调用原始审计另存既有运行数据目录。

验证：`python3 scripts/check_method_workbench.py`（9组）、`python3 scripts/check_workbench_execution.py`（5组）。实际模型及MCP运行、浏览器和导出报告记录位于 `output/method-workbench-check/ml007/`。截图、完整案例摘录及数据库不入Git；原试验和正式工作台均保留作者及失败来源。
