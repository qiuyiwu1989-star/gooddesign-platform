# 方法页标准 v1

状态：平台候选标准，2026-11-05。用于把方法内容、Agent使用、引擎调用和质量证据统一验收，不代表专家认证。

## 1. 方法页不是一篇文章

每个方法是一套版本化资产包：Dossier为知识真源，Deep Content为经审核的深化候选，Asset登记能力与版本，Skill指导Agent，Invocation约束调用，Contract约束严格Artifact，Evaluator检验行为，Reference Run提供回放，Quality Report说明证据与缺口。

HTML、Markdown、Skill和MCP读取结果必须由相同资产引用生成，不能分别维护方法事实。

## 2. 必备内容

| 板块 | 必须回答 | 不合格表现 |
|---|---|---|
| 身份 | 方法类型、版本、谱系、近邻差异 | 把框架/专题/工具混称 |
| 原理 | 为什么有效、前提、推论范围 | 只有定义和术语 |
| 适用性 | 何时用、何时不用、替代方法 | 所有创新任务都适用 |
| 输入 | 必需性、来源、单位、缺失处置 | 未知自动补全 |
| 过程 | 步骤、依赖、判断、返工、停止 | 固定步骤没有判断 |
| 产物 | 中间产物、输出、解释上限 | 报告长度代替Artifact |
| 引擎能力 | 阶段、能力、逻辑产物、上下游 | 只按方法名硬编码 |
| 调用 | Skill级别、MCP、成本、权限 | S1冒称严格自动执行 |
| 示例 | 完整例、负例、迁移边界 | 虚构客户或实测 |
| 评测 | 单元、路由、端到端、真实情境 | 结构通过等于方法有效 |
| 版本 | 内容/Skill/契约/评测/引擎版本 | 历史运行随最新版漂移 |
| 反馈 | 人工修订、Outcome、变更提案 | 点赞自动改公共方法 |

## 3. 最小案例与评测

每项方法至少具备：一个完整工作示例、两个实质负例、一个迁移边界例和一个符合能力等级的调用示例。数值方法还须给单位、公式、输入和独立复算；框架方法还须展示回返或编排决定。

评测分四层：方法单元、路由、端到端研究对照、真实情境。前端展示不纳入效果证据，文件数量和字段填充率不自动加分。

## 4. 调用等级

- S0：读取、解释和返回缺口，不能生成已执行结论。
- S1：引导、追问、组织草稿或研究计划，不能严格提交或冒称求解。
- S2：按冻结Schema和依赖执行、检查和交接，不等于专家或工程通过。

计算方法没有实际求解器时只能S1。缺概率、模型、材料、许可或真实结果时必须降级或停止。

## 5. 引擎质量贡献

每个方法声明`improves`和`failure_signals`，并绑定可观察Artifact或研究维度。评价至少覆盖问题理解、证据支持、机制推导、实施条件与风险、验证决策价值，另记人工修改、失败和成本。

不得用方法被调用、报告更长、术语更多或选项更多推断研究质量提升。端到端对照必须保持任务、资料、模型和预算一致，作者与独立评审分离；小样本只描述本次结果。

## 6. 状态与放行

内容候选、结构通过、语义复核、路由通过、端到端描述性结果、客户确认、领域专家、工程验证和发布分别记录。`isolated_effect_established`只有在方法专属性对照真实完成后才可为true。

任何关键错误、假证据、伪造现场/客户/专家、错误公式、无法复查的参考运行都阻断标杆。需要外部资源的事项列入依赖，不用免责声明代替可完成工作。

## 7. 版本与反馈

所有运行绑定精确内容、Skill、契约、评测和引擎版本。原始记录不可覆盖，反馈形成ChangeProposal，经固定回归、留出任务和独立审核后才能发布。回滚不删除历史。
