# 功能分析 · 1.0.0

平台操作改编；可研究试用，非原典逐字复现、方法认证或工程验证。

将任务拆成对对象产生作用的功能和接口，识别有用作用、有害作用及不足。

## 何时使用

- 系统边界是什么？
- 每个功能的输入输出是什么？
- 哪些作用必要，哪些作用有害或不足？
- 哪一个接口最需要验证？

## 输入

- 上一步问题简报（必需）
- 项目机制与证据（必需）

## 操作步骤

### 1. 确定系统与超系统边界

区分待设计系统、对象、操作者与外部环境；现有企业系统未知时只建目标功能模型。

产物：`system_boundary`。

检查：目标功能模型不是现有设备实测。

停止/待补：缺少必需信息则记录待补，不填造数据。

### 2. 分解必要功能

使用动词+对象描述功能及输出，关联上一阶段成功指标；保持功能与物理部件的区别。

产物：`function_tree`。

检查：每个功能服务一个要求；保留替代实现空间。

停止/待补：缺少必需信息则记录待补，不填造数据。

### 3. 描述作用关系

记录作用主体、作用、受体、结果、阶段、类型及依据；有害作用的目标发生情况未知则标风险假设。

产物：`interaction_model`。

检查：有害/不足/缺失不混用；每条关系有事实或假设标记。

停止/待补：缺少必需信息则记录待补，不填造数据。

### 4. 核对接口与失效链

描述前一环节的输出怎样进入后一环节；标出颗粒、运动、封口、转送等接口的条件及可能失效。

产物：`interface_risks`。

检查：单件成功不等于整链成功；专利候选不等于整机采用。

停止/待补：缺少必需信息则记录待补，不填造数据。

### 5. 确定优先分析的功能问题

按影响与未验证程度选择问题；把关系及接口作为下一步矛盾候选输入，不编造风险概率。

产物：`function_model`。

检查：给出焦点与理由；不将功能图视为工程验证。

停止/待补：缺少必需信息则记录待补，不填造数据。

## 输出

- 功能与接口模型
- 接口风险清单

## 限制与常见误用

- 企业现有设备不详时不宣称已找到真实故障根因
- 不能用部件罗列替代功能分析
- 危险工艺仍需专业安全评审
- 只列钻头、电机、软袋没有动作或受体
- 未见企业数据却标已发生故障
- 以一个部件性能代替全流程质量
