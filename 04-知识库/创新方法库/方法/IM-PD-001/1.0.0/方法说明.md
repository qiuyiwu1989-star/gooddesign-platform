# 问题定义 · 1.0.0

平台操作改编；可研究试用，非原典逐字复现、方法认证或工程验证。

把企业愿望整理为对象、情境、目标、约束、成功口径与待确认的问题简报。

## 何时使用

- 服务谁，处理什么对象？
- 现状与基线有什么记录？
- 哪些限制绝对不能改变？
- 成功由什么指标和阈值判定？

## 输入

- 用户/模拟任务（必需）
- 项目知识背景（可补）

## 操作步骤

### 1. 建立任务边界

明确谁在何处对什么对象完成什么工作，保留需求来源和模拟/真实标签。

产物：`task_boundary`。

检查：对象和目标清楚；不把模拟输入写成访谈事实。

停止/待补：缺少必需信息则记录待补，不填造数据。

### 2. 区分症状、目标和原因假设

记录观察到的现象、希望获得的效果、对原因的猜测；没有企业数据时症状和基线留空。

产物：`problem_layers`。

检查：原因不是事实标签；不把已有技术方案写成唯一目标。

停止/待补：缺少必需信息则记录待补，不填造数据。

### 3. 检查约束与知识参照

核对硬约束、可变条件和未知；从源项目提取问题/功能结构作参考，不移植其数值。

产物：`constraint_map`。

检查：硬约束优先；来源目标与企业目标分开。

停止/待补：缺少必需信息则记录待补，不填造数据。

### 4. 定义成功口径与追问

将成功拆成独立可测量维度：对象、指标、单位、工况、阈值与测量方法。缺少阈值则记录确认责任。

产物：`success_and_questions`。

检查：未知不补0；样品质量不能替代层序保持；无基线不计算提升。

停止/待补：缺少必需信息则记录待补，不填造数据。

### 5. 形成问题简报与阶段许可

汇总目标、边界、缺口和关键假设；输入足够可做概念探索，缺工况/阈值则禁止定型和效果承诺。

产物：`problem_brief`。

检查：每项要求可回溯需求；明确允许与禁止的输出。

停止/待补：缺少必需信息则记录待补，不填造数据。

## 输出

- 问题简报
- 成功指标与追问

## 限制与常见误用

- 关键对象和目标未知时先追问
- 紧急安全处置不能等候此研究流程
- 本方法不替代用户验证或正式需求评审
- 把我想要某机器人直接当完整问题
- 没有基线却输出效率提升
- 把来源约束误当企业已确认限制
