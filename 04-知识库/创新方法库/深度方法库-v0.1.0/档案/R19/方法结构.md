# 设计启发式：方法结构

身份：R19 / IM-ML-019 / 0.1.0

分类：B功能分析与概念生成；类型：tool_family

本文件定义检索与调用所需结构；完整解释见深度说明，逐步执行见操作指南。

## 任务入口

适合早期概念不够多样、已有可画或可描述的初始概念、团队愿意暂缓评判时使用。输入要有问题边界和必须保留的功能，否则变换可能只是脱离任务的幻想。若任务是按既定图纸制造、或法规和接口不允许关键变更，应明确哪些提示不能采用。没有合法可用卡片内容时，可以讨论公开策略思想与原创提示，不伪造卡号或声称已运行完整77卡库。

## 输入契约

- `brief`：任务与约束；object；必需=True；缺失=ask_or_stop
- `concept`：初始概念；object；必需=True；缺失=ask_or_stop
- `prompts`：合法可用提示；array；必需=True；缺失=ask_or_stop

## 步骤与产物流

| 步骤 | 依赖 | 输入 | 输出 |
|---|---|---|---|
| R19-S01 记录初始方案和固着点 | 入口 | brief、concept、prompts | concept_baseline |
| R19-S02 选择并标识变换提示 | R19-S01 | concept_baseline、brief、concept、prompts | selected_prompts |
| R19-S03 生成并描述概念变换 | R19-S02 | selected_prompts、brief、concept、prompts | concept_variants |
| R19-S04 检查差异和任务适配 | R19-S03 | concept_variants、brief、concept、prompts | variant_review |
| R19-S05 交接筛选与试验 | R19-S04 | variant_review、brief、concept、prompts | selection_package |

## 最终产物与判读

- `concept_variants`：概念变换链；字段：baseline、prompt_ref、variant、mechanism_change；说明思路改变，不证明性能。
- `selection_package`：概念比较输入；字段：concepts、constraints、unknowns、validation_questions；交给筛选和验证。

## 引擎边界

先按任务与适用条件筛选，再检查输入是否足够；步骤查询来源，产物按绑定关系交给下一方法。当前只提供内容与读取接口，未注册既有运行执行器。

## 评估情境

- 多个草图实际机制相同 → 标为细化而非多原理创新。
- 无官方卡组版本却要求卡号 → 拒绝伪造编号，可用明确原创提示。
- 提示导致丢失防散落功能 → 排除或重构，并留下原因。
