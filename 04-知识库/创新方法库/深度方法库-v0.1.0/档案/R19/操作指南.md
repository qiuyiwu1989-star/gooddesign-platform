# 设计启发式（Design Heuristics）

R19 · IM-ML-019 · 0.1.0 · tool_family

用具体的设计变换提示打破对首个概念的固着，并保存每次变换如何改变功能、结构与使用方式。

状态：研究档案；平台操作适配；未专家审核；工程效果未验证。

## 身份与原典

本条指Daly、Yilmaz、Seifert、Gonzalez等研究者发展的Design Heuristics，不是一般意义上的经验法则，也不是界面可用性检查清单。团队公开介绍其77项策略卡，并提供研究和教学材料。本档案采用“提示驱动概念变换”的用法，不收录或重制完整商业卡组。研究、教学活动和本平台调用协议有不同身份，不能把一份课堂流程当普适工程标准。

## 什么时候用

适合早期概念不够多样、已有可画或可描述的初始概念、团队愿意暂缓评判时使用。输入要有问题边界和必须保留的功能，否则变换可能只是脱离任务的幻想。若任务是按既定图纸制造、或法规和接口不允许关键变更，应明确哪些提示不能采用。没有合法可用卡片内容时，可以讨论公开策略思想与原创提示，不伪造卡号或声称已运行完整77卡库。

## 输入准备

| 输入 | 类型/必需 | 内容与来源 | 缺失处置 |
|---|---|---|---|
| 任务与约束 | object / 必需 | 必要功能、使用场景、不能改变的接口和限制 | ask_or_stop |
| 初始概念 | object / 必需 | 工作机制、草图或文字结构及当前不足 | ask_or_stop |
| 合法可用提示 | array / 必需 | 官方已取得卡片或明确平台原创提示，含身份版本 | ask_or_stop |

## 操作步骤

### R19-S01 记录初始方案和固着点

**输入：** brief、concept、prompts

**动作：** 说明现方案如何工作、哪些地方只有单一路线，并列必须保留的功能。

**判断：** 若初始概念不能解释作用，先补描述；没有必要功能则回任务。

**产物：** concept_baseline；原始概念、功能、固着点、边界。

**检查：** 不把问题模糊直接当缺创意。

**停止/返回：** 无法说明待变换对象时停止。

**知识查询：** 按本步对象查询功能、机制、工况及验证边界，并保留原文位置

**依据：** S01、S02

### R19-S02 选择并标识变换提示

**输入：** concept_baseline、brief、concept、prompts

**动作：** 从合法可用提示中选择适合对象的方向，记录真实名称、编号或平台原创身份。

**判断：** 提示与硬约束冲突则排除；无卡片版本不宣称官方命中。

**产物：** selected_prompts；提示内容、出处、选择理由和限制。

**检查：** 原创提示不套用官方卡号。

**停止/返回：** 无法确认提示身份或使用权时换公开/原创提示。

**知识查询：** 按本步对象查询功能、机制、工况及验证边界，并保留原文位置

**依据：** S01、S02

### R19-S03 生成并描述概念变换

**输入：** selected_prompts、brief、concept、prompts

**动作：** 分别或连续应用提示，用图文说明构件、作用或交互怎样变化；保留前后链。

**判断：** 变体须解释如何工作；仅改名不算新概念。

**产物：** concept_variants；变体、变换前后、作用机制和生成链。

**检查：** 纵向细化和横向变化分别记录。

**停止/返回：** 变体丢失必要功能时返回。

**知识查询：** 按本步对象查询功能、机制、工况及验证边界，并保留原文位置

**依据：** S02

### R19-S04 检查差异和任务适配

**输入：** concept_variants、brief、concept、prompts

**动作：** 比较变体与原方案的功能分配、布置、交互及风险，记录无效提示与未知。

**判断：** 违反硬约束剔除；关键数据未知不判更优。

**产物：** variant_review；差异表、排除原因、代价和未知。

**检查：** 数量与新颖性不替代可用性。

**停止/返回：** 没有可说明的有效变换时换提示或改用其他方法。

**知识查询：** 按本步对象查询功能、机制、工况及验证边界，并保留原文位置

**依据：** S01、S02

### R19-S05 交接筛选与试验

**输入：** variant_review、brief、concept、prompts

**动作：** 按共同准则整理可比较的概念，形成关键假设验证问题。

**判断：** 缺少证据则给条件性候选，不给唯一最优。

**产物：** selection_package；原方案与变体的比较包及后续验证问题。

**检查：** 每条路线仍覆盖任务目标。

**停止/返回：** 不能确定验证对象时先补概念描述。

**知识查询：** 按本步对象查询功能、机制、工况及验证边界，并保留原文位置

**依据：** S01、S02

## 产物

- **concept_variants / 概念变换链**：baseline、prompt_ref、variant、mechanism_change。说明思路改变，不证明性能。
- **selection_package / 概念比较输入**：concepts、constraints、unknowns、validation_questions。交给筛选和验证。

## 结果怎样判读

输出关注概念之间的有意义差异及变换链。一个新概念要能说明工作机制和保留的必要功能，而不是只有一句新名字。纵向细化与横向改变都可能有价值，不应一律把变化大当好。记录某次提示没有带来有效概念同样重要，可以揭示边界或输入缺失。后续通过共同准则筛选和工程验证，不能把卡片使用次数或概念数量当成质量总分。


## 完整示例

教学演示：初始概念是固定式桌面零件托盘，任务是便于取放且不使小零件散落。第1步记录托盘的盛放与取用功能；第2步选一个明确标平台原创的“改变构件相对位置”提示，不称其为某号官方卡。第3步形成可倾斜取用面和可拆分小盒两个变体；第4步说明前者可能增加零件滑落风险，后者增加装配与清洁负担，分别标未知。第5步把初始方案和两条变体交给共同准则比较。这里没有用户试用或有效性数据，示例只展示如何留下可审查变换记录。


## 反例与常见误用

误用一：把任何随机建议都叫77卡的某个编号，正确做法是使用真实取得的版本并标出处。误用二：抽到提示后先改外观，却不说明作用链，应要求新旧概念并排解释。误用三：为了显得创新忽略原功能和安全要求，须通过边界检查。反例是零件必须完全兼容现有工装且不允许变更结构，此时提示只能在允许空间内细化，不能把不合约束的变体作为可实施方案。


## 检查与验证

执行检查可要求每个概念附来源、变换前后、作用变化、保留功能和未知项，并用外观变化反例核验是否误报原理创新。方法效果需在适当任务中比较概念多样性与适用性，避免只数草图。工程效果则需额外的受力、制造、用户和寿命测试；课堂使用或实验室概念研究不自动成为真实产品收益证据。没有卡组许可时，引擎不得复制卡片图示或隐藏来源。


## 平台适配说明

研究者的经验启发式思想、教学协议对新旧概念和采用提示的记录要求为参照。平台增加输入契约、约束检查、概念差异说明和来源版本，以便同形态学、筛选和验证连接。示例提示为平台自行构造，不宣称等同官方卡片；本文也未把教学活动规定的团队人数或时间安排设为引擎必须遵守的固定算法。
