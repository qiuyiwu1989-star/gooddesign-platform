# 公理化设计（Axiomatic Design）

R30 · IM-ML-030 · 0.1.0 · theory_method

在顾客、功能、物理和过程域之间建立映射，以功能独立性诊断耦合，并在有可靠成功概率证据时比较信息含量。

状态：研究档案；平台操作适配；未专家审核；工程效果未验证。

## 身份与原典

公理化设计由Suh发展，利用域、层级、往返分解和两条公理组织设计。四域分别描述顾客希望获得的益处、功能要求FR、实现它们的设计参数DP以及制造实现的过程变量PV。它既可用于新方案，也可用于诊断现有架构。FR不是零件名，DP不是需求的换一种说法；把两者混淆会使矩阵看似清晰却没有设计信息。

## 什么时候用

输入应有顾客需求来源、FR及允许范围、约束、候选DP和影响证据。FR构成满足任务所需的最小独立要求集合，不宜把所有营销形容词各列一项；约束是可接受方案的边界，应与可调整功能要求区分。层级分解应在选择上层DP后展开下层FR，因为不同实现原理会引出不同下层任务。

## 输入准备

| 输入 | 类型/必需 | 内容与来源 | 缺失处置 |
|---|---|---|---|
| 顾客需求与约束 | object / 必需 | 益处、场景、边界及来源 | 先需求定义 |
| 功能要求 | array / 必需 | FR、范围与父子关系 | 先分离功能与实现 |
| 候选设计参数 | array / 必需 | 实现元素、范围和影响证据 | 生成候选实现 |

## 操作步骤

### R30-S01 区分四域与约束

**输入：** needs、fr、dp

**动作：** 把顾客益处、FR、DP、PV分开，检查FR不包含预设零件。

**判断：** 需求缺证据先回需求分析。

**产物：** domain_map；四域与约束映射

**检查：** FR和DP角色不混淆

**停止/返回：** 功能遗漏则暂停诊断

**知识查询：** 按本步对象查询功能、机制、工况及验证边界，并保留原文位置

**依据：** S01

### R30-S02 建立同层设计矩阵

**输入：** domain_map、needs、fr、dp

**动作：** 记录每个DP对每个FR的影响及依据、阈值与工况。

**判断：** 未知影响写未知，不填零。

**产物：** design_matrix；可追溯影响矩阵

**检查：** 所有非零和零项有解释

**停止/返回：** 关键影响未知则补分析

**知识查询：** 按本步对象查询功能、机制、工况及验证边界，并保留原文位置

**依据：** S01、S02

### R30-S03 诊断独立或耦合

**输入：** design_matrix、needs、fr、dp

**动作：** 检查对角、可排序三角与循环耦合，给出操作顺序或重构需求。

**判断：** 重排只改变显示，不消除真实依赖。

**产物：** coupling_review；架构类型与调整逻辑

**检查：** 验证顺序对功能满足的影响

**停止/返回：** 错误合并FR隐藏耦合则重写

**知识查询：** 按本步对象查询功能、机制、工况及验证边界，并保留原文位置

**依据：** S01、S02

### R30-S04 往返分解实现

**输入：** coupling_review、needs、fr、dp

**动作：** 在已选上层DP基础上生成下层FR/DP，逐层复查独立性。

**判断：** 不同上层原理可导致不同下层FR。

**产物：** hierarchy；功能与实现层级

**检查：** 层级边界保持一致

**停止/返回：** 缺上层选择依据则不盲目分解

**知识查询：** 按本步对象查询功能、机制、工况及验证边界，并保留原文位置

**依据：** S01

### R30-S05 有条件比较并验证

**输入：** hierarchy、needs、fr、dp

**动作：** 先保独立性；有可靠概率才比较信息含量，同时测试范围与制造条件。

**判断：** 无概率证据标不可计算，保留定性结论。

**产物：** ad_validation；架构验证及信息比较状态

**检查：** 不以件数或字数代替信息量

**停止/返回：** 关键FR未满足则淘汰

**知识查询：** 按本步对象查询功能、机制、工况及验证边界，并保留原文位置

**依据：** S01

## 产物

- **ad_validation / 公理化设计档案**：四域映射、FR范围、设计矩阵、耦合类型、顺序、层级、验证、信息比较状态。给出功能独立性诊断，概率不足不伪造信息量。

## 结果怎样判读

平台把四域映射和矩阵诊断作为可执行核心，把信息公理作为证据有条件时才启用的比较层。定性X/O矩阵需要说明忽略小交叉影响的阈值；非线性系统的影响随工作点变化，应记录适用工况。矩阵可重新排序以寻找解耦顺序，但重排不能消除真实耦合。若没有概率分布或可靠数据，输出信息量不可计算，不给伪精确排名。


## 完整示例

教学例：夹具要求设定夹持力和定位位置。若同一调节螺钉同时改变两者，而另一调节件也交叉影响，形成耦合。候选可把定位基准与施力路径分开，使位置调整先完成、夹持力随后设定；实际矩阵也可能只是三角结构，需保留操作顺序。若弹性变形仍改变位置，必须在工作载荷下复查影响。此例为原创，不是MIT水龙头示例转录，也没有概率数据比较信息量。 定性矩阵补充：令FR1＝定位位置、FR2＝夹持力；DP1＝定位基准调节、DP2＝独立施力调节，行FR、列DP。初始耦合假设A0＝[[X,X],[X,X]]，表示两调节均影响两要求。若结构改变后得到A1＝[[X,0],[X,X]]，则先调DP1满足位置，再调DP2满足夹持力；DP2不改变位置，DP1会扰动夹持力，因此反过来或再次调DP1需重新设定夹持力。若真实载荷下测得DP2仍显著改变位置，A1的零项失效，应恢复耦合判断。理想独立候选A2＝[[X,0],[0,X]]可分别调节，但本例没有工程证据证明达到A2；X/0均是待核验影响假设，不是数值灵敏度。


## 反例与常见误用

不要因为设计有两个旋钮就认定独立，必须看输出响应；也不要将多个FR合成一个模糊要求来藏耦合。矩阵零项通常是建模近似，不表示任何条件下严格为零。多目标优化可以找到折中点，但不会自动改变耦合架构。信息公理不能用主观打分冒充成功概率，FR之间有相关性时也不能随意把单项概率相乘。


## 检查与验证

首先审查FR是否覆盖真正需求且未预设实现；其次通过计算、试验或专家证据建立DP影响。对候选检验调整顺序、载荷变化、公差和不同工作点，确认FR在允许区间内。若采用概率比较，须说明设计范围、系统表现分布、数据来源及相关性处理；数据不足时保留定性独立性结论。架构诊断和最终制造可行性仍需分别验收。


## 平台适配说明

引擎可保存顾客需求—FR—DP—PV链及父子层级，每条影响关系附证据、工况和强度。先检查循环耦合，再建议变更实现原理、分离功能或改变调整顺序。与DSM区别在于这里是不同域的需求实现映射，DSM通常是同类元素间的方阵依赖；不能用同一矩阵名互换。方案生成可交形态学或TRIZ，回来再做独立性诊断。
