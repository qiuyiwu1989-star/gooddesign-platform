# 系统工程：方法结构

身份：R04 / IM-ML-004 / 0.1.0

分类：G全流程规划与创新管理；类型：framework

本文件定义检索与调用所需结构；完整解释见深度说明，逐步执行见操作指南。

## 任务入口

适合多个子系统或组织参与、有复杂人机/信息/物理接口、生命周期较长或集成风险显著的装备。小型项目仍需系统思考，但责任和文档可以裁剪；不应为一个简单零件配置航天规模评审。必须知道系统服务什么任务、边界和相关角色。若完整上游要求不可得，先建立暂定运行概念与未知，不把推断要求写成已批准基线。

## 输入契约

- `mission_context`：系统任务与运行情境；object；必需=True；缺失=ask_or_stop
- `system_inventory`：系统元素与已有证据；object；必需=True；缺失=ask_or_stop

## 步骤与产物流

| 步骤 | 依赖 | 输入 | 输出 |
|---|---|---|---|
| R04-S01 定义系统及运行场景 | 入口 | mission_context、system_inventory | conops_scope |
| R04-S02 形成并检查系统要求 | R04-S01 | conops_scope、mission_context | system_requirements |
| R04-S03 建立架构和功能分配 | R04-S02 | system_requirements、system_inventory | allocated_architecture |
| R04-S04 定义关键接口和集成次序 | R04-S03 | allocated_architecture | interface_integration_plan |
| R04-S05 建立验证确认与变更追溯 | R04-S04 | interface_integration_plan、system_requirements | system_assurance_package |

## 最终产物与判读

- `system_assurance_package`：系统工程设计与保证包；字段：conops、requirements、architecture、interfaces、vv_plan、configuration、unknowns；支持系统协调和下一步验证，不是整体性能证明

## 引擎边界

先按任务与适用条件筛选，再检查输入是否足够；步骤查询来源，产物按绑定关系交给下一方法。当前只提供内容与读取接口，未注册既有运行执行器。

## 评估情境

- 子系统均有报告但接口未知 → 输出接口风险，不判系统达标
- 复用设备换环境 → 重新分析适用与验证
- 任务边界缺失 → 先定义运行情境
