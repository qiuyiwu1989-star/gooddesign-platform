# 系统化工程设计：方法结构

身份：R01 / IM-ML-001 / 0.1.0

分类：G全流程规划与创新管理；类型：framework

本文件定义检索与调用所需结构；完整解释见深度说明，逐步执行见操作指南。

## 任务入口

适合新技术产品、复杂改型和多专业交叉研发，尤其适合存在若干原理路线、要求和制造条件尚需逐步协调的任务。已有成熟零件仅需校核一个尺寸时，可裁剪到要求、计算和确认活动，不必重跑概念探索。必须至少知道处理对象、预期作用与不可改变条件；只有市场口号时先做问题定义。安全或法规关键任务需相应专业流程，不能以本框架替代合规工作。

## 输入契约

- `task_brief`：任务简报；object；必需=True；缺失=ask_or_stop
- `design_resources`：设计资源；object；必需=True；缺失=ask_or_stop

## 步骤与产物流

| 步骤 | 依赖 | 输入 | 输出 |
|---|---|---|---|
| R01-S01 澄清任务并固定要求口径 | 入口 | task_brief、design_resources | requirements_baseline |
| R01-S02 建立功能与工作原理候选 | R01-S01 | requirements_baseline | principle_concepts |
| R01-S03 形成实体布局并核对取舍 | R01-S02 | principle_concepts、design_resources | embodiment_options |
| R01-S04 细化定义与验证安排 | R01-S03 | embodiment_options、requirements_baseline | detail_package |
| R01-S05 审查并决定冻结或返回 | R01-S04 | detail_package | design_stage_record |

## 最终产物与判读

- `design_stage_record`：系统化设计阶段包；字段：requirements、functions、principles、embodiment、verification_plan、unknowns；说明设计逻辑和成熟范围，不证明实物达标

## 引擎边界

先按任务与适用条件筛选，再检查输入是否足够；步骤查询来源，产物按绑定关系交给下一方法。当前只提供内容与读取接口，未注册既有运行执行器。

## 评估情境

- 任务清晰但工况未知 → 形成阶段计划与未知清单，不发布制造达标结论
- 只有市场口号 → 返回问题定义
- 简单尺寸校核 → 裁剪到所需分析，不强制全链
