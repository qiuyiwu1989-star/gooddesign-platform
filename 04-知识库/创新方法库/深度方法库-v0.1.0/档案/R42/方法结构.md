# 验证与确认：方法结构

身份：R42 / IM-ML-042 / 0.1.0

分类：F方案决策与验证评价；类型：framework

本文件定义检索与调用所需结构；完整解释见深度说明，逐步执行见操作指南。

## 任务入口

适合硬件、软件、集成产品以及采购复用件；在开发早期应同步规划，在零件和系统各层按相应目的实施。需要可追踪要求、预期使用和对象版本；若要求含糊，先回要求定义，不让测试工程师事后发明及格线。用于监管产品时还需适用专门标准、受控设施及责任审批，本档不提供行业资格或认证程序。

## 输入契约

- `requirements`：技术要求基线；array；必需=True；缺失=ask_or_stop
- `intended_use`：预期使用与利益相关方期待；object；必需=True；缺失=ask_or_stop
- `product_configuration`：对象与配置；object；必需=True；缺失=ask_or_stop
- `test_capabilities`：执行能力与既有证据；object；必需=False；缺失=mark_unknown

## 步骤与产物流

| 步骤 | 依赖 | 输入 | 输出 |
|---|---|---|---|
| R42-S01 分离两类追溯目标 | 入口 | requirements、intended_use、product_configuration | vv_targets |
| R42-S02 建立方法与判据矩阵 | R42-S01 | vv_targets、test_capabilities | vv_plan |
| R42-S03 检查就绪与配置 | R42-S02 | vv_plan、product_configuration、test_capabilities | readiness_record |

| R42-S06 报告并保留可复用证据 | R42-S05 | vv_findings、vv_evidence | vv_dossier |

## 最终产物与判读

- `vv_dossier`：验证与确认档案；字段：verification_coverage、validation_coverage、configuration、methods、criteria、evidence、anomalies、limitations、retest；有计划不等于已执行；结论只覆盖相应配置和条件

## 引擎边界

先按任务与适用条件筛选，再检查输入是否足够；步骤查询来源，产物按绑定关系交给下一方法。当前只提供内容与读取接口，未注册既有运行执行器。

## 评估情境

- 输入足够的研究任务 → 产生vv_dossier，每项判断保留依据、假设和适用范围
- 缺少requirements → 追问目标与边界，停止确定性分析，不编造输入
- 候选违反明确硬约束 → 排除并解释，不用总分或统计指标抵消要求
- 实际数据、测量或分析工具不可用 → 只保存研究/验证计划，不填造实际结果、通过或风险降低
