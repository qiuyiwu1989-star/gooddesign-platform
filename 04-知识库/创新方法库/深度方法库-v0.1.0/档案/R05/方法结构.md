# 机电系统V模型：方法结构

身份：R05 / IM-ML-005 / 0.1.0

分类：G全流程规划与创新管理；类型：framework

本文件定义检索与调用所需结构；完整解释见深度说明，逐步执行见操作指南。

## 任务入口

适合同时包含传感、执行、控制、软件、网络或人机交互的产品，尤其是接口决定性能的装备。纯机械零件不必为了采用V模型强加控制系统。必要输入是可说明的系统任务、分解层级及各专业边界；若对象和用途未定，应先做问题定义。专业设计尚不成熟时，右侧可以先规划集成实验，不把模型检查升为实物结果。

## 输入契约

- `system_task`：机电系统任务；object；必需=True；缺失=ask_or_stop
- `discipline_context`：专业与接口条件；object；必需=True；缺失=ask_or_stop

## 最终产物与判读

- `v_model_record`：机电V模型开发记录；字段：levels、design_refs、interface_refs、verification_links、changes、unknowns；说明分层开发与证明计划，不是整机验证结论

## 引擎边界

先按任务与适用条件筛选，再检查输入是否足够；步骤查询来源，产物按绑定关系交给下一方法。当前只提供内容与读取接口，未注册既有运行执行器。

## 评估情境

- 只有空载演示 → 只认可空载行为，不扩大到有载/故障
- 机械软件坐标不一致 → 返回接口定义
- 需求更改但测试未更改 → 标原证据待复核
