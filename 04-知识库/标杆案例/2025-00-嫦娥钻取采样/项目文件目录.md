# 嫦娥项目文档 · 文件目录

这份目录把现有案例按统一规范归类；文件保持原位。阅读时以同一份[项目档案](档案.html)中的三个入口为主，维护时按下表找到唯一编辑位置。

```text
嫦娥月球钻取采样系统
├── 项目档案：项目概况 / 需求与系统 / 设计思路 / 指标与验证
│             专利与论文 / 历程与故事 / 应用与价值 / 质量与维护
├── 资料与解读：4篇文献解读 / 23份来源目录
├── 档案评估：六维自评 / 模块统计 / 待补资料 / 审核与版本
├── 数据：事实真源 / 正文真源 / 解读 / 评分依据 → 生成字段、索引与统计
├── 来源：来源卡 / 内部原始附件定位
└── 版本：内容快照 / 增删改 / 完整性记录
```

上述4篇/23份为2026-10-20的目录规模，不表示全量成果已找到；其中2篇全文、2篇摘要，自评55/100，仍待专业审核。

## 三个阅读入口对应什么文件

| 读者入口 | 当前入口与内容真源 | 说明 |
|---|---|---|
| 项目档案 | [档案.html](档案.html)、[主档案结构.json](主档案结构.json)、[阅读内容.json](阅读内容.json) | HTML默认阅读版，八模块按需展开；正文依据结构化记录组织 |
| 资料与解读 | 同一HTML的“资料与解读”、[来源卡](来源卡/)、[档案数据.json](档案数据.json) | 解读与题录共享论文ID，摘要不标全文 |
| 档案评估 | 同一HTML的“档案评估”、[质量评估依据.json](质量评估依据.json)、[质量评估.json](质量评估.json) | 依据人工维护，分数按量规计算；不是项目技术评分 |

[档案.md](档案.md)是现有研究正文导出，不是三个阅读视图逐字拼接的独立文档。新规范的三份独立MD在本案例尚未单独生成，避免把不存在的导出件列为已完成。

## 后台文件职责

| 分类 | 当前文件 | 维护方式 |
|---|---|---|
| 事实与来源真源 | 档案数据.json | 修改事实先改此处，并处理依赖正文及关联记录 |
| 整合正文真源 | 主档案结构.json | 人工整合，12维度/49复合字段 |
| 解读真源 | 阅读内容.json | 平台解释，不自动升级为事实 |
| 评分依据 | 质量评估依据.json | 记录评价理由、等级与证据 |
| 研究过程 | 研究日志.json、研究证据.json、引擎审计.json | 记录实际检索、工况、缺口和判断 |
| 设计经验 | 匹配知识.json | 三条经验及人工样例，尚非真实企业匹配验证 |
| 原子化数据 | 原子字段档案.json、字段规范.json/csv | 生成/共享字典副本，17实体/233字段；不手工改输出 |
| 索引与统计 | 字段索引.json、来源反向索引.json、阅读统计.json | 生成，取值计数以真源为准 |
| 计算与评估 | 研究分析.json、质量评估.json、匹配评估.json | 生成，区分来源数据与平台复算 |
| 来源材料 | 来源卡/；内部原始附件在平台01-原始资料/ | 来源ID回链；原附件不随页面默认公开 |
| 版本治理 | 版本声明.json、版本/版本索引.json、版本/<版本>/ | 页面/内容/规则独立编号，冻结后不可覆盖 |
| 检查报告 | 各验收JSON/MD、阅读交互验收.json | 检查结果，不当作项目本身研究证据 |
| 派生图谱 | 项目图谱.html/json、割胶机器人-迁移试读.json、图谱调用样例.json | 人工迁移试读，固定源档案0.4.0；目标资料不写回嫦娥事实 |

## 后续使用

新案例复制[空白模板](../../模板/项目文档标准模板-v1/README.md)，依[文件结构规范](../../项目档案标准-v1/项目文档文件结构规范-v1.md)组织。嫦娥保留现有路径，以兼容当前构建和历史链接；不能把现有所有文件连同事实复制后只改项目名。

本例统一构建入口：项目根执行`python3 scripts/build_benchmark_dossier.py`。新项目使用新目录前需要通用构建适配，当前脚本仍针对嫦娥样本。
