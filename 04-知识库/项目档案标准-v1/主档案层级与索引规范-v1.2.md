# 好设计主档案：成文、层级与索引规范 v1.2

适用：v1.0字段框架、v1.1证据执行规范及012主档案。本文补齐“有研究台账”到“有完整项目主文档”之间的内容组织规则。

## 1. 标准文档的交付定义

主档案是一份独立成文的项目文档，读者沿正文即可理解项目身份、需求、设计、创新、验证、成果和历程。来源目录用于支持和审查正文，不承担拼接正文的功能。

交付分为：
- 主档案正文：有摘要、目录、章节导语、整合叙述、指标表、发展时间线和缺口说明。
- 字段索引：按维度、语义字段、标签、数值或相关条目定位正文。
- 证据附录：事实条目、原始资料、核读边界以及来源使用关系。

三者共用数据，不分开维护互相冲突的版本。

## 2. 五层关系

项目（project_id）
→ 档案维度（dimension key / D号）
→ 正文字段（field_key / 稳定record_id / 当前显示序号）
→ 事实、分析、事件、专利、论文或任务条目
→ 来源资料（source_id、原文位置、读取范围）。

一份来源可以支持多个字段，一个字段也可以引用多份来源。记录“被哪些字段使用”的反向索引，修订时能追踪影响范围。技术候选关系不因建立索引自动升级为项目确证。

## 3. 正文层级

| 一级维度 | 主要叙述任务 |
|---|---|
| 项目身份与摘要 | 说明是什么、谁完成、何种奖项、研究边界 |
| 背景、目标与约束 | 说明问题、需求、已有基线和约束 |
| 技术系统与设计过程 | 说明组成、原理、接口、关键材料、操控及待补指标 |
| 创新机制与五大构成 | 解释设计如何回应问题、取舍和边界 |
| 性能、验证与应用结果 | 集中呈现指标、版本、单位、工况与实际结果 |
| 知识产权与成果 | 区分披露总量、已找到条目和已确认归属 |
| 团队、协作与贡献 | 区分完成单位、报道角色和待确认分工 |
| 发展历程与版本 | 以事件串联前期、承研、验证、应用及获奖 |
| 关键故事与决策 | 组织可核实故事，列出待访谈的决策问题 |
| 知识迁移与应用 | 连接产业、馆和教育，保留假设与验证边界 |
| 资料与可信边界 | 解释来源、读取范围、事实与分析及授权 |
| 生命周期与维护 | 展示项目/档案/审核状态、更新记录与任务 |

正文先陈述整合结论，再呈现数据或必要表格；逐条证据放在可展开的依据区。不能以原文摘录的顺序替代项目叙事。

## 4. 字段合同

每个字段至少有：
- `id`：本项目内稳定编号，如F020；既有编号不因章节调序重排。
- `record_id`：跨项目唯一编号，如2025-00:F020。
- `field_key`：语义键，用于跨项目映射；通用字段与领域扩展分别标识。
- `display_code`：当前目录中的显示序号，允许随排序改变，不作永久ID。
- `title`、`body`：字段标题与整合后的正文。
- `data_type`、`value`、`unit`、`scope`：可检索的结构化值和适用口径。
- `tags`：受控词表ID；同时记录标签轴和显示名称。
- `content_nature`、`value_state`、`review_state`：性质、资料状态和审核状态。
- `claim_ids`、`record_refs`、`evidence`：关联条目及原始出处/位置。
- `gap_id`、`task_ids`：缺口与维护任务，缺失数据保持null或明确的部分对象。
- `valid_as_of`：资料有效范围的截止时间。

整合分析必须标记为平台解读；结构化值不通过标签或模型推测自动补全。字段的值若为表格，每一行保留独立对象/版本和对应条目。

## 5. 标签与索引

标签轴包括对象、问题、机制、验证、成果、历程、价值、应用与治理。每个标签ID唯一，名称有定义；项目具体标签只在适用时使用，不要求所有案例拥有相同机制标签。

正文点击标签进入相关字段集合；字段索引支持标题/数值/单位/语义键/事实编号/来源编号/关联专利号检索，并可组合维度与标签筛选。索引结果必须能直接回到对应正文段落。

来源附录显示引用该资料的全部字段；背景或选例资料未直接使用时明确标明，不生成空泛的“所有字段都引用所有来源”。

## 6. 完成度分开验收

- **文档结构已整合**：维度明确，正文可以独立阅读，字段和索引关系闭合。
- **资料已充分**：重要事实有足够来源、关键缺口已经补证。
- **专业审核通过**：有实际审核人和确认记录。
- **持续维护成立**：有责任人与真实更新历史。

四项分别显示。文档结构完成不能替代后三项，也不能用资料不全为理由只交一份台账。

## 7. 数据与重建

- `档案数据.json`：研究证据台账，保留原有条目。
- `主档案结构.json`：人工整合正文和层级的真源。
- `字段索引.json`、`来源反向索引.json`：生成视图，不人工另改。
- `档案.html`、`档案.md`：由主档案生成的阅读与导出版本。
- `研究台账.html/md`：保留原研究视图供审计。

生成器不从条目自动推断主档案正文，不覆盖人工编写的主档案JSON。新增字段只追加新ID；移动维度或更改语义键需保留迁移映射。数据结构当前为试行合同，正式API仍需迁移与Schema校验设计。
