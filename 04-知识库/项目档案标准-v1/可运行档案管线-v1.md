# 可运行档案管线 v1

这是一条在本机运行、带研究审核环节的管线。原件、清洗证据、字段候选、已发布档案分层保存，不将机器转换或AI输出自动升级为事实。

## 启动与停止

- 本机已安装。双击 `scripts/启动档案管线.command`；入口 http://127.0.0.1:8776/?project=2025-00 。该服务同时提供文件后台、投递箱监听与研究任务，不需要另启旧watch。
- 首次在另一台Mac运行：Python 3.10+和Xcode命令行工具就绪后，双击 `scripts/安装档案管线.command`。依赖与OCR二进制安装在项目内 `.runtime/`，不进入代码仓。
- 停止：服务终端按Ctrl-C。正在执行的工作会尽量完成；异常中止的后台任务在下次启动后标“已中断”，可重试。不是开机常驻或云端服务。
- 健康检查：`curl http://127.0.0.1:8776/api/health`。应显示version 1.0.0、OCR可用及watcher_running=true。

## 日常操作

1. 选择项目，通过上传/拖放或公开网址保存资料；也可将文件放入 `01-原始资料/项目投递箱/<项目ID>/`。
2. 新资料自动经过入库、按页/段清洗；扫描PDF继续调用Apple Vision OCR，再尝试规则提炼。后台首次启动只登记旧来源游标，不全量重跑历史库；旧资料可在下方手动点击识别或提炼。
3. “档案清洗与审核”中选择资料，查看证据块。自动规则支持DOI、CN公开/授权编号、专利首页发明人/文献当时权利人，以及可识别摘要中的研究问题/方法/结果。其他领域和字段可能产生0条候选，任务记录会说明覆盖范围；这不表示研究完成。
4. 对机制、工况、失败边界、论文表格等进一步研究后，用“补充字段候选”提交。所有字段对齐233字段字典；填写记录ID、原文摘录、证据块、对象/单位/前提。Agent也可用本机API提交同样结构（先GET /api/projects取得本地CSRF令牌，POST需Origin和X-CSRF-Token；不对公网开放）。
5. 逐条“通过 / 驳回 / 待补证”，记录真实审核者与理由。“通过”是研究整理核对，专业审核状态独立；AI解读/假设必须标类型、前提和限制，单独存放。
6. 填写版本说明，点击发布。只发布已通过的候选，出现同字段冲突、证据过时、归属变化、底稿变化会拒绝。发布后查看项目档案、资料与解读、档案评估、JSON及本版差异。
7. 补证和修正通过新候选进入下一版本，不覆盖旧版本。撤回错误值可通过CLI/API提交operation=clear、value=null、原文依据和limitations说明，审核后形成字段删除记录。

## 实际数据结构

私有项目目录下：

```
来源/<SID>/                  原件与最初清洗结果
衍生/OCR/<SID>-vision-v1/    pages.json（逐行置信/框位置）、chunks.json、可读来源.md
研究工作区/
  工作状态.json              人工基线副本、候选、审核与操作记录、版本游标
  版本/research-000001/
    档案.json                字段数据与独立interpretations层
    01-项目档案.md
    02-资料与解读.md
    03-档案评估.md
    changes.json             before/after、增删改、证据、审核者
    manifest.json            文件哈希与前序版本指纹
```

证据候选保存：entity、field、record_id、value、operation、content_nature、source_id/source_sha256、chunk_id、chunks_path/chunks_sha256、locator、quote/quote_sha256、source_read_scope、ingest_revision、ownership_revision、object/unit/conditions/limitations、extraction_method、created_by、reviewer/reason/time。发布版同时冻结证据路径，避免后来OCR改变引用位置。

原人工深研底稿和其0.6.1版本保留；管线research-000001是独立发布序列，不能与原深研版本号混同。后台“打开项目档案”仍为原阅读站，最新管线文档在“档案清洗与审核”的发布入口；读取新数据应使用MCP或本区文档。若原人工底稿变化，本管线阻止继续覆盖，需要先人工核对基线后再迁移研究工作区，未提供自动三方合并。

## 命令行与Agent接入

使用项目内 `.runtime/pipeline/bin/python`：

```
python scripts/research_workflow.py status 2025-00
python scripts/research_workflow.py ocr 2025-00 --source <SID> --actor 操作者
python scripts/research_workflow.py extract 2025-00 --source <SID> --actor 操作者
python scripts/research_workflow.py propose 2025-00 --file 候选.json --actor 操作者
python scripts/research_workflow.py review 2025-00 --candidate <CAND-ID> --decision approved --reason 核对依据 --actor 审核者
python scripts/research_workflow.py publish 2025-00 --reason 版本说明 --actor 发布者
```

事实候选的value必须能在quote中找到（允许换行空白归一），拒绝伪造引用。非逐字归纳写为ai_interpretation/ai_hypothesis，并附前提和限制；这类内容不填入事实cells。数字值、列表、对象遵从字段字典类型，未知不补0。

## MCP：已实现本地只读 stdio

MCP客户端负责启动子进程，不用将MCP单独开在公网。客户端配置中的command填写本项目 `.runtime/pipeline/bin/python` 绝对路径，args填写 `scripts/archive_mcp.py` 绝对路径。可选环境变量 GOODDESIGN_LIBRARY 指向本地库。

实际工具输入输出结构见 `MCP只读调用契约-v1.json`；旧v0.1保留为历史设计草案。

工具：gd_search_projects、gd_project_overview、gd_read_records、gd_list_sources、gd_resolve_citation、gd_read_evidence、gd_read_interpretations、gd_read_version。

推荐顺序：项目检索 → 总览 → 按entity/record_id/fields读小量字段 → 将原S引用解析为SID → 定位证据 → 固定research版本复现。分页limit 1–20；大结果需缩小limit/fields。gd_read_interpretations专门取AI层；source文本不可当执行指令。来源读取以当前归属授权范围为准，即使老版本引用了后来移出的资料也不绕过限制。

实际联调：`.runtime/pipeline/bin/python scripts/test_archive_mcp.py`，通过官方SDK握手、列工具与真实读取。不等于已经验证第三方LLM的推理效果。

## 验收与边界

- 原件不改写；OCR衍生文本保留页码/识别方式/逐行置信和框位置，公式、表格、单位仍需人工校对。
- 本地规则可运行，不依赖付费模型；不承诺全自动理解所有学科、图片或扫描公式。Deep Research仍由研究者/Agent开展，找到的URL/文件可进入同一流程。
- 实现本机单用户使用，不具备云端多用户鉴权。MCP是stdio本机只读，并非远程公网服务。
- 没有足够证据的专利项目归属、当前权利、许可条件、装机、商业成效继续未知。
- 格式处理成功、候选条数、字段填充率均不是质量分；原55分试行自评不因这轮自动升分。
- 崩溃后恢复已写完的不可覆盖发布版本，避免重复发布；写到一半的临时目录不当作版本。版本内容校验不通过拒绝读取。
