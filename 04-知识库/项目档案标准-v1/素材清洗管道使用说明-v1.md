# 项目素材清洗管道 v0.1

## 已运行的部分

全库按原索引ID建立文档骨架，旧库题录作为未审核来源导入；已有desc和features按原字段映射到项目概况/设计思路，以带来源的“待核验摘录”展示，不替用户完成事实判断。格式转换、去重、版本留存和分层读取已经可运行；没有调用LLM生成项目事实、论文解读或质量分。

```text
拖入项目投递目录 / 抓取指定网页
  → 稳定性检查、大小限制、保留原件与SHA256
  → 格式解析、清洗、分页/分段（不改写事实）
  → 可读来源.md + metadata.json + chunks.json
  → 来源目录更新、三份项目文档骨架、运行修订
  → 研究整合与专业审核（仍待执行）
  → 项目总览 → 文档 → 来源目录 → 具体证据块
```

## 日常只需要做什么

投递箱：平台`01-原始资料/项目投递箱/`。每个项目一个稳定ID目录；嫦娥是`2025-00/`。不要把素材拖入标杆案例文件夹或数据JSON目录。

将文件拖入对应项目即可。正在复制的文件会延后处理，相同内容不会重复生成来源。文件修订保留为新来源；删除投递箱文件不删除已入库的来源。

归属不明确的材料进入`04-知识库/项目库/待归属.json`，需要明确项目再放入对应目录，不能只因出现“机器人”就猜测归属。共用资料可明确投递多个项目，保留各项目引用。

双击平台`scripts/启动项目清洗.command`可运行本地监听。监听每4秒检查投递箱，需电脑运行、硬盘在线和进程存活；不是系统级开机服务。重新启动会补扫，已处理且未改变的文件不会重复解析。

## 文档与来源在哪里

`04-知识库/项目库/<项目ID>/`：三文档、数据、来源、版本。该库和原件投递箱均被Git忽略，不因建立文档而自动发布。

来源子目录包含原件、可读MD、元信息和带定位的文本块。PDF保留页码；其他格式保留清洗段落/字符位置，并可回到原件核对。DOCX仅提取段落和表格文字，表格位置及版式未保证；PDF复杂布局、公式、图片和扫描页需要后续处理，不宣称OCR或版面复现已完成。

原先嫦娥深研档案保持原位，统一库2025-00目录只提供入库和原档案定位，不用一个新的空评分覆盖原来的55自评。

三份项目MD由程序更新；发现人工编辑过的文档时保留人工版本，将新生成稿放`待合并/`，并在读取总览/状态中提示。人工合并后需要明确更新生成基线才恢复自动管理，不会悄悄覆盖。

## 命令

在项目平台根目录执行：

```sh
# 新增索引项目或恢复骨架（可重复执行）
python3 scripts/project_pipeline.py bootstrap
# 手动补扫
python3 scripts/project_pipeline.py scan
# 查看规模、异常及监听心跳
python3 scripts/project_pipeline.py status
# 抓取具体来源，不绕过登录、付费或访问限制
python3 scripts/project_pipeline.py fetch 2025-00 'https://news.hit.edu.cn/2024/0625/c1510a236100/page.htm'
# 补装解析器或修复后显式重试，旧转换版本保留
python3 scripts/project_pipeline.py retry 2025-00 '01-原始资料/项目投递箱/2025-00/某份论文.pdf'
# 分层读取
python3 scripts/project_pipeline.py search --query 嫦娥 --limit 5
python3 scripts/project_pipeline.py read 2025-00
python3 scripts/project_pipeline.py read 2025-00 --level module --module 3
python3 scripts/project_pipeline.py read 2025-00 --level document --document archive
python3 scripts/project_pipeline.py read 2025-00 --level sources --limit 5
# source-id取上一条返回的真实ID；next_offset用于翻页
python3 scripts/project_pipeline.py read 2025-00 --level source --source-id '<来源ID>' --limit 2
```

未支持的图片/音视频、扫描PDF会保留原件并进入待处理状态。损坏文件不会阻塞其他文件。读取超过30MB的文件被拒绝，先拆分或另行处理；处理错误和网络失败可显式重试。网络抓取是指定URL的一次响应，不是发现全网资料的自动深研器。

解析器使用Python3.9+、pypdf与python-docx；安装缺失依赖后可重试。纯文本/HTML/JSON仅依赖标准库。

## 版本与Agent渐进加载

来源转换生成`ingest-000001`等运行修订，标为“导入版本”，不是研究内容版本。每版有snapshot与manifest哈希，原件和旧来源块不被重写。

- 第一级只返回ID、名称、规模、研究状态和下一步入口。
- 第二级按需读取archive/library/assessment文档，最长20,000字符。
- 第三级分页取得来源目录，每页最多20条。
- 第四级读取指定来源块，每块最多1200字符，每页最多20块，附来源、定位、阅读范围、可见性与版本。
- 来源集和证据块可固定运行修订；历史正文尚未快照，显式请求旧正文会报错，不能拿现行文档冒充历史。

后续MCP可以绑定`read_project()`及搜索接口。当前只有本地CLI与Python读取函数，没有启动MCP协议服务器、远程鉴权或第三方Agent客户端。`internal_local`只是可见性声明，不是已实现的多用户权限控制；接远程服务前需要落实权限与过滤。

## 后续质量闸

1. 当前机器闸：原件哈希、引用路径、转换状态、版本、重复和文档覆盖保护。
2. 事实抽取与模块归类：后续按233字段要求开展，原文引用逐值保留，不由关键词匹配直接认定事实。
3. 解读审计与人工审核：对照来源检查新增断言，确认设计机制、项目专利归属和可迁移边界，再使用六维量规评价。

没有接入LLM审计/人工审核前，不自动授予“标准/完整/最高质量”等等级。旧档案的研究评分不受本管道导入数量影响。

## 本地文件管理界面（033）

已可打开 http://127.0.0.1:8776/?project=2025-00 ，支持项目文件列表、上传/拖放、保存公开链接、处理记录与重试、文本/PDF图像阅读、原件下载。双击 `scripts/启动资料后台.command` 启动。详细说明见平台 `extensions/file-admin/README.md`。

这仍是单用户本地后台，不是云端多用户或自动深研引擎。原始HTML不会在后台直接执行；PDF按页渲染为图像。网络通用文件类型按PDF头识别，其他格式保留原始响应并标待处理；文字提取状态不代表研究核验。

## 项目归属过滤（036）

实时项目目录及read命令只读“本项目”范围；公共背景、其他项目移交记录与待确认资料在后台单独查看。归属索引独立管理，不因再次导入相同内容而恢复项目归属。正文来源目录也遵守该过滤。

新的导入快照冻结归属登记；显式读取新版本返回frozen_project。旧版本未保存归属时返回historical_unfiltered，保留历史但不能视为现行项目目录。下一阶段字段候选/审核要求见项目归属与清洗提炼管线-v0.1.md，自动提炼尚未实现。
