# 好设计项目档案与全生命周期管理标准 v1.0

日期：2026-10-19。状态：产品标准讨论稿，供首个标准案例试做与校准；未代表560个项目已完成深度研究。本轮定义标准，不启动全库采集，不改变生产页面。

## 1. 产品定义

每个项目建立一份持续更新、可检索、可追溯的主档案。以项目身份为中心，连接技术方案、创新机制、知识产权、人物组织、发展事件、应用成果、证据资料及后续协作任务。

一次深度研究产出的是“截至某日、在已声明检索范围内的档案版本”。未来新增资料、技术变化和真实反馈持续进入档案，保留历史版本。

用户包括研究员/编辑、项目团队、企业创新用户、策展及教育人员。研究员需要追溯每个判断；团队需要补证与纠错；企业需要了解可迁移经验和边界；应用端需要复用有据可查的知识。

### 三层结构

1. **证据资料层**：网页、论文、专利、报告、图片、视频、访谈与检索日志，保留出处和读取范围。
2. **结构化档案层**：项目事实、人物组织、版本、事件、技术、专利关联，以及逐条事实与证据的关系。
3. **知识与应用层**：创新机制、五大构成分析、跨行业迁移、展览讲解、教育活动和企业课题，回链项目与证据。

原始素材集中存储；文章和报告是档案的视图。一个案例可以有多种应用解读，共享主档案及来源。

## 2. 项目身份与边界：先明确我们研究的到底是什么

- 保留现有 project_id，不因标题、单位更名而变更。
- 区分：获奖条目、技术项目、具体产品/型号/版本、团队、机构。一个获奖条目可关联多个实施版本；同一技术多次获奖也不应复制成互不关联的实体。
- 主档案包含研究范围和排除范围，明确系统层级、时间窗口、地域、版本及相关子系统。
- 别名、英文名、旧名、简称记录为检索别名；关联实体关系须有依据，不能只按名字近似合并。
- 关键事实按版本或时间定位，避免把新型号参数填回老项目。
- 核心对象可用统一实体ID；获奖记录、专利、来源、断言、事件、任务分别有独立ID。

## 3. 档案目录与字段字典

字段可扩展，基础记录必须说明字段适用性和资料缺口。P0为标准案例必研究项；P1为补充研究项；某项无材料时记录缺口，而非补写推断。

| 模块 | 字段清单 | 首轮要求 |
|---|---|---|
| 01 项目身份与奖项 | project_id、规范名称、别名、英文名、项目类型、领域/行业、问题/机制标签、研究范围/排除范围、子项目/版本关系；奖项名称、届次/年份、等级、颁发方、原始完成单位、核验来源 | P0：唯一身份、边界及获奖事实 |
| 02 人物与组织 | 人物/机构ID、姓名/名称、历史名称、项目角色、贡献、参与时间、协作关系、归属依据、公开联系渠道及可见范围 | P0：单位与关键角色；P1：可核实的贡献与协作网络 |
| 03 背景与需求 | 时代/产业背景、需求发起方、目标用户、使用场景、原有方案、痛点、目标、问题定义、基线、约束、核心矛盾 | P0：问题、原方案、目标、约束 |
| 04 技术与设计方案 | 系统组成、功能/子系统、工作原理、关键部件、材料、制造/工艺、控制/软件、接口、设计版本、替代方案、取舍、可靠性与维护、参数 | P0：核心原理与关键措施；参数含原值、单位、工况、版本、测量方式、来源 |
| 05 创新机制与五大构成 | 创新点ID、原问题、设计措施、因果解释、对标基线、改进证据、贡献/代价、适用条件、失效边界；科技/艺术/人本/商业/文化维度证据与平台分析；TRIZ等方法映射及映射理由 | P0：至少3条机制候选，并标明证据支持程度；资料不足可少于3条但必须说明；五大构成不强制均衡或评分 |
| 06 知识产权与研究成果 | 专利实体/同族及关联；论文DOI/题目/作者/出版时间、标准编号/版本、软件/数据库/著作权线索、奖项之外的鉴定或成果记录 | P0：专利与论文检索过程和关联判断；其他按适用性补充 |
| 07 发展时间线与决策 | 日期/精度、事件类型、阶段、涉及版本/团队、目标、行动、结果、决策理由、失败/返工、来源、下一阶段关联 | P0：已有证据支持的关键里程碑；不要求凑足数量 |
| 08 实验、应用与价值 | 样机/测试/试点/实际部署记录、测试主体、基线、指标、工况、样本/范围、日期、结果；客户/场景、规模、效益口径、维护反馈、限制与负面结果 | P0：有据可查的验证和应用；商业/社会效益区分自述和独立证据 |
| 09 人物与项目故事 | 故事主题、相关人物、事件时间、原话/转述、关键决策与挫折、采访来源、可核实细节、叙事稿、素材授权、待访谈问题 | P0：公开故事线索及其来源；找不到则标缺口，访谈作为待办 |
| 10 产业关联与后续机会 | 上下游/供应链角色、相关技术/竞争或参照项目、差异、可迁移机制、目标场景、前提、代价、待证假设、最小验证、合作/许可线索 | P0：事实关系与平台建议分开；P1：企业确认与试验结果 |
| 11 资料与素材库 | source_id、标题、类型、URL/文件定位、作者/发布方、发表时间、访问时间、语言、阅读范围、摘要、页码/段落/时间码、文件哈希、权利与使用方式、失效状态、转载链 | P0：所有重要事实回链来源；全文存储仅在可合法保存时执行 |
| 12 运营与治理 | 档案负责人、研究任务、审核人、档案状态、研究轮次、完成日期、下次复核日期、版本、变更记录、冲突、缺口、公开/授权/内部可见范围、派生内容依赖 | P0：责任、状态、版本、待办与复核机制 |

### 信息缺失的标准表达

- `not_researched`：尚未开展这项研究。
- `not_found`：已按登记范围检索，未找到；关联检索日志。
- `not_disclosed`：材料明确表示未公开；保留依据。
- `not_applicable`：该字段不适用；写明理由与审核人。
- `conflicting`：发现互相冲突的说法，尚未解决。
- `known`：有值；另行注明来源与审核状态。

不能用一个空字符串混合以上情况，也不能把“未找到”当作“不存在”。

## 4. 证据与事实：精确到一句话

每条关键事实建立 claim 记录：

`claim_id / project_id / entity_or_version_id / field_path / value / unit / conditions / valid_time / source_ids / source_locator / content_nature / verification_status / reviewed_by / reviewed_at / conflict_group / visibility`。

- 内容性质：来源陈述、平台分析、研究假设、实际验证结果。
- 审核状态：待核对、已核读来源、已交叉核验、项目方确认、专家复核、存在争议、已撤回；这些状态可用审核事件记录，不将“专家看过”等同“实验证实”。
- 来源类型和事实可信度分别记录。官方新闻中的“领先”仍是该机构的表述，需要基线与测试条件才能形成独立对比结论。
- 独立性：转载同一新闻不算多份独立证据；用 origin_source_id/转载关系识别。
- 只看到搜索摘要时标记 `snippet_only`，不能当作读过全文。全文页码/段落、视频时间码、访谈记录号可作为定位。
- 原始数据保留，换算/归一化结果另存并记录方法。
- 冲突双方并存，标出不同版本/时间/口径；审核后保留取舍理由及旧值。
- 重要来源失效或结论修订时，标出受影响的知识单元、报告、教案与展项，安排复核。

## 5. 专利专题标准

### 专利实体字段

申请号、公开号、授权公告号（分别保存）、名称、法域、类型、申请日、优先权与优先权日、公开日、授权日、申请人、发明人、当前权利人及其来源、IPC/CPC、摘要、权利要求定位、同族ID/同族定义/成员、引用与被引用线索、法律事件、状态来源及截至日期。

### 项目—专利的关联字段

`project_id / patent_id / relation_type / innovation_ids / supporting_claims / source_ids / relation_review_status / reviewer / rejection_reason`。

关联类型：项目材料明确列出、技术方案直接关联、同团队候选、技术相近外部参照、排除。后两类不计入项目已确认专利。

- 公司或团队名下的专利只作为候选池，逐件判定与项目及具体创新点的关系。
- 同族聚合时保留各法域成员；公开/授权文本不重复计为两项独立发明。统计同时展示“文献数、申请数、同族数、关联已确认数”，写清口径。
- 同族定义与数据源有关，保留数据源/定义，不能直接混用不同平台的族编号。
- 法律状态是带日期的记录，按相关专利局/登记簿复核。技术关联、权属记录和许可/商业使用条件分开保存；文本相近不自动形成可转化判断。
- 全文/权利要求分析注明读取的版本与具体位置；授权范围和可实施性需要专项复核，本标准先组织资料与证据。

参考入口（本轮仅用于校准字段结构，未开展项目专利检索）：
- WIPO PATENTSCOPE 用户指南：https://patentscope.wipo.int/search/help/en/users_guide.pdf
- EPO 专利同族说明：https://www.epo.org/en/searching-for-patents/helpful-resources/first-time-here/patent-families
- EPO 法律状态查询说明：https://www.epo.org/en/service-support/faq/searching-patents/espacenet-worldwide-patent-search/how-do-i-find-out-if-patent

## 6. 全网深度研究作业流程

1. **建研究任务**：项目ID、边界、截止日期、负责人、目标问题、优先缺口、预期投入与复核人。
2. **构建检索词表**：规范名/别名/英文名、单位历史名称、核心人物、子系统、技术术语、专利申请人/发明人组合。
3. **分渠道搜集**：奖项官方资料、项目/完成单位、政府/科研机构、专利库、论文与标准、行业与应用端、权威媒体/采访、公开影像；记录无法访问和未开放资料。
4. **实体消歧与线索登记**：判断属于该项目、同名其他项目、前后代还是外部参照；候选与确证分开。
5. **材料登记和去重**：保留元信息、原始出处与阅读范围；可保存的原件在移动硬盘归档，受限资料保存元信息/链接/获授权摘录。
6. **事实抽取与冲突检查**：逐条绑定来源和定位，整理参数、事件、专利及人物；形成缺口和访谈问题。
7. **机制分析与应用提炼**：从有依据的措施和效果出发形成知识单元，标明分析与迁移边界。
8. **人工审核与发布版本**：完成身份核对、关键事实审核、专利关联复核、素材可见范围检查，冻结本轮版本。
9. **进入持续更新**：保留未结任务及复核计划，追踪后续公开信息和团队补充；新版本不覆盖旧证据。

### 检索日志与收束规则

每条日志记录 research_run_id、渠道/平台、完整检索式、日期、时间范围、语言/地域、读取范围或结果页范围、新线索数、排除原因、阻断项、下一步。

首个样本建议按“身份奖项、技术、专利论文、时间线故事、应用与后续”五条研究线检查覆盖。连续两轮扩展检索没有新增重要证据，可作为收束参考；如果关键问题仍无依据，只能标为缺口，不能宣布全部研究完成。

“本轮研究完成”必须同时具备：声明范围已执行或解释无法执行、重要线索已处理、关键冲突有结论或显著保留、待补事项有责任人与后续路径、审核通过。来源数量与报告字数不作完成标准。

## 7. 双生命周期管理

### A. 项目真实发展

需求/立项 → 研发/设计 → 样机/试验 → 示范/应用 → 推广/转化 → 迭代/维护 → 退出/替代。

这些是可选阶段，允许并行、返工、分支和不同版本处于不同阶段。获奖是事件，不自动代表商业化或技术成熟。

每个事件记录 event_id、project_id、版本、日期与精度、阶段、事件内容、结果、证据、记录人。涉及未来计划时注明“计划”，与已发生事件分开。

公开资料能支持历史追踪。要参与真实项目管理，还需要项目方提供并确认目标、负责人、计划、实际执行和结果；没有协作输入时称为“研究档案与发展追踪”。

### B. 档案生产与维护

待建档 → 身份确认 → 深度研究 → 待审核 → 已发布 → 待更新 → 更新审核 → 新版本发布；可进入暂停/归档，发现重大错误可撤回。档案审核状态与项目进展分别显示。

任务字段：task_id、project_id、类型（搜集/访谈/专利复核/冲突处理/内容修订/验证）、负责人、依赖、截止日、状态、交付物、审核人、来源或缺口关联。到期未完成保留并显式显示。

初始建议：高变化字段（应用进展、专利状态等）每90天复核；静态背景每年复核；发现新版本、官方纠错、来源失效或团队补证立即进入待更新。周期为试点假设，按成本与使用需求调整，尚未创建自动监测任务。

## 8. 用户界面与检索

前台保持五个主入口：**概览、创新解析、发展历程、资料与专利、应用与合作**。审核人员额外进入“研究与维护”后台。

- 概览首屏：研究对象、核心问题、当前发展状态、档案深度、最后核验时间、主要缺口。
- 创新解析：问题—约束—措施—机制—效果—边界，附证据展开。
- 发展历程：按项目版本筛选事件，区分计划与已发生。
- 资料与专利：全文/字段检索、来源过滤、同族聚合、候选关联与确证分开。
- 应用与合作：已发生应用、平台建议、教育/展览资源及可授权联系入口。
- 后台：检索任务、线索池、冲突处理、审核队列、版本差异、更新提醒、派生内容复核。

检索支持项目/人物/机构/专利号/时间/场景/问题/机制；组合筛选年份、领域、应用阶段、证据状态和可见范围。语义检索和问答返回断言/原始定位；严格按权限检索，不通过摘要泄露私有资料。

## 9. 档案深度与验收

档案深度使用 D0—D3，独立于审核状态和真实项目阶段。

| 深度 | 交付标准 |
|---|---|
| D0 名录 | 身份索引、奖项记录、原始来源、已知缺口 |
| D1 基础档案 | 身份边界核对，问题/方案/成果摘要，基础时间线，来源清单与研究计划 |
| D2 深研档案 | 五条研究线均有执行/阻断记录，逐条证据、专利候选/关联表、创新机制、故事线索、冲突与缺口清单，完成本轮审核 |
| D3 持续管理 | 在D2基础上具备负责人、任务和更新计划、至少一次真实增量更新与版本差异；有项目方协作时另记录协作状态，不据此假设研发管理已上线 |

首个标准案例目标：**D2深研档案，具备D3所需的维护字段与任务结构**。完成一次真实更新后，再验收D3。

首例验收：
- [ ] 唯一身份与研究边界清楚，奖项事实回链官方资料或保留显著待核验标记。
- [ ] 全部对外发布的关键事实100%有来源与精确定位；冲突项不作为确定事实发布。
- [ ] 五条研究线都有检索日志；未找到/无法访问/不适用逐项说明。
- [ ] 技术参数带单位、工况、版本与日期；不可比参数不生成排名结论。
- [ ] 每件候选专利有纳入/排除/待核决定；已确认关联有依据；同族和法律状态注明口径与日期。
- [ ] 创新机制能回到具体措施与证据；故事能回到采访/记录，未核实情节不补写。
- [ ] 本轮版本、负责人、审核、缺口及下一次复核安排齐备；敏感/受限资料不混入公开输出。
- [ ] 从项目名、专利号、人物、问题/机制四种入口能检索到正确内容和证据；缺失类型能被筛出。
- [ ] 至少输出一份可读档案、一份结构化记录、一份来源目录、一份研究日志、一份缺口与更新清单；可生成一项应用样稿但标清解读性质。

## 10. 第一例选择与推进

建议先以现有 `2025-00`（名录名称：嫦娥五/六号月球钻取采样方法及系统设计）试做。选择理由仅来自现有本地资产：已有档案、知识/应用关系样本和部分可定位摘录，能减少从零整理成本；名称、完成单位和奖项仍要重新核验。

研究边界限定在“钻取采样方法及系统设计”这一获奖对象，分别记录五号、六号实施版本；任务整体背景、其他载荷与相关机构专利不自动计入本项目成果。

步骤：先校准身份边界及研究清单 → 开展五线研究 → 整理档案与证据 → 审核D2并评估投入 → 用一件产业类项目测试标准可迁移性 → 调整后再分批覆盖560项。

首例投入先按研究轮次记录，不承诺固定小时即可穷尽全部资料。首例完成后再评估每案工时、可获得资料、审核成本及批量策略。

## 11. 分期建设与待确认事项

P0：标准与空白模板、研究日志、来源/断言、专利关联、事件、任务、首个D2案例。验收以第9节为准。

P1：项目档案页面、审核后台、字段/全文检索、版本差异、更新提醒、第二个工业案例。验收包括权限过滤和修订影响追踪。

P2：大规模自动采集、持续监测、跨项目知识发现、团队协作、项目方主动管理与专用模型优化，依据试点结果再定范围。

待确认：项目方联系人及采访可得性（项目负责人）；公开素材的授权范围（资料负责人）；专利关联的专业审核资源（知识产权审核人）；首轮投入与优先级（平台负责人）。这些不阻挡标准设计，缺少证据或授权会影响对应内容的发布。
