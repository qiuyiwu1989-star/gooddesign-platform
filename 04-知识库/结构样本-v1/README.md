## 样本一：嫦娥五/六号月球钻取采样项目

选择理由：已有项目档案、知识页面、拆解数据与课堂教案，可以直接检验跨板块关联。

- 主项目：2025-00，名称、单位和获奖记录保留现有名录原文。
- 来源：历史详情JSON，登记文件路径、哈希与本轮整理日期。
- 三条知识：非确知环境与工程约束；设计理念与准则；相似性/等效性/覆盖性验证。
- 每条知识保留原文摘录及JSON字段、段落定位，状态为待核验。
- 应用关联：已有拆解资源与课堂课例；策展问题明确标注为平台建议。
- 已验证：摘录与来源一致，项目/课例/拆解文件均存在，应用引用的知识ID有效。
- 待做：官方依据复核、团队设计过程补充、展项任务审查、课例引用校准与实际反馈。

这次完成的是“同一项目如何被知识与应用引用”的数据样本，尚未改写或制作新的展项及教案。

## 样本二：双环机器人关节平台化

把原Demo的一条路线拆成三份明确对象：

1. 问题卡：企业与研究范围、问题、真实目标、基线、约束和负责人。尚未获得的信息保留为空。
2. 机会卡：案例ID、方法组合、研究假设与适用边界。
3. 验证计划：需补资料、建议动作、观察指标、通过门槛与实际结果。后两项待企业确认及验证后填写。

这样后续可以更新一个企业问题，不必重写整份演示。机会被否定也可以保存理由，成为新的知识。

## 下一轮升级顺序

A. 校准这两组样本的字段与证据；优先复核原始依据，确认哪些知识适合教学/展项使用。
B. 建立全量旧内容映射，选择其余9个资料较充足项目；内容深度优先，暂不扩大页面数量。
C. 在原项目页局部增加关联资源入口，教育页补课程关系，产业页让问题卡可编辑；保持原版视觉。
D. 将助手接到经审核的项目知识，回答指向具体来源；先验证项目解释，再升级企业研究。

本地JSON是可供后续内容后台与检索服务使用的初始结构，不是正式数据库接口契约。
