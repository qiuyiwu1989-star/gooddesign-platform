# T03 密钥交付与客户恢复验收流程

2026-11-16。流程设计已交付，业务状态存储/页面尚未实现；没有假填客户回执，没有签发或恢复任何凭据。

## 两条状态线

密钥有效线：active / expired / revoked；依据服务端注册表与真实到期时间。交付线：issued → delivered → client_updated → client_verified。密钥变更不能自动推进交付线；revoked不抹掉历史交付状态，也不意味着新钥已交付。

每条交付事件建议保存：event_id、key_id、customer_reference（最少必要客户标识）、delivery_revision、from/to状态、occurred_at、actor、evidence_reference、request_id（若有）、客户端入口/工具版本、备注。不得存明文token、完整Authorization、截图密钥、客户请求正文。交付渠道只登记类型/回执，不复制消息内容。

## 执行步骤

1. 管理员确认客户归属、用途及所需读取权限，核对旧钥状态及撤销原因。旧钥暴露已撤销时不得为了恢复服务而重启用。
2. 管理员通过受控渠道签发/交付专用钥；issued要求真实key_id和操作记录；delivered要求安全交付回执。签发不由诊断脚本自动执行。
3. 客户更新连接配置，只反馈脱敏检查报告与request_id；client_updated需客户明确回执，不以文件时间猜测。
4. 客户设备使用正确域名，实际完成initialize、tools/list、capabilities及授权范围内最小只读查询；记录每项成功和时间才可client_verified。服务器监测钥成功不替客户验收。
5. 任一失败保留待验；按网络/跳转/401/协议/工具层处理，管理员以request_id查原因，不要求客户把密钥粘贴聊天。
6. 轮换记录旧key_id、新key_id和客户交付进度；暴露旧钥立即撤销，不以等待客户为由继续泄露。非暴露轮换的并行窗口需管理员明确，不能自动默认。

## 正反例验收

- active但未交付：不得显示客户已接入。
- 已交付但客户仍用旧钥：保持待客户更新，不能标服务恢复。
- 独立测试钥成功：只记服务技术通过，客户状态不变。
- 客户只打开公开说明页：不得client_verified。
- 撤销/过期/注册表不可用：拒绝访问，错误报告不泄露token及内部路径。
- 客户成功回执附完整明文钥：报告应拒收/脱敏并触发管理员泄露处置，不自动归档原文。

待客户与管理员实际配合：确认当前有效专用钥归属、安全交付、客户本机成功回执。当前客户恢复仍未确认，设计文档不能替代这些事实。
