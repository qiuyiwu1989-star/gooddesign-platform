# 管线运行与验收说明

这套管线在本机私有运行。原件入库、格式转换、投递箱监听、任务持久化和有限规则提炼已自动化；深度语义研究由外部Agent阅读原件、提交带证据的候选，合格增量再由管家自动入档。没有后台内置通用研究模型，不承诺无人值守完成所有Deep Research。

## 启动与使用

在项目根目录双击 `scripts/启动资料后台.command`，或运行：

```sh
.runtime/pipeline/bin/python scripts/file_admin.py --port 8776
```

打开 `http://127.0.0.1:8776/`，选择项目后上传文件或保存公开网络文件。也可以将文件放入 `01-原始资料/项目投递箱/<项目ID>/`；监听每4秒扫描，稳定文件进入对应项目。不要把整届多项目目录或其他项目资料不加区分地放入本项目。

原件保存在私有项目库并按指纹去重。转换成功不等于已阅读；扫描PDF先生成OCR，OCR不等于人工核对。来源归属不清、提取冲突、关键指标或权利判断会留下待办，不能为了清空任务而强行完成。

当前资料与文件后台统一在8776。历史8773/8775预览不代表新管家状态。退出服务后原件、任务、候选和研究版本仍在外置盘；再次运行恢复队列。机器休眠、硬盘离线或服务退出期间不能执行任务；“任务仍在”不表示那段时间一直在工作。

## Agent如何接续

1. 在对应项目来源目录读取原件、可读文本和证据块；先确认项目/型号/年代边界。
2. 事实候选引用source_id、chunk_id和逐字quote；AI解读另标content_nature，并写适用前提与限制。
3. 用可信本地 `archive_steward.py submit` 提交候选。管家检查类型、来源指纹、归属、冲突和敏感字段，再发布合格增量；其余留待判断。
4. 新研究版发布后，重新制作并冻结绑定该版的八模块导读及六维评估。它们是AI阅读辅助/研究判断，不改变事实或自动加分。
5. 引擎通过 `archive_mcp.py` 的本机stdio只读工具逐层读概览、记录、AI解读和冻结证据；不是公开HTTP服务，也未接第三方生产应用。

自动化边界请特别保留：原始申请人、公告时专利权人、现权属是不同字段；同团队、同专利家族或标题出现项目名，都不能证明正式获奖成果或实际装机。关键纠错应建立新研究版本，旧版保留。

## 可重复端到端验收

在项目根目录运行：

```sh
.runtime/pipeline/bin/python scripts/check_pipeline_e2e.py
```

脚本在外置盘 `output/pipeline-acceptance/` 新建**虚构验收样本库**，启动自己拥有的真实HTTP子进程，并验证：

- 上传、原件下载、清洗预览、项目隔离与CSRF拒绝；
- 投递箱自动发现新文件；机器转换不会编造语义事实；
- 暂停、持久任务、真实服务重启和恢复；
- 模拟外部Agent提交固定证据，后台自动研究发布；
- 冲突候选保留待判断、既有版本不覆写、重复文件去重；
- 真实MCP SDK读取已发布字段和冻结来源；
- 交付包生成及独立check.py/read.py运行。

完成后自动停止它自己创建的子进程，保留JSON报告、服务日志和测试包。不会停止8776生产私有后台，也不会向真实项目写入测试内容。报告是运行链路验收，不是项目资料质量、真实语义推理或全网研究成功率证明。

报告失败时查看同目录服务日志；不要删除失败记录。重新运行创建新目录，不覆盖旧验收。
