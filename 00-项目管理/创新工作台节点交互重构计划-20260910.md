# 创新工作台节点交互重构计划

日期：2026-09-10
对象：好设计产业 Demo / 创新工作台 / 双环案例

## 1. 当前问题判断

截图里的直接 UI 错误是：选中节点进入 active 状态后，文字变成白色，但卡片背景仍然接近浅色，造成标题和正文不可读。这不是单纯配色问题，而是节点状态模型没有拆清楚：现在 active、selected、dormant、has 等状态叠在一个卡片上，视觉优先级冲突。

更大的产品问题是：工作台还像“流程图 + 节点库”的混合体，而不是一个真正的人机协作创新节点系统。用户需要的不是把方法都摆出来，而是在一个具体创新故事里，按问题、证据、判断逐步生成、添加、移除和复原节点。

## 2. 我建议的产品定位

创新工作台应该定义为：面向企业产品创新的人机协作推理画布。

它不是知识库浏览器，也不是普通表单，也不是把 ComfyUI 外观照搬过来。它的核心价值是把一次企业创新研究过程拆成可编辑、可复核、可沉淀的推理节点：每个节点都说明输入是什么、AI 做了什么、人需要判断什么、输出会流向哪里。

## 3. 节点的基本模型

每个节点都应该有四层信息：

1. 节点身份：输入、方法、证据、Agent、判断、验证、产出。
2. 节点状态：未添加、已添加、选中查看、运行中、已产出、需人工复核、被移除可恢复。
3. 节点内容：当前输入、推理过程摘要、输出结果、证据来源、适用边界。
4. 节点关系：上游依赖、下游去向、为什么连接、连接是否经过人工确认。

节点不能只是卡片。它应该是一个可保存的推理单元。

## 4. 交互前后的逻辑

### 4.1 进入工作台前

用户从产业演示或现场 Agent 进入工作台时，系统不应该自动铺满方法库，而应该生成一个“最小可讲故事画布”：

- 企业输入
- 问题定义
- 方法选择器
- 1 到 3 个已触发方法
- 证据匹配
- 方案生成
- 验证计划
- 报告沉淀

其他方法都留在左侧模板库。

### 4.2 添加节点

添加节点不是“新增一个装饰卡片”，而是一次明确动作：

- 用户从模板库选择节点。
- 系统说明这个节点适合解决什么问题。
- 节点被放到当前选中节点附近。
- 如果它有默认上游或下游，系统用虚线连接，并标注“建议连接”。
- 用户确认后，虚线变成实线。

### 4.3 移除节点

移除节点不等于删除知识。

- 移除后节点回到模板库。
- 与它相关的连接变成隐藏或断开记录。
- 如果下游依赖它，系统提示“这个节点被移除后，某些结论将变成待复核”。
- 关键主线节点可以锁定，防止现场误删。

### 4.4 运行节点

运行节点应该像一个小型推理过程：

- 输入：来自上游节点和用户补充。
- 处理：AI 使用方法或证据进行分析。
- 输出：生成结构化结果。
- 复核：需要人判断是否接受。

现场 Demo 中可以预加载结果，但交互上要让人看到“它在基于节点关系推理”。

### 4.5 复原节点

复原应该分两类：

- 复原视图：只恢复缩放和平移。
- 复原画布：恢复双环演示默认节点组合、坐标和连接。

现在这两个概念需要在 UI 上分开，避免用户误解。

## 5. 页面布局建议

我建议推倒重做工作台页面，结构如下：

### 左侧：节点模板库

左侧不再只是分类按钮，而是“可添加节点库”。包含：

- 主线节点：企业输入、问题定义、报告沉淀。
- 方法节点：功能拆解、TRIZ、案例类比、机会分析、五大构成、专利检索、场景分析。
- 证据节点：好设计项目、企业资料、现场访谈、测试数据。
- Agent 节点：调研 Agent、匹配 Agent、方案 Agent、验证 Agent、报告 Agent。
- 判断节点：人工取舍、专家复核、风险判断。
- 产出节点：方案卡、验证计划、研究报告、知识沉淀。

每个模板显示“适用场景”，而不是只显示名称。

### 中间：推理画布

中间是核心区域。

- 默认显示少量主线节点。
- 节点可拖动、放大、缩小、连接。
- 连接线带标签：触发、输入、证据、修正、产出。
- 方法节点按需展开，不在默认画布上堆满。
- 可以有“演示模式”，按故事逐步点亮节点。

### 右侧：节点检查器

右侧负责解释当前节点。

- 这个节点在解决什么问题。
- 上游输入来自哪里。
- AI 做了什么。
- 人需要判断什么。
- 当前输出是什么。
- 哪些结论已确认，哪些只是平台假设。
- 可操作按钮：运行、接受、驳回、生成下游节点、移除节点。

### 底部或浮层：演示控制台

现场演示需要一个轻量控制台：

- 上一步 / 下一步。
- 暂停。
- 聚焦当前节点。
- 显示讲解词。
- 切换“讲故事视角”和“工程编辑视角”。

## 6. 双环 Demo 的推荐故事线

双环案例不应该一开始展示复杂全链路，而应该讲一个清楚的故事：

1. 双环来了：它不是泛泛企业，而是传动系统和机器人关节相关企业。
2. 问题收窄：不是问“企业怎么创新”，而是问“机器人关节平台化如何形成可复用能力”。
3. 方法选择：平台判断这类问题先用功能拆解，再用 TRIZ 看性能取舍，再用好设计案例做机制迁移。
4. 证据匹配：从好设计项目库找高端装备、机器人、精密制造里的可迁移机制。
5. 现场修正：如果企业补充约束，现场 Agent 更新节点关系。
6. 生成方向：只输出 2 到 3 个候选方向，每个方向都有收益假设、代价和未知项。
7. 验证计划：把概念落到小试指标。
8. 报告沉淀：形成网页版报告，并把问题、方法链、证据关系回写到底座。

## 7. UI 设计原则

1. 画布上少即是清楚。默认只显示当前故事需要的节点。
2. 方法不是菜单，而是被问题触发的工具。
3. 节点状态必须分层，避免 active 和 selected 抢样式。
4. 证据、假设、人工判断要视觉区分。
5. 现场演示优先讲得懂，深度内容放在展开层。
6. 不追求一次做成完整平台，先把双环案例跑顺。

## 8. 下一轮实现计划

### 第一步：修 UI 状态错误

- 重写节点状态样式。
- active 节点使用明确深色或明确高亮浅色方案，不再出现白字浅底。
- 区分 selected、active、running、review-needed、hidden-template。

### 第二步：重做节点数据模型

- 把节点模板和画布实例分开。
- 模板是可添加的能力。
- 实例是当前项目里的一个具体节点。
- 移除节点只移除实例，不删除模板。

### 第三步：重做连接模型

- 连接不再靠数组索引，而用 nodeId。
- 支持建议连接、已确认连接、断开连接。
- 隐藏节点后自动隐藏相关连接。

### 第四步：重做左侧节点库

- 从分类按钮改为模板库。
- 每个模板显示用途、适用问题、添加按钮。
- 默认折叠非当前相关方法。

### 第五步：重做右侧节点检查器

- 加入输入、处理、输出、复核四段。
- 加入“生成下游节点”“接受输出”“移除节点”。
- 对证据和假设做清晰标注。

### 第六步：做现场演示模式

- 演示模式不只是轮播节点，而是逐步添加/点亮节点。
- 每一步有讲解词、当前动作、画布变化。
- 支持暂停和继续。

## 9. 我建议下一版的目标

下一版不要继续补丁式优化，而是做一个新的 `workspace-v2.html` 或直接重写 `workspace.html`：

- 画布默认清爽。
- 节点可添加、可移除、可复原。
- 方法按问题触发。
- 交互像 ComfyUI，但业务逻辑是企业创新推理。
- 双环案例能完整演示“从问题到方法到证据到方案”。

如果明天演示优先，我建议先做一个稳定的双环 Demo 版本：保留当前功能，修掉 UI 错误，强化演示模式和节点模板库。完整的连接编辑、节点运行状态、下游生成机制可以放到下一轮。
