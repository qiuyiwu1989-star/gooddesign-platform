# 好设计：项目库与方法库统一 MCP 使用说明

## 从哪里接入

日常只配置一个入口：`gooddesign-innovation`。它连接独立的项目库与64方法目录，原有两个MCP继续保留，不需要同时重复配置。

这是本机stdio服务。当前电脑和外置盘在线时可用，不是一个可直接粘贴到远程聊天里的HTTP网址。网页项目库用于浏览，MCP用于让支持本地工具的AI客户端调取知识。

标准MCP客户端配置：

```json
{
  "mcpServers": {
    "gooddesign-innovation": {
      "command": "/Volumes/邱懿武/邱懿武认知大脑/好设计平台/.runtime/pipeline/bin/python",
      "args": ["/Volumes/邱懿武/邱懿武认知大脑/好设计平台/scripts/innovation_gateway_mcp.py"]
    }
  }
}
```

Codex客户端使用TOML配置时，对应配置为：

```toml
[mcp_servers.gooddesign-innovation]
command = "/Volumes/邱懿武/邱懿武认知大脑/好设计平台/.runtime/pipeline/bin/python"
args = ["/Volumes/邱懿武/邱懿武认知大脑/好设计平台/scripts/innovation_gateway_mcp.py"]
```

配置后重连MCP，先调用 `inno_capabilities`，应看到10项工具，默认无模型调用。换电脑时须先复制/挂载同一套项目和运行环境，再修改路径；不要把本机路径当云端服务。

## 直接这样对AI说

> 使用 gooddesign-innovation，帮我研究“小型异形零件内腔抛光时，怎样降低表面损伤并改善去除均匀性”。目前材料、尺寸、允许损伤和验收标准未知。先查项目与方法，说明选取理由，再用问题定义、功能分析和形态组合形成研究草稿。原文主张、分析和目标假设分开；每项重要判断标明项目版本、记录字段和方法版本。没有证据就保留未知，不把相关专利写成装备已经采用。最后列出需要我提供的数据、候选方向、验证计划和停止条件。如需保留过程，请显式创建独立研究计划，并把run_id给我。

AI客户端负责分析与撰写；入口提供有版本的上下文、方法步骤和输出要求。组包完成不表示分析、用户研究或工程验证已完成。

## 可复现的一条调用链

1. `inno_capabilities`：了解范围和副作用。
2. `inno_search_projects({"query":"内腔抛光"})`：找到 `2025-04`，再读总览核对象和版本。
3. `inno_search_methods({"query":"问题定义"})`：确认R48；需要时分别读取R48/R14/R17的io、steps、boundaries。
4. 以下调用组装研究包，不写文件：

```json
{
  "tool": "inno_prepare_research",
  "arguments": {
    "problem": "研究小型异形零件内腔抛光的表面损伤与去除均匀性；材料、尺寸、载荷与验收阈值未知。",
    "project_ids": ["2025-04"],
    "method_ids": ["R48", "R14", "R17"],
    "keywords": ["抛光", "表面"]
  }
}
```

返回 `packet` 和 `packet_sha256`，含源项目精确研究版本/档案指纹，方法版本/指纹、步骤、输入产物、命中的字段证据和输出要求。关键词为逐字检索，不是语义相似度；无命中不等于知识不存在。

5. 要保留记录，使用相同参数调用 `inno_start_research`，得到 `run_id`；再调用 `inno_read_research({"run_id":"返回的ID"})`回读。仅此工具会保存独立计划，不会修改项目和方法，不调用模型。记录在外置盘 `output/innovation-unified-private/runs/`，不对公网开放。
6. 针对命中字段，用 `inno_read_project` 的records层取得完整上下文；再把返回的project_id/source_id/revision/chunks_sha256传给 `inno_read_evidence`，核原文与范围。AI解释用interpretations层单独读取。

默认R48→R14→R17只是一个固定研究顺序，未自动判断一定最适合问题。调用方应核对方法边界，也可以明确指定其他方法ID。

## 你应该拿到的交付

| 部分 | 应包含什么 |
|---|---|
| 问题定义 | 已知、未知、假设、约束与需澄清事项 |
| 案例与证据 | 相关机制及条件，项目版本、记录字段、来源引用 |
| 方法分析 | 使用了哪一版方法，关键中间产物和未覆盖项 |
| 候选方向 | 前提、取舍、反例与不适用条件，保持为假设 |
| 验证计划 | 所需数据、量测方式、比较基线、停止条件 |
| 可追溯记录 | run_id、packet_sha256、项目与方法版本 |

事实、方法教学、目标假设不能混写。来源有声明不等于独立验证；related-only专利不等于项目采用。

## 常用工具

| 目的 | 工具 |
|---|---|
| 找项目与方法 | inno_search_projects / inno_search_methods |
| 查结构化知识 | inno_search_fields / inno_read_project |

## 使用限制与排错

- 外置盘离线：先接盘，不能退回系统盘创建第二份库。
- 项目ID或方法ID不明：先搜索，不猜ID。
- 项目没有发布研究版：组包会拒绝，先选已有研究版本的项目。
- 版本在组包时变化：重试；已经保存的记录保留当时的内容与指纹。
- 返回过大：减少项目/方法/关键词，按层级读取。组包最多3项目、5方法、5关键词，120KB上限。
- 当前没有自动模型调用、求解器执行、源档案修改、专家认证、远程HTTP接入或公网MCP。独立计划保存也不是完成研究报告。

独立测试发现的空证据版本绕过已修，超过200字项目query与未知字段/实体也已加校验。研究包返回上限120KB，project query最长200字，显式fields最多30个有效字段名。
