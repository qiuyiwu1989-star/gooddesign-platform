# 好设计 · 像素工业志

目标：让读者认出真实项目，并理解它在哪里、如何被使用。**原型准确优先，风格统一其次。** 插画不等于实物照片、结构验证或工程证据。

## 使用前

1. 确认项目 ID、名称、设备/系统边界、用途及实际需要的配图位置。不要仅凭标题想象机器。
2. 有原照片或图纸时，先实际看图，记录可见轮廓、比例、主要部件、连接和识别配色；将该图作为生成参考。原图约束高于风格样图，文字描述不能替代看图。
3. 核对图片是否对应同一对象/型号/时期。资料冲突先保留问题；不把相似设备当原型。有侧面图不等于知道背面或内部结构。
4. 选择模式：有图重绘、场景扩展、无图概念或批量补图。具体规则见 [references/workflow.md](references/workflow.md)。

## 画面规则

- 16:9，清晰主体与应用环境。单体设备通常占画面约65–75%，可按真实尺度调整；主体外缘留约8%安全区，先保完整形态。
- 精致16-bit复古科技插画：有意的像素簇、干净阶梯边、有限抖色；不用照片加随机噪点冒充像素绘画，也不糊成油画或泛光。
- 背景常用钴蓝/青/深蓝，暖白高光、少量琥珀。**原设备的红白、金色等识别色不得为统一色盘而改掉。**
- 有前中后景，主轮廓清楚，背景比主体简化一级。参考视角能讲清用途时保留参考视角，不强制改成三分之四角度。
- 不重设计主体，不随意改变太阳翼、轮子、发动机、推进器、机械臂等关键部件的数量和位置。不画原图没有依据的内部机构。
- 标题、奖项、年份、参数由网页排版，不烘焙进图片；不让生成器编造品牌、徽章、标注或性能数字。真实标记按任务与使用许可处理，不为“像素风”添加装饰性标志。
- 项目是主角，默认不加小好等吉祥物。方法图标保持既定玻璃风格，导航、文字、按钮不随插画像素化。

详细配色与叙事规则见 [references/style.md](references/style.md)。提示词见 [references/prompts.md](references/prompts.md)。

## 生成与校正

使用所在 Agent 支持的图像生成/编辑工具；Codex 有内置 imagegen 时优先用它，不将付费API当隐含依赖。仅有本 Skill 不代表已具备生成工具；工具不可用时交付任务包并说明缺口，不伪称出图。

一次生成一件独立资产。有图重绘把原图作为对象参考，另有样图时明确“仅供风格，不能复制样图设备”。先核对主体，再看风格；主体不一致时收紧原图约束重绘，不能以风格漂亮放行。不要通过裁切掩盖关键结构错误。

样例见 [references/examples.md](references/examples.md)；附带三张公开插画用于风格学习，**不能充当其他项目的结构参考**。星球车和蛟龙号重绘是参考校正案例，并非对所有生成细节的工程认证。

## 验收与交付

按 [references/review.md](references/review.md)逐件对照。先过原型关，再过用途、风格、小尺寸显示关。没有可靠外观原图的只能标记“概念场景插画”，不能以风格分数抵消外形问题。

交付独立目录：项目ID、原图路径/来源及SHA256、用途依据、完整提示词、生成工具实际名称、版本、原图/插画对照、已知简化、审核状态、文件SHA。模板：[examples/intake.json](examples/intake.json)、[examples/review.json](examples/review.json)。

保留生成原件和旧版本；WebP缩略图是展示衍生，不覆盖原始照片/图纸。按宿主项目落盘约定保存。其他Agent默认交付待审核包，不能仅因本Skill可读就修改正式数据、评分或自动部署。页面须区分场景插画与原始资料；不从插画反推采用、试验或性能事实。

可运行 `python3 scripts/check_package.py` 检查本技能包完整性；它只验文件哈希，不代替视觉审核。
